# 性能监视

从设置中的「关于 WeQ → 性能监视」进入，也可搜索“性能监视”。该工具记录正在连接的 WeQ 宿主：桌面窗口和桌面内置 Web 共用一份历史，独立 Web 服务记录服务器进程；浏览器本身不在监视范围内。切换 QQ 账号不更换历史或设置。

## 记录档位

| 档位 | 记录内容 | 频率 |
| --- | --- | --- |
| 关闭 | 停止周期采样及专用性能事件，已有历史仍可查询和导出 | 不采样 |
| 轻量记录（默认） | CPU、进程内存、JS 堆、主进程事件循环及已有缓存计数 | 30 秒 |
| 完整记录 | 基础指标，以及桌面页面、媒体、动画、样式、缓存明细和服务请求、数据库任务统计 | 基础 10 秒，详细 30 秒 |

完整记录默认一小时后回到轻量，可选 15 分钟、四小时或持续。截止时间随宿主保存，重启不会重新开始计时。运行繁忙或详细采样成本偏高时会延后详细统计，页面显示退避时间和间隔。切换档位立即生效，不需要重启。

## 查看历史

选择最近一小时、一天、一周或自定义北京时间范围。图表支持时间缩放、拖动及进程筛选；点击曲线选中采样，在下方切换资源类别查看明细。图表聚焦时左右方向键选择采样，`+`／`-` 缩放。暂停跟随后，实时记录仍继续，但不会把正在查看的历史跳回最新。

CPU 按整机逻辑核总容量归一到 0–100%，不是单核 100% 的口径；第一次没有比较区间的进程 CPU 可能不可用。进程驻留内存、JS 堆、外部内存、Chromium 图片缓存属于不同统计口径，不能相加当成总占用。Web 服务不提供桌面 DOM、动画等指标，不支持的字段显示不可用。

长时间图表按时间桶显示均值及最低／最高范围，不抹掉峰值；选中明细是该桶最后一次真实采样。关闭、休眠和进程会话切换处保留间断，不补造数据。图表与事件时间为北京时间，导出时间保留原始时间戳或 ISO 时间。

进程会话过多、图表超过 8000 个聚合点时，会明确提示仅显示前段历史；可选择单一进程或缩小时间范围。CSV 不会静默导出截断图表，JSONL 可导出完整原始记录。

## 保存与导出

默认保存七天、最多 128 MiB，可设置 1–365 天和 64／128／256／512 MiB。先达到时间或容量条件就删除最旧历史；实际可查看时间以页面显示为准。缩短时长或降低容量需要确认。关闭采集后仍会清理过期历史。

JSONL 导出所选时间范围的原始记录；CSV 导出当前范围、进程筛选及分桶的图表统计。桌面选择文件位置，Web 生成下载。清空历史需要再次确认，不改变记录档位或聊天记录。

历史位于宿主数据目录的 `performance-monitor/history.sqlite`，包括 SQLite 的附属文件。原有 `logs/dev-memory-monitor` 文件不会自动导入或删除。普通应用错误日志不受关闭性能记录影响。

采样耗时分同步执行与异步等待，等待毫秒数不能直接视为界面阻塞。队列、丢弃和延期计数可用于判断记录是否完整；写入异常会显示原因并低频重试，不无限积压。
