# macOS QQ 数据读取授权

WeQ 无法读取本机 QQ 的数据库时，会在「受限模式」详情中显示「QQ 数据读取受限」，不占用账号页空间。这和密钥不正确不同，无需反复扫码或更换密钥。

1. 打开「受限模式」详情，点击「打开系统设置」，进入「隐私与安全性 → 完全磁盘访问权限」。如果没有跳到对应页面，可按此路径手动进入。
2. 展开「查看应用与读取路径」，添加提示中显示的当前应用并开启访问权限。若此前已授权但更新后失效，可移除旧条目，再添加当前应用。
3. 返回 WeQ 点击统一的「重新检查」。读取恢复后会重新加载账号，继续选择账号打开。
4. 如果仍提示受限且已完成授权，请彻底退出 WeQ 后重新启动，而不是仅关闭窗口。

检测由读取 QQ 数据的 WeQ 进程只读打开数据库完成，不以系统设置开关或目录存在作为成功依据；不修改 QQ 数据。不需要本机 QQ 数据的备份导入和静态账号仍可使用。

## 开发版的启动来源

从 Terminal、iTerm 或编辑器终端运行的开发版，文件访问可能被 macOS 归属到启动来源。
仅为 Electron 开启完全磁盘访问权限不一定生效。「查看应用与读取路径」会显示可识别的启动来源，
请同时检查该应用的完全磁盘访问权限，再从该来源重新启动开发版；如果系统要求重新打开启动来源，按系统提示处理。
父进程信息只能确定启动来源，不能单独证明系统实际将授权归属到了哪个应用。

例如本机已核实的一次失败，系统记录的访问进程为 Electron、授权主体却是 Terminal，
Electron 已获授权但 Terminal 未获授权。反复重启 Electron 无法替代对正确主体的授权。

## 在线状态未知

QQ 登录状态文件读不到时，WeQ 保留「QQ 在线状态待确认」，不会当作「QQ 不在线」。
如果检测到 QQ 主进程，会说明 QQ 正在运行；进程存在不代表已确认当前账号登录。

「QQ 数据读取检测失败」表示其他读取错误，不能直接认定为授权问题。请根据显示的路径、错误码和日志检查数据目录。未找到数据库不属于授权失败。

如果界面或日志在进程附加、抓包等其他操作中显示 `Operation not permitted`，不能据此套用本页的磁盘授权处理方法。

Apple 对完全磁盘访问权限及添加应用的说明见[隐私与安全性设置](https://support.apple.com/guide/mac-help/change-privacy-security-settings-on-mac-mchl211c911f/mac)。
