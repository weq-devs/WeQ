# macOS 安装与首次打开

本页使用 Finder 和“系统设置”完成安装与首次放行，不需要终端命令，不关闭 SIP，也不更改 QQ 登录方式。

## 安装

1. 在苹果菜单的“关于本机”确认芯片：Apple 芯片选择 `mac-arm64.dmg`，Intel 选择 `mac-x64.dmg`。
2. 从项目 [Releases](../../../releases) 下载对应版本。确认来源可信，不使用来历不明的重新打包文件。
3. 打开 DMG，将 `weQ.app` 拖入“应用程序”。如果已有旧版本，先正常退出旧版，再确认是否替换。
4. 在 Finder 的“应用程序”中打开 WeQ，不从 DMG 内直接运行。

## 首次放行

没有 Developer ID 和 Apple 公证的版本，macOS 仍可能提示“无法验证开发者”或“Apple 无法检查是否包含恶意软件”。
只有确认下载来源可信、文件没有被篡改时，才按 Apple 提供的单应用放行流程继续：

1. 先尝试打开一次 WeQ，关闭系统警告。
2. 打开苹果菜单 →“系统设置”→“隐私与安全性”。
3. 向下找到“安全性”区域中与 WeQ 对应的提示，点“仍要打开”。根据系统版本，也可能先显示“打开”。
4. 完成系统要求的身份验证，在再次出现的确认框中点“打开”。
5. 此应用会被保存为例外，之后从“应用程序”中双击打开即可。按钮通常只在尝试打开后一小时内出现。

这是对一个可信应用的明确例外，不是关闭 Gatekeeper 或系统安全检查。
Apple 的完整说明见[通过覆盖安全设置来打开 App](https://support.apple.com/zh-cn/guide/mac-help/mh40617/mac)。

## 不同警告

| 提示 | 处理 |
| --- | --- |
| 无法验证开发者／Apple 无法检查恶意软件 | 确认可信来源后，可按上面的单应用流程放行 |
| App 已损坏、被修改、将损坏电脑或被移入废纸篓 | 不把它等同于普通首次提醒。停止打开，从官方版本重新下载；若仍出现，报告具体版本、芯片和完整提示 |
| 没有“仍要打开”，且设备由单位或学校管理 | 可能受管理策略限制，联系设备管理员，不用脚本绕过策略 |
| 能启动，但某项 QQ 在线能力不可用 | 安装问题与 QQ 登录／功能权限分别诊断，不以放行应用代替在线能力就绪 |

详见 Apple 的[在 Mac 上安全地打开 App](https://support.apple.com/zh-cn/102445)。

## 签名范围

无证书构建使用 ad-hoc 签名封装最终应用并检查资源完整性。它不需要付费证书，但**不等于 Developer ID、Apple 公证或 Apple 已确认应用安全**，也不承诺首次双击没有警告。
当前安装修复不调整登录、密钥获取或 SIP，不会让 SIP 开启时依赖读取 QQ 进程内存的功能自动可用。
自动更新和首次下载后的系统放行是不同流程，本页不将本地签名校验代替更新验收。
