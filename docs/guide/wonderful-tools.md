# 维护与诊断工具

从 **设置 → 数据维护 → 维护工具** 打开密钥扫描、其它设备密钥及数据库修复；抓包与逆向解析从 **设置 → 高级与诊断 → 高级诊断** 打开；QQ 登录账号管理从 **设置 → 账号与消息 → 账号管理** 打开。各项独立展示，数据库修复使用独立窗口。

本页介绍以下工具，其余维护入口见[设置总览](settings.md)：

| 工具 | 说明 |
| --- | --- |
| **密钥扫描** | 零注入内存扫描主密钥 |
| **其它设备密钥** | 获取账号其它设备的密钥 |
| **数据库修复** | 备份 · 重建坏库 · 可回滚 |
| **ntqq 抓包** | 非侵入式读网卡 · TCP 重组 · d2key 解密 |
| **Protobuf / JCE 逆向** | hex/base64 → 简洁 JSON |
| **QQ 登录账号管理** | 快速登录账号 · 删除账号 · 更换设备标识（GUID） |

维护工具里的「数据库修复」与数据库损坏提示中的「尝试修复」打开同一修复工具。

## 1. 密钥扫描

后端遍历 `login.db` 的全部历史账号，逐个反查 `nt_msg.db` 目录与在线 QQ 进程 pid（Windows 走
Restart Manager、Linux 走 fcntl 写锁）。

- 在线账号卡片亮起（绿色在线点 + 高亮），离线账号置灰；
- 卡片显示头像、昵称 / QQ 号、在线 / 离线；工具栏有「刷新」，并显示「N / 总数 在线」；
- 点击任意卡片 → 卡片加载动画 → 对该账号进程做**零注入内存扫描**
  （`nt_helper scanKeyFromDatabaseWithProgress`）：先扫 HMAC_SHA1 锚点 / 簇，找不到
  可验证的密钥时自动**回退扫描整个内存**（较慢）；扫描期间结果弹窗显示两阶段进度条；
- unix（Linux / macOS）上读别的进程内存通常要管理员权限：普通用户直接扫不到时，会像
  「读取 QQ 内存 / 抓包」一样弹**管理员密码框**，授权后由一个临时的 root 子进程重扫
  （macOS 若 SIP 开着则提示使用扫码登录等可用方式，不发起无效的提权尝试）；
- 扫描结果弹窗显示：头像 / 昵称 / QQ 号 / PID，以及
  - 恢复出的**密钥**（可一键复制）；
  - 密钥所在内存的**上下文 hexdump**（前 256B + 后 256B，**高亮**密钥字节）；
  - 或失败原因。

## 2. 其它设备密钥

用来处理「我手上这份 `nt_msg.db` 是别的设备导出的」这种情况。

- 先检查是否有可用的在线 QQ 实例（复用密钥扫描的 pid 判定）；没有就把「获取密钥」按钮置灰；
- 选择其它设备导出的 `nt_msg.db` → 读取头部字节（256B）显示 hexdump，**高亮**发包用的
  `key_meta`（文件偏移 `0x2f..0xaf`，与 native 的 `request_decrypt_key` 一致）；
- `key_meta` 下方给出有效 / 无效徽章；
- 点「获取密钥」→ 显示加载动画 → 按 bootstrap 的实例取密钥流程（跳过注入，直接调
  `nt_helper requestDecryptKey`）→ 返回密钥或失败原因；
- 成功后显示密钥（可复制）与返回它的在线实例 PID。

> [!note]
>
> 这里用到的「在线实例」受**完全离线模式**影响：若在[设置 → 账号与消息 → 接入与监听](./settings.md)里关掉了
> 「自动读取 QQ 内存（完整功能）」，本工具会显示「完全离线模式」，按钮保持灰色，无法向 QQ 请求密钥。密钥扫描
> 是零注入的，离线模式下仍可用。

## 3. 数据库修复

修复流程为**体检 → 修复**，修复记录与回滚在标题栏的独立入口中查看。修复只能重建仍可读取的内容，无法保证恢复全部数据。

### 打开即体检

- 打开后自动执行**只读**体检，帮助判断数据库状态；
- 可以跳过体检，直接选择数据库；
- 结论里**有问题的库排在前面**，其余收在「其他数据库」后面；全部健康时全部铺出来；
- `PRAGMA integrity_check` 读到坏页时**抛出的 malformed 错误本身就是损坏结论**，会判成「结构损坏」，
  而不是含糊的「结构检查没跑成 / 未判定」。

### 修复

- 所有数据库健康时，仍可通过「仍要修复」继续，但通常没有必要；修复会替换数据库并关闭 WeQ 中当前打开的账号；
- 修复界面显示**进度条、阶段和百分比**，耗时取决于数据库大小、状态和设备性能；
- 服务层流程为「**备份 → 重建 → 替换 → 自检**」，备份前可能先合并 WAL 日志。重建失败时不会用产物替换源库；替换后的自检失败会尝试从备份还原。遇到失败请先查看报告中的实际阶段、备份及还原结果，再决定后续操作；
- 替换会**先关掉正在打开的这个账号**，修完（或替换阶段失败）由全局的倒计时浮层**倒数几秒回
  首页**；
- 修复完成后可以**回滚**，也会留下修复记录。

### 空间与缓存位置

- 选中数据库后，分别显示缓存卷、原库卷的可用空间、预计新增峰值和建议预留空间；位于同一卷时合并为一项，按修复阶段的峰值计算。预计峰值包含未合并 WAL 可能带来的主库增长，建议值再加 25% 与每卷 64 MiB 缓冲；两者都不是最大占用保证。
- 低于预计峰值时拦截修复；预计峰值足够、只是建议余量不足时仅警告，可在确认区勾选接受风险，再点「仍要继续并修复／迁移」。这不会跳过备份、指纹复核或自检；空间变化后会在实际开始时再次判断，实际占用超过估算仍可能失败。取消确认或换库／缓存位置后需重新确认。
- 「修复缓存」右侧的文件夹按钮可选择备份和临时工作文件的位置，回转箭头恢复默认。历史索引与报告保持原位，已有备份不会被自动迁移或删除，仍可从原记录回滚。自定义目录失效时停止新修复，不创建替代目录。
- 新原生组件在重建完成后释放明文源副本，并直接生成带 QQ 头的加密产物；旧组件仍按较高的中间文件预算预检。最终临时产物始终留在原库同目录，以便安全替换。
- 备份优先尝试文件系统的独立写时复制克隆，不支持时正常复制；预检不依赖这部分节省。成功与失败的修复记录均按默认最近 3 份保留备份，历史记录保留；手动「只备份」生成的独立备份不受该记录保留策略管理。
- 当前自定义位置下的修复数据也会计入存储管理，清除时需确认失去回滚能力并退出应用，不参与普通缓存清理。

### 布局迁移（旧版误修复的大库）

旧版 WeQ 在 1 GiB 以上的 QQ 库上可能把它误判成损坏，并用 standard SQLite 的页布局
「修复」出一个错位库：第 `262144` 页是真实数据，而 QQ 认为它是保留页。新版本不会在启动
时自动检查；**只有进入这一页并选中库**时，才会读两个 4 KiB 页做判断：

- 文件不超过 1 GiB：不检查，直接按普通修复处理；
- 第 `262144` 页有数据、第 `262145` 页全零：判定为旧版误修复的 standard 布局，面板会
  显示「布局迁移」优先按钮；
- 第 `262144` 页全零、第 `262145` 页有数据：QQ 布局，正常；
- 其它组合：不提示迁移。

布局迁移与普通修复共用同一条流程（备份 → 重建 → 替换 → 自检），区别是
按 standard 页号读出全部数据、再写回 QQ 布局。它同样会关掉当前账号并回到启动页；失败
时请以报告中的实际阶段与备份状态为准。旧版 native 产物不支持这项能力时会在替换前中止并提示更新产物。

#### 「占用」那一格怎么读

环境检查里的「占用」分三档，处置完全不同：

| 显示 | 含义 | 要做什么 |
| --- | --- | --- |
| **可以开始** | 没有进程持有这个库 | 直接修 |
| **QQ 正开着这个账号** | QQ 在写这个库，边写边读会读出撕裂的页 | 点「结束 QQ」（或自己关掉那个账号的 QQ） |
| **WeQ 自己开着（会自动释放）** | 占着它的就是 WeQ 本进程 | **什么都不用做**，替换前会自动关掉这个账号 |
| **被其它程序占用** | WeQ 之外的进程占着，我们关不掉它 | 自己把那个程序关掉再修 |

> [!note]
>
> Windows 上「WeQ 自己开着」几乎每次都会出现：Restart Manager 枚举的是**谁把这个文件打开
> 着**，而 WeQ 读消息时就握着这个库的连接。那是我们自己的句柄，替换前会主动释放，所以它
> **不拦修复** —— 不要为它去退出账号（面板本身也只能在账号打开时进入）。
>
> 结束 QQ 后的等待也一样：如果库里剩下的持有者只有 WeQ / Electron 自己，面板会**静默当作已
> 释放**，不会再报「可能还有别的东西在用」。

> [!warning]
>
> 修复目标在渲染层只用**库名**标识，目录、密钥、算法都在主进程解析 —— 这样接口不会变成任意
> 路径写入器。

## 4. ntqq 抓包

非侵入式读网卡（**不注入、不改 QQ**）：TCP 重组 → MSF 帧切分 → 用该会话的 d2key 做 TEA 解密。
版式参考 reqable：左侧会话表（同一 `seq` 的发包 / 收包合成一行），右侧出该方向的
总览 / 解密数据 / 原始数据。

- 顶部工具条选一个**在线账号** →「开始抓包」→ 可选暂停 / 继续 / 停止 / 清空；
- 过滤条可按方向（全部 / 发包 / 收包）+ 关键字（命令字 / seq）筛；
- 解密数据栏对正文自动按 protobuf → JCE → 去长度前缀的顺序解析成 `{tag: value}` 树；
- Windows 需先装 [Npcap](https://npcap.com/)；Linux/macOS 需要 root，会弹授权窗口把抓包
  会话放进临时提权子进程（WeQ 本体不以 root 运行）。

### 导出

工具条的**「导出」**按钮把当前列表里**符合过滤条件**的帧（也就是眼前看到的这些）导出成文件，
下拉里选格式：

| 格式 | 内容 |
| --- | --- |
| **JSON** | 一份自包含文档 `{ meta, frames }`，每帧带 `decoded` 解析树与 raw / plain / body 的 hex |
| **JSONL** | 每行一帧，方便 `jq` / `grep` 流式处理 |

桌面端弹系统保存框、落到所选路径；Web 端写进服务端导出目录并直接触发浏览器下载。
导出结果会以一条提示（含帧数 / 体积 / 路径）反馈。

## 5. Protobuf / JCE 逆向

把 hex / base64 输入，按 **protobuf** 或 **JCE**（QQHook TarsParser 语义）解析为 `{tag: value}`
的简洁 JSON（对齐 CyberChef 的 Protobuf Decode）。**嵌套 message 会自动逐层展开**，不用再手动把
子字段的 hex 拿出来二次解析；`tag ≥ 1001` 的字段名直接跟在字段号后面显示。

顶部可切换两种视图：

- **简洁**（默认）：纯 JSON，只有字段号与值 —— 能当可读文本的 bytes 直接给字符串，其余给 `0x…` hex。
- **详细**：每个值旁再出现转换按钮，用于逐个值做旁路解读：

| 类型 | 可转换 |
| --- | --- |
| bytes | hex ↔ 文本 / Base64 / 按 protobuf 解析 / 按 JCE 解析（支持混合嵌套） |
| 整数 | 有符号 ↔ 无符号 / bool / 时间戳 / zigzag / hex |
| fixed64 / fixed32 | 整数 ↔ float |
| 字符串 | 文本 ↔ hex |

面板支持自动识别格式、复制结果、清空、载入示例。适合研究 QQ 协议里那些二进制字段。

> [!note]
>
> MCP 的 `decode_blob` / `decode_db_blob` 也是同一套输出：纯 JSON `fields` 树（嵌套自动展开）
> 外加一个 `names` 图例，把树里出现过的 `tag ≥ 1001` 字段名单独列出来，避免字段名把数据树撑长。

> [!tip]
>
> **开头的长度前缀会自动识别并剥离**。抓包 / 内存里经常拿到形如 `00 00 00 D5 0A 08 …` 的字节：
> 前几字节是长度头，直接解析会让游标跑偏。解析器会枚举 4 / 2 / 1 字节 × 大端 / 小端，
> 只有「读出的值 = 整包或负载长度」**且**剥完能完整解析时才采用，所以不会硬编码「砍 4 字节」，
> 正常数据也不会被误削；命中时结果里会标出剥掉了什么。

## 6. QQ 登录账号管理

管理**本机 QQ 的登录记录和设备标识**，数据来自 `login.db` 及设备标识文件。修改前需要退出所有 QQ 实例，重新启动 QQ 后核对结果；不需要重启 WeQ。

### 页面内容

- 顶部是本机**设备 guid**（服务端认设备的依据，可一键复制），旁边一枚「随机更换」；
- 下面每个账号一张卡片：头像 / 昵称 / QQ 号 + 「快速登录」徽章（该号在 `login.db` 里有缓存的
  a1）、上次登录时间，以及**数据目录还在不在**（只有登录记录、目录已经被删的号会标出来）。

### 三个动作

| 动作 | 做了什么 | 影响 |
| --- | --- | --- |
| **移除快登** | 清掉 `login.db` 里缓存的 a1（`[1004]`） | 账号行还在，但下次 QQ 启动它不再出现在快速登录列表，要重新输密码 / 扫码 |
| **删除账号** | 从 `login.db` 删除该账号的登录记录 | **不会删除聊天记录与账号目录**；不等于注销 QQ 账号，后续仍可重新登录 |
| **随机更换 guid** | 随机生成设备 GUID 并写回本机设备标识文件 | 改变后续请求使用的设备标识，可能影响设备识别或触发登录验证，请在重新启动 QQ 后核对 |

### 必须「所有 QQ 都退出」才能改

三个写操作都受同一条闸门约束：**检测到有 QQ 实例在运行就全部置灰**，页面上会写明原因。

因为 `login.db` 与设备标识文件（Linux `global/nt_data/msf/machine-info`、macOS
`machineid-info`、Windows `<msf>\Registry20`）都是 QQ 常驻读写并缓存在内存里的 —— 在线时改完
会被它覆盖回去（Windows 的硬件回退甚至会自动重写自己的缓存）。与其做一个静默失效的按钮，
不如要求先退出 QQ。实例数用 QQ 自己记的 `launcherCounts` 判断，不数进程。

> [!note]
>
> 换完 guid，WeQ 自己存的那份账号配置会一起同步（guid 与按旧 guid 解出来的 a1 payload 缓存），
> 所以之后从 WeQ 发起的快速登录 / 抓包 / 在线识别不会拿旧 guid 去冒充新设备。

## 7. 完全离线模式

「自动读取 QQ 内存（完整功能）」位于[设置 → 账号与消息 → 接入与监听](./settings.md)。关闭后，依赖此能力的入口进入**完全离线模式**：

- 依赖在线实例的功能（其它设备的密钥、需要发包补齐的导出等）会明确提示不可用；
- 本地记录查看、本地文件导出、密钥扫描等不依赖在线 QQ 的功能仍可使用；涉及缺失媒体或在线记录的内容可能无法补全。

此开关不代替所有功能的网络设置。克隆、助手及其他 API 功能仍可能按各自配置访问服务商，使用前请核对对应页面的联网说明。
