# QQ 在线操作

这些入口会真实修改 QQ 侧的数据，不是 WeQ 的本地显示设置。需要当前配置具备 QQ 在线能力；同号在线配置与静态配置仍按配置 ID 区分。

## 入口

| 位置 | 操作 |
| --- | --- |
| 窗口标题栏头像 → QQ 资料与状态 | 昵称、签名、性别、头像、基础／扩展／自定义在线状态；手动查询服务端状态 |
| 好友资料／成员资料／个性主页 → 赞资料卡图标 | 选择本次次数并提交资料卡点赞；本人、机器人或缺少真实 UID 时不提供入口 |
| 会话设置 → 会话偏好 | 好友／群备注、置顶、免打扰、已有好友分组；自己的群昵称与专属头衔文本 |
| 群文件侧栏 → 工具栏／行菜单 | 文件和文件夹选择、保存、重命名及删除，文件移动，文件夹新建，本机文件拖入上传，数量与空间 |
| 群资料侧栏 → 群公告 | 独立公告摘要，点击标题进入公告管理：发布、附图、置顶、需要确认、新成员公告、弹窗提醒、群名片引导及删除 |
| 群资料侧栏 → 群待办 | 直接查看列表、完成待办；群主／管理员取消待办 |
| 群资料侧栏 → 打卡 | 今日打卡，按北京时间日期查看打卡名单及翻页；打开页面本身不打卡 |
| 群相册 → 打开相册 | 图片上传；具备媒体定位的项目可删除、点赞／取消赞及发送评论 |
| QQ 空间说说下方 | 点赞、取消赞、文字／带图评论 |
| 自定义表情资源页 → QQ 收藏表情管理 | 从服务器读取收藏、添加图片、改备注、调整顺序、删除及导出收藏包 |
| 好友通知／群通知卡片内 | 对收到且仍待处理的好友、可疑好友、加群及过滤申请直接同意／拒绝；退群通知与自己发出的申请不提供审批按钮 |
| 会话设置 → 群管理（仅群聊） | 群名、群头像、加群方式、分类标签、退群 |
| 群消息右键菜单 | 设置／取消精华，设为群待办 |
| 群资料侧栏 → 精华 | 查看精华；有权限且消息定位齐全时可取消精华，取消按钮与消息跳转分开 |
| 群消息头像或群资料侧栏成员头像右键 | 修改自己的群名片，群主／管理员可修改低职权成员的名片；仅群主可编辑专属头衔 |
| 私聊输入框工具栏的键盘图标 | 开启／关闭“正在输入”广播，按账号、数据源和会话记忆；未设置时跟随全局默认（初始关闭），每十秒最多发送一次 |
| 群聊输入框输入 @ | 候选首项为“全体成员”，右侧显示本账号及群剩余额度；权限、额度或在线状态未核实时不可选 |
| 机器人消息内联键盘 | 链接继续走外部链接；定位与机器人信息齐全的回调按钮可在确认后提交 |
| 联系人 → 群聊 → 加入群聊，或左栏添加菜单 → 申请加入 QQ 群 | 读取分享链接对应的群资料与验证问题，填写回答并申请加入 |

## 加群与状态

群聊的“全体成员”候选不依赖成员列表是否已经加载到自己。打开候选时按当前账号与配置读取权限和额度，不顺带查询打卡，也不新增持续轮询。只有群主／管理员、远端允许且个人／群额度均大于零时可选；离线、读取失败和权限未知会明确显示，未知额度不写成零。选择只插入提及 token，不发送消息；实际发送仍以 QQ 服务端结果为准，其他设备的即时额度变化不由该菜单实时推送。

群资料、群公告和群待办在同一侧栏分区竖排，长内容在各区内部滚动；内容少时按实际高度收缩，下方保留群成员列表，不需要在公告与待办页签之间切换。

群待办标题与摘要正文都可打开详情。详情打开时保留并隐藏原资料栏，关闭后恢复。待办列表合并本地已有摘要与在线读取结果，同一消息采用在线状态；离线仍可查看本地缓存，读取失败不会显示成“暂无群待办”。在线接口未返回某条本地摘要不代表它已被取消，本地缓存也不代表其他设备的实时状态。

消息菜单、精华列表和消息角标共用精华状态。提交后通过普通读取接口核对，读到目标状态再更新显示，失败或确认超时时保留原记录，不自动重发写请求。加载、成功和超时都显示在右下角横幅中，不在消息或列表旁附加提示。只有本地记录、缺少原消息 `random` 时，不猜测定位参数，取消按钮会说明缺口。

通用加群需要有效的 QQ 群分享链接，不提供任意群号生成鉴权串的功能。鉴权串只保留在主进程；读取的目标短时有效，过期或目标变化后需要重新读取。验证问题显示“无法获取”不等于该群没有问题；多问题表单尚未证实，当前提交的是单个回答字符串。

入群申请已提交不等于已经入群。非明确回包可能涉及官方安全验证，会显示结果未确认，需先在 QQ 核对。接口不会绕过入群问题、管理员审核或安全验证。

群打卡使用现有的 `0xEB7_1` 写入链路，提交后通过普通接口读取当天名单，在右下角横幅核对当前账号的打卡记录；读取失败与写入失败分开提示。离线验证不代替目标群的真实验收。

标题栏状态来自本地缓存；资料编辑器的服务端状态按钮是独立查询。预设扩展状态使用各自的 `extStatus`，自定义状态使用本机经典表情的 QSid，不能互换成 Unicode 编号。

状态编辑器按基础、扩展、自定义状态排列。扩展状态选择后会显示对应图标和文字预览，点击保存才提交；自定义状态的表情位于文字输入框左侧。

资料保存收到回执后即可继续编辑其他字段，不必等待后台列表刷新。编辑器会在随后 15 秒内每秒回读本地资料与状态，并同步刷新标题栏；回读不覆盖尚未提交的草稿。超过这段时间仍未更新时，可使用重新读取按钮核对 QQ 缓存，勿因同步延迟反复提交。

## 备注与名片

资料卡获赞数与生日、亲密度等资料并列，右侧点赞图标打开 +1、+10、+20 和铅笔四个圆形按钮；点击铅笔在同一弹窗内切到 1–20 次输入、确认和取消，遵循系统减少动态效果设置。这个范围是本次批量请求的输入边界，
不是“每日还剩 20 次”。每日额度与会员差异由 QQ 服务端判定，当前不展示未经核实的剩余额度。
打开或关闭编辑器不发送请求；发送在途不可重复提交，也不自动重试。

请求提交后会刷新该人的累计获赞统计，不在本地直接加数。累计获赞可能同时受到其他人操作影响，
不能单靠数字变化证明本次请求的准确生效次数。未知回执显示待核对，次数限制或业务拒绝保留实际错误；
核对 QQ 后再决定是否继续操作。本入口已做离线验证，真实每日额度与多端生效仍待验收。

好友备注保存或清空后，按当前账号和数据源回读资料，更新会话标题、联系人姓名与预览。
群名片只更新对应群的成员和预览，不改变其他群的名称；迟到的旧补全不会盖回新值。
群备注作为聊天标题、会话列表与群聊列表的显示名称，资料中的真实群名保留，仍可按真实群名、
备注或群号搜索；清空群备注后恢复显示真实群名。

读回最多四次。QQ 本地缓存尚未同步时保留明确提示，不自动重发写入；刷新失败与远端写入失败
分开处理。切换账号或来源后，旧操作不会把资料回填到新来源。

## 置顶同步

真实好友和群聊的列表右键置顶／取消会提交 QQ 请求，会话偏好里的开关使用同一链路。
操作后有界读回本机置顶表；未同步或读取失败会明确提示，不写 QQ 数据库来伪造生效。
置顶组按 QQ 的置顶时间排列，不再被列表组件重新按最后消息时间覆盖；同秒或缺少置顶时间时回退到消息时间。
克隆与聚合入口的置顶仍属于 WeQ 本地设置，不宣称跨设备同步。

## 消息接收策略

群消息接收编辑器从服务端读取正常提醒、接收但不提醒、群助手与屏蔽四档策略。
保存后最多进行四次读回，不重复发送写请求。服务端已更新而 QQ 本地缓存仍是旧值时，
编辑器显示服务端值，并提示“服务端与本机消息策略尚未同步”；这不代表其他设备已完成同步。
手动重新读取仍可重试，切换账号、数据源或会话后不继续旧操作的回读。

好友免打扰从 QQ 云端完整好友名册读取，不再依赖本机资料是否已经同步，也不从会话提醒级别推断。
读取期间禁止重复切换；读取失败可以重试，不使用旧缓存冒充当前状态。完整名册中缺省的免打扰属性
按关闭处理，异常属性值保持未知；账号或好友身份不匹配、分页不完整时不会产生关闭结果。
切换后最多四次只读核对，不重复发送写请求，只有云端读回一致才提示生效；不代表其他设备的通知效果已经验收。

## 群头衔显示

展示头衔选择、云端等级查询和本机显示开关已从会话设置撤下，不再为显示徽标查询或修改服务端的头衔选择。
群消息与群成员列表统一采用「专属头衔 > 群主／管理员 > 等级头衔」的文字优先级；群主橙黄色、管理员青绿色、普通成员专属头衔紫色，其余灰色。
「我的专属头衔」及群成员资料中的专属文本编辑仍保留原权限检查。具体显示规则见[聊天窗口](./chat-view.md#2-聊天窗口)。

## 分类标签目录

群管理中的目录按当前群的分类读取。服务端只返回名称、没有数字编号或类型时，内部保留未知，不补成 0；同名记录合并显示返回条数。
目录读取遇到截断或异常字段时显示错误，不展示部分解析结果作为有效目录。合法空回应只表示本次没有返回目录项。
这里的创建／删除操作针对分类目录，不等于已将标签应用到当前群；选中、绑定和应用结果核验仍在后续需求中。

## 群文件管理器

群文件使用同一张列表浏览和操作，不再另开“文件操作／操作目标”表单。列表展示名称、大小、上传者与
北京时间，可按名称、大小或最近修改排序；搜索只筛选当前目录。窄面板把次要信息放在名称下方，保留完整名称与保存菜单。
单击选择，Shift 连选，Ctrl／Command 追加选择，也可使用复选框。工具栏与右键菜单作用于所选项目；
文件夹通过名称、双击或 Enter 打开，面包屑可逐层返回。搜索直接定位到未知祖先路径的目录时，
显示“定位目录”，返回入口回到全部文件，不猜测其父目录。

重命名与新建在列表上方编辑，移动时浏览并选择目标目录。普通成员只能管理自己上传的文件；
文件夹的新建、重命名和删除需要群主或管理员，文件夹暂不支持移动。提交前重新读取目录并检查
同名冲突，不会静默替换已有项目；其他设备在检查后产生的变化仍以 QQ 实际回执为准。

在桌面端拖入本机文件，或将文件拖到某个文件夹，会先进入待上传列表，允许修改名称和移除，确认后
才上传并发布群文件消息。同一路径、同一目标不会重复排队，待上传列表最多 100 项。
Web 无法取得本机路径时可使用文件选择入口，不会把浏览器临时地址当成服务器文件路径。
群内文件拖到目录同样先准备移动，确认提交；跨账号、跨来源或跨群的内部拖拽会被拒绝。

批量操作逐项执行，通过普通目录读取核对结果，确认进度与结果只显示在右下角横幅中。停止只停止后续项目，不撤销已经提交的请求；
不要求明确写回执，执行异常时停止后续项目，也不自动重发。保存所选文件与文件夹复用公共保存偏好和后台任务，
保留已知的相对目录结构；取消位置选择不清空选择、不创建任务。离开目录前会保护未提交的编辑和上传列表。

## 收藏表情包导入与导出

聊天输入区的表情选择器切到「收藏」后，也提供导入、导出和保存菜单；导入完成会重新读取收藏列表。它与收藏表情管理使用同一套账号绑定和收藏包流程。

导出工具的表情包页面可选择「图片目录」「ZIP 图片包」或「ZIP 收藏备份（含元数据）」。前两种按所选的我的表情／收到的表情输出图片，按图片文件头修正扩展名，原样保留 GIF、APNG 等动态图片字节；收藏备份则只使用当前账号的在线收藏，并保存原图、备注和顺序，供后续导入。

收藏表情管理右上角的下载图标导出当前账号的在线收藏快照。旁侧保存菜单沿用统一保存设置，可另存到指定位置，或先生成后在任务列表保存；Web 端可在任务完成后下载 ZIP，服务器保存与浏览器下载是不同操作。

收藏包保留原图字节、备注与来源顺序，同图只存一份。在线列表决定导出范围，不把本地缓存中其他散图混入。原图从当前账号的原图缓存或已登记的 QQ 图片地址读取，缺失、下载失败或图片校验不符时保留失败条目，不退成缩略图。任务列表分别显示成功和失败数量；生成 ZIP 不代表每张原图都已导出。

在线详情按小批次依次读取，但仍导出全部在线收藏，不限于第一批。读取与排序使用同一条串行路径，QQ 进程变化后会中止旧请求；读取失败不会自动重复上传。

桌面端的上传图标可选择 WeQ 收藏包 ZIP。预览中点击条目看图，勾选要导入的图片；已存在、包内重复和校验无效的条目不可勾选。确认添加后，新增图片按包内相对顺序放在 QQ 收藏最前，恢复各自备注；同图已存在时跳过，不覆盖现有备注和顺序。Web 端暂不支持选择本机收藏包导入。

单项排序只提供“移到最前”，不提供任意位置或上下移动。在线列表和导出的位置按 QQ 收藏面板的显示方向排列。

导入进度在预览窗口内逐项显示，也可从工具栏重新打开；“已添加，元数据需核对”与“结果未确认”不是完整成功。停止只阻止后续操作，已发送请求无法撤销；需要等待在途请求返回，不要直接重复上传。上传结果不明时会停止后续图片，先在 QQ 核对并重新读取状态。图片添加后备注或排序失败，也不会自动重传同图。

预览只在当前账号和数据源内短期有效，十分钟后过期；过期或关闭账号会停止后续写入并清理私有预览文件。它不是可断点续作的导入队列，进程重启后不会自动恢复写请求。

单包最多 2000 条，单图最多 20 MiB，图片合计最多 256 MiB。导入也接受普通图片 ZIP，按包内顺序预览和去重，不从文件名推断收藏备注；包内存在 WeQ 收藏清单时仍严格校验，不因清单损坏退回普通图片导入。包内可能含私人图片和备注，分享前请核对内容。

## 确认、结果与权限

联系人图标、好友通知和群通知入口在有未查看的新通知时显示红点；首次成功读取时以已有通知建立基线，不把历史记录当作新通知。打开对应列表后即清除该类提示，不要求先处理申请。查看记录按账号与数据源分别保存在本机，下次新通知到达后再次提示；群资料补齐或申请处理状态变化不会重复提醒。

- 删除文件、文件夹、公告、相册媒体、收藏表情，以及退群、处理申请、发布公告等操作有明确确认。
- 群公告与加群设置需管理权限；其他操作的最终权限由 QQ 服务端判定。
- 提交写入后，右下角横幅显示加载图标和“正在确认操作完成情况”，使用普通读取接口核对目标状态，不要求写接口提供确认回执。读取到目标状态后，同一横幅更新为完成；确认超时也只更新横幅，不在按钮、表单或列表旁附加操作结果文字。
- 备注、昵称、签名、群名片、头衔、在线状态等显式保存入口允许提交当前值，受理后也可主动再次提交。原值不会自动重发；操作在途、权限不足、离线或输入无效时仍会禁用。自动保存的选择框与直接生效的开关保持原交互方式。
- 确认最多读取四次，单次读取长时间不返回时，总确认等待上限为 15 秒；不会自动重发写请求。尚无可核对字段的操作（如群相册个人点赞、评论）和无法读到目标状态的操作会显示确认超时，不把请求受理当作已生效；超时也不表示请求未发送，请重新读取或在 QQ 中核对。
