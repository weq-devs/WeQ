# macOS QQ 调试副本

可以保持 SIP 开启，用 QQ 调试副本提供本机内存读取能力。WeQ 创建独立的
`~/Applications/QQ-WeQ.app`，不改 `/Applications/QQ.app`，不关闭 SIP。
副本与原 QQ 共用数据目录、登录态和热更新，不是独立的账号数据环境。

## 准备与使用

1. 在账号选择页点击「QQ 调试副本」，或进入「设置 → 账号基础 → QQ 调试副本」。
   SIP 开启且 QQ 不在线或缺少在线凭据时，「受限模式」详情也提供同一入口。
   离线时请在此创建并启动独立的调试副本，在副本中登录目标账号，无需启动原 QQ。
2. 检查「WeQ 读取端」是否显示「调试权限已就绪」。若当前开发宿主未签名或仍是旧构建，
   需要换用包含调试权限的桌面构建；仅创建 QQ 副本不会改变读取端权限。
3. 点击「创建副本」。WeQ 先建立 APFS 写时复制副本，保留原 entitlement，增加
   `get-task-allow`，完成本机 ad-hoc 签名及校验。准备失败时保留原安装及已有副本。
4. 点击「启动副本」，在副本中登录目标账号。其他 QQ 实例不会被自动退出；同一账号若已
   被原 QQ 使用，需自行选择在哪个客户端保持登录。
5. 打开目标账号，在「受限模式」详情中点击「重新检查」或「启用完整功能」。
   如已开启自动完整功能，则沿用自动读取流程。只有实际凭据及在线能力就绪后才显示恢复。

受限详情只保留一个「重新检查」，同时刷新副本环境、数据读取授权与当前账号在线状态。
账号选择页和设置中的独立副本管理仍保留自己的检查入口。

「副本已就绪」只代表签名与调试权限已通过检查；「副本正在运行」不代表账号已登录。
启动副本不会自动改变完整功能偏好。系统若拦截本机重签应用，请按系统提示处理单应用放行；
WeQ 不会移除隔离属性或修改全局系统设置。

## 更新与移除

- QQ 的容器内热更新通常不改变副本 bundle。原安装版本变化后，面板会显示「可更新」。
  从副本菜单退出 QQ，再点击「更新副本」。新副本完成校验后才替换旧副本。
- 点击「移除副本」并确认，仅删除 WeQ 管理的副本；原 QQ、账号和聊天数据保留。
- 运行中的副本不能更新或移除。同名位置若已有非 WeQ 管理的应用，不会覆盖或删除。
- 同时只能有一个管理操作。若 WeQ 异常退出遗留 `.lock` 目录，错误中会显示确切路径；
  确认所有 WeQ 已退出且没有管理操作后再移除该锁目录，并重新检查。

副本允许本机具有调试权限的程序读取其内存，只在本机使用，不要分发副本。
网卡抓包仍沿用原有管理员/长期授权；内存能读不代表抓包已授权。

## 截图、麦克风与摄像头授权

原版 QQ 的授权不一定适用于重新签名的副本。创建或更新成功后会自动展开权限引导，
可点「稍后设置」跳过；之后可从副本管理面板的「权限设置」随时重新打开。
无需完成这些授权就能创建、启动副本或读取聊天数据。

- 选择截图、麦克风或摄像头，点击对应按钮打开系统设置。WeQ 无法可靠枚举原版与副本的
  全部系统授权，因此始终提示「待确认」，打开设置或启动成功不代表授权成功。
- 截图：在「隐私与安全 → 录屏与系统录音」（旧系统称「屏幕录制」）中添加副本并开启。
  可用「在访达中显示副本」定位，或复制副本路径，在系统添加窗口按 `⌘⇧G` 输入。
  系统条目可能仍显示「QQ」，不显示「QQ-WeQ」。若旧条目阻碍添加，可先移除旧 QQ 条目，
  再选择副本；原版可能需要重新授权。
- 麦克风、摄像头：先在副本中尝试语音或视频通话触发系统请求，再到对应页面允许 QQ。
  未出现条目时，返回副本触发请求，不使用录屏页面的手动添加步骤。
- 若系统提示退出并重开，选择「稍后」，从副本菜单正常退出 QQ，再点击引导中的
  「授权后启动副本」。该按钮按副本固定路径启动，不使用系统自动重开，不退出原版 QQ。
  副本仍运行时按钮禁用，等待进程状态刷新即可。
- 重新尝试截图、语音或视频确认结果。副本更新、重新签名后可能需要再次授权。

若截图仍无法使用，展开「仍无法截图」查看手动重置方法：先退出两个 QQ，再运行
`tccutil reset ScreenCapture com.tencent.qq`，然后重新添加、授权并从 WeQ 启动副本。
该命令也会清除原版 QQ 的截图授权，不删除聊天数据；WeQ 不会自动执行。
仍失败时可临时使用 macOS 系统截图并粘贴到 QQ。
