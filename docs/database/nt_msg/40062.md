# 40062 — 贴表情（表情回应）

`group_msg_table` 的 `40062` 列（`setEmoji`）存**群聊消息的贴表情回应**——
别人在这条消息上贴的商城表情（类似微信的「表情回应」）。一行一个 BLOB，
内容是 protobuf：`MsgEmoji`，里面是 `repeated EmojiSticker`。

- **只有群聊表有这一列**；c2c / dataline 没有。
- 贴表情的变更不产生新消息行：QQ 原地改写该行的 40062，所以「重读当前窗口」
  （`listFrom`）就能捡到新增/变化的贴表情。

对应 WeQ 解析实现：

| 文件 | 职责 |
| ---- | ---- |
| `packages/codec/src/proto/msg/40062.ts` | wire schema（`MsgEmoji` / `EmojiSticker`，tag 的唯一事实来源） |
| `packages/codec/src/domain/msg/row_to_message.ts` | BLOB → `SetEmojiItem[]`（含空占位过滤） |
| `packages/db/src/msg/group.ts` | 群行 SELECT 带上 40062，解码进 `GroupMsg.setEmojiList` |

---

## 一、wire 结构

```text
40062 (BLOB)
└── 40062  repeated EmojiSticker   ← 每项 = 一个贴上的表情
    ├── 48301  emojiId    string  表情 id
    ├── 48302  setFlag    int32   未知标志
    ├── 48303  emojiNum   int32   被贴次数（同表情累计）
    └── 48304  isSelfSet  bool    本机是否贴过
```

| tag | 字段名 | 类型 | 必有 | 含义 | 置信度 |
| --- | ------ | ---- | ---- | ---- | ------ |
| 48301 | `emojiId` | string | ✅ | 表情 id（商城表情的 id，可回指 emoji.db / mface 资源） | 已验证 |
| 48302 | `setFlag` | int32 | | 未知标志 | 观测一致 |
| 48303 | `emojiNum` | int32 | ✅ | 该表情被贴的次数（多人贴同一个会累加） | 观测一致 |
| 48304 | `isSelfSet` | bool | | 本机账号是否也贴了这个 | 已验证 |

> 外层 tag 与列号同名（40062），与 40800 列（外壳 tag 也是 40800）是同一个套路：
> 列本身就是最外层字段号。

## 二、空占位陷阱（必读）

**没有贴表情的消息里，40062 不是 NULL，而是 4 字节空占位** `f2 c7 13 00`
（tag 40062 + LEN 0）。直接解码会得到一个 `emojiId = ''`、`emojiNum = 0` 的假条目。

WeQ 的过滤规则：**`emojiId` 为空的条目一律丢弃**——真实条目的 emojiId 必非空。
`decodeEmoji`（`row_to_message.ts`）在解码后统一做这一步。

## 三、WeQ 的读法

```sql
-- 群行 SELECT 固定带上 40062（见 group.ts 的 SELECT_COLUMNS）
SELECT "40001", …, "40062" FROM group_msg_table WHERE "40027" = ? …;
```

```ts
// 解码 + 过滤（row_to_message.ts 摘要）
const decoded = emojiCodec.decode(sanitizeBytes(blob, MsgEmoji));
return (decoded.stickers ?? [])
  .filter((s) => !!s.emojiId)          // 空占位过滤
  .map((s) => ({
    emojiId: s.emojiId ?? '',
    setNum: s.emojiNum ?? 0,
    isSelfSet: !!s.isSelfSet,
  }));
```

与 40800 正文一样，解码前先过 `sanitizeBytes` 容错清洗（防 wire 类型误声明炸掉
整条记录，见 [40800 · 容错解码](./40800.md#六容错解码-sanitizebytes)）。
