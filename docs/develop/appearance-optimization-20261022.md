# 外观优化与验收范围（2026-10-22）

这是用户“全方位外观优化”的进行中记录，不能用一组公共控件或单个页面通过来代表全应用完成。
沿用现有设计和信息架构，不新增产品流程，不通过隐藏内容、删入口或固定主题色规避适配。

## 共同要求

- 浅色、深色、跟随系统均有效；深色不是简单取反。
- 保留用户原色与背景选择，实心文字、强调文字和必要的描边独立派生。
- 页面保持既有密度与分栏，长文案、窄窗口、工具栏、底部操作区不相互遮挡。
- 键盘焦点可见；悬停不改变控件尺寸；减少动态效果不丢失功能或状态。
- 加载、空、失败、在途、禁用和成功分别可辨认，不用假数据或默认结论填空。
- 复用原图标、头像、图片和既有公共组件，不重造同类控件。

## 本阶段实施

- 提取已有 Hex 规范化与 sRGB 混色到 `shared/theme_colors.ts`，设置选色器、主题状态和助手主题共用；
  不引入依赖、不创建第二套主题设置。新增标准亮度对比计算与可读色派生。
- 实心前景在黑／白间选择，强调字在不改变原色的前提下调整至普通文字对比度；
  hover 同向增加而不降低实心对比度。派生色只影响实际使用对应 token 的控件，不冒称所有旧样式已迁移。
- 清除自定义色后，助手桥接发送当前实际预设色，避免主进程仍保留旧色；无效存储值回落默认。
- 主题动画延迟提交时读取最新主色／背景，并拒绝过时的主题请求；配置恢复也使旧请求失效，
  不让动画旧快照覆盖后续设置。
- 公共按钮、分段选中、主页面导航、己方文字／链接、发送键和确认框接入可读色；
  媒体／语音／贴纸纯内容分支不套普通气泡背景。必要焦点、图标尺寸与窄屏设置行单独修正。
- 浅色描边带中性色基础，避免白色主题把界面边界全部冲掉；语义危险按钮和已有中性按钮保留各自覆盖。
- PostCSS 与值 AST 精确识别“同一规则的纯主题色实心底＋固定白字”，只迁移 61 条前景声明；
  不改变尺寸、背景、图片、渐变、半透明填色或业务交互。工具二次扫描该限定集合为零，不代表全部颜色问题为零。
- 会话／联系人桌面选中行的暗色覆盖改为跟随主题，标题、预览、时间与签名共用相应前景；
  移动端保留透明选中底并使用中性文字，不把实心底的前景直接套到透明底。未读数字与免打扰灰色徽标补充独立语义 token。
- 迁移后另查同类控件的局部覆盖：四条原先向黑压暗的 hover／播放底改用安全派生色，
  危险清理按钮保留红底并使用独立前景，不从用户主色推断红底文字。
