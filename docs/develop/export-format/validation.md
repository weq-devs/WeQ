## 针对性校验

```bash
pnpm test:export-schema
pnpm exec biome check package.json schemas/export/v1
git diff --check
```

规范测试采用 Node 内置 test runner + Ajv 2020-12，使用合成字段、固定字节和假地址，
不读取真实 QQ 数据、不访问业务网络。全部 schema 先做 meta-schema 校验、引用注册和
预编译，再分别校验正例与预期失败反例。

仍按覆盖矩阵逐来源对账。

旧静态 JSON/JSONL 示例保持不变；新增历史夹具同时验证 full/basic 投影和 JSONL 往返。
未以这些结果替代下列业务实现验收；逐项补充要求见[历史兼容对照](historical.md#对照与验收)。

## 兼容性修订（2026-11-05）

已将严格 writer 与兼容 reader 分开：参考模型支持读取 1.x 的新增可选属性，保留完整
结构与原版本，未知 Record 属性参与摘要；JSONL 提交外壳、必填字段、类型、枚举、native
和引用检查未放宽。时间精度与规范 base64 直接由 schema 校验，不猜未知对象的含义。

新增/扩充验证包括：七领域未来小版本属性；header/Record/data/元素/Actor/Observation/
Resource/归档集合的未知属性保留；JSONL 往返与有实际新正文的追加；未知字段被篡改后的
摘要拒绝；已有反例同时走 reader；数字键/浮点/Unicode 的独立规范化预期与固定摘要；
相同和未知观察时间经过 full→basic、JSON/JSONL 后顺序与默认正文不变。未知小版本的
有损投影拒绝执行，不猜字段档位。

修订后 **180 项规范测试通过**，既有静态示例与摘要未修改。生产 reader、查看器、迁移
提取器和导出/增量任务未接入；第五项本轮完成接入顺序与验收契约，见
[业务接入顺序](incremental.md#业务接入顺序与验收)。未转换任何历史原件或缩减历史范围。

## 同格式内容范围修订（2026-11-05）

七领域由 basic/full 两套草案入口合为每领域一个 schema，共 12 个 schema；native 可选，
存在时内部结构、字段类型、来源映射与残余约束仍校验。header.profile 仅说明首次导出
选项，observation.profile 可记录当次选项，读取不按档位分派，取得/解析覆盖另行记录。

同一归档允许从真实来源补充 native，随后 basic 扫描不删除旧附加数据；有损投影不强制
分配新 archiveId，也不修改原 full。新增两项回归并调整原先仅因 profile 不同而拒绝的
断言，改为检查有效统一结构及实际缺字段错误：**182 项规范测试通过**，12 个 schema
自校验及引用预编译通过，原有静态示例与摘要未修改。仅修改文档/schema/规范工具，
WeQ 主程序、实际导出、查看器、定时和增量任务均未改动。

## 后续业务实现仍需验证

- 提取器枚举实际来源全部字段、重复 tag 与缓存变体，证明已消费与残余覆盖完整；对输入
  中尚无 schema 声明的新增字段做反例，不以当前 RenderElement 当黄金完整样本。
- 原位更新的独占 writer、外部修改检测、JSON 原子替换、JSONL fsync 和截断恢复；真实
  断电、盘满、掉盘、损坏文件、权限变化及跨平台文件系统行为。
- 长归档的流式读取、索引重建和峰值空间/内存；此处参考模型在内存处理合成样本，未作
  大数据性能验收，也不宣称增量更新完全没有临时空间占用。
- 下载与来源状态分离；本地/在线媒体和转发补全沿用现有完整服务，覆盖 rkey 回退及多级
  缓存，不用单条旧 URL 的失败代表无可用资源。
- 两档 UI、独立媒体选项、增量支持选项的格式依赖，以及查看器/定时任务/旧格式导入。

本轮不运行全量 CI、不打包、不安装、不发布、不推送，不转换或清理既有归档。
