# WeQ 导出格式设计

状态：**设计与生产接入并行维护**，2026-11-05（北京时间）。正式读写、当前业务适配、
查看投影及聊天增量已开始接入，具体源码与验证范围见[实施记录](../unified-export-implementation-20261105.md)。
schema 的完整覆盖要求不等于所有来源字段已取得；应用版本未修改，个人历史归档未批量转换。

## 通用设计理念

导出应交付可长期读取、分析、补全的数据，而不只是某个页面的显示结果。数据库、
网络缓存和本地生成记录是来源；规范化内容是正式产物；HTML、文本和表格是视图。
读取者不应依赖 WeQ 的安装、原 QQ 缓存路径或一份隐藏的正文基线。

1. **基本内容不是缩略内容。** `basic` 回答谁、何时、在哪里、以什么顺序、表达了什么。
   媒体、文件、引用、转发内部消息、评论回复、工具过程属于内容，不能拍成占位文本。
2. **全部数据不是再附一份原件。** `full` 包含 basic 的相同语义内容，加上所选对象及其
   关联来源中全部其他字段。未知不等于无用；当前解析器不认识的字段也有保存位置。
   不复制整个数据库、不混入未选对象，也不以原数据库快照替代字段覆盖。
3. **一种信息只保留一份权威表示。** 能完整表达的已知字段存规范化值；来源到字段的
   映射不带值。未理解、类型冲突、不可无损规范化的部分保留原值或字节。不得同时保存
   整行原始数据和同一行的已解析字段，也不同时保存整个 BLOB 和从中消费出的已知值。
4. **关联和差异不应抹掉。** 原消息与转发内消息、空间原帖与转发文案、收藏摘要与详情
   不是可以任意互换的内容。不同来源有冲突就保存不同版本或关联对象；相同字段的相同
   值可以复用，独立原文中实际不同的信息必须保留。
5. **事实与处理状态分开。** 档位、来源取得覆盖、解析覆盖、资源下载状态各自记录。
   `full` 不代表所有服务端历史已取得；列表走到末尾不证明正文、评论、附件也完整。
6. **正式数据就是后续输入。** 身份、版本、来源观察、资源关系随 JSON/JSONL 公开保存。
   索引和检查点只加速访问；丢失它们应可重建，不再额外保存一整份正文 journal。

## 适用对象

普通私聊、群聊、数据线、服务号、公众号、频道私聊共用消息模型；空间包括说说、
评论回复、转发、相册和照片/视频，以及历史日志、留言、分享、空间收藏和逐次访问；QQ 收藏覆盖当前八类内容及未知类型；邮箱包含每封
邮件而非会话摘要。联系人、群、成员、本地生成对话及资源目录均有独立身份。

群文件、群相册、各类表情、装扮、生成附件，以及已存在的报告/机器人包文件清单，
使用资源目录模型。数据库 `.db`、PNG 长图、HTML 报告及机器人运行包本身不改成 JSON；
只为它们已有的结构化元数据、文件关系和取得回执提供 schema。历史实体已能由 schema
表达，不表示新增空间日志/留言等在线采集能力；频道群聊仍未接入。多个账号及未知账号
分区可组成同格式 archive set，不要求合成一个 archive。正式保存 full，basic 可按需投影，
不强制常驻两份正文，既有 raw 原件保持原样。

本目录保存设计、schema、示例和规范验证工具；业务接入在实施记录中单独验收。普通消息已
补实际 SQL 列枚举和原生 wire 提取，其余来源仍须按覆盖矩阵逐项核实，不能仅凭统一封装
宣称来源全量或历史迁移完成。

兼容性修订：保留全部既定历史覆盖；严格 writer 与兼容 reader 分离，允许同主版本新增
可选字段并原样保留，摘要覆盖未知属性；观察/资源顺序成为正式语义。生产接入与历史迁移
的顺序和验收见 [增量契约](incremental.md#业务接入顺序与验收)，仍不冒称已经实现。
