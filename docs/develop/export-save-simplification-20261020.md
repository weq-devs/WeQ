# 保存位置逻辑简化（2026-10-20）

## 目标与边界

全局设置管理长期偏好，下载／导出按钮菜单管理本次例外，任务列表管理完成结果。常用全局模式收敛为每次询问和默认文件夹，明确保存过的旧 `after` 偏好继续兼容；单次选择不改写全局默认。

单文件使用另存为，多文件使用目录选择；Web 区分服务器保存和浏览器下载。取消不算失败，已生成结果不丢失；目录不可用时重选，不静默回落到其他位置。

## 第一阶段：任务完成后的另存

已实现的本阶段范围：

- `ExportSavePolicy` 增加互斥的单文件 `filePath`；`after` 仍清除位置。文件／目录均要求绝对路径。
- 单文件先在目标同卷私有目录复制并校验，通过无覆盖硬链接发布；报告先以 `<文件名>.report.json` 发布，主文件冲突或取消时只撤销本轮仍属于本次副本的报告链接。源缓存始终保留。
- 桌面目录必须仍可用，不创建缺失位置作为替代；Web 明确指定的子目录可在已核实的服务器导出根内创建。
- `saveExportTaskOutput` 未提供位置时，按任务真实的 `bundleDir` 决定文件框／目录框。用户取消返回 `null`；文件选择返回后重新核对账号和配置绑定。
- 保存状态与生成状态独立；再次另存失败仍保留上次成功保存的路径。任务详情只通过任务 id 打开已记录结果，不接受前端提供任意打开路径。
- 批量保存遇到取消后停止，不把未保存的生成结果记成失败；Web 仍由现有服务器子目录表单明确选择位置。

本阶段没有更改全局默认模式，也没有移除页面保存配置栏。原有助手卡片与其他独立下载入口尚未全部改走新管线，不能据此宣称整个保存逻辑已完成。

## 后续阶段与进展

第二阶段已接入常用默认偏好：首次使用及未声明合法模式时采用 `before`，明确存过的 `after` 不变；全局设置正常只展示询问／默认文件夹，当前旧偏好才额外展示兼容项。首次启用自动保存但没有文件夹时先选择，取消不改变模式。未读到全局设置前不启动保存准备；无交互后台任务遇到没有位置的隐式 `before` 时先生成，保留任务结果等待保存，显式传入缺失位置的 `before` 仍拒绝建任务。

该偏好阶段的 41 项服务回归、13 项桌面回归、服务与渲染层类型检查通过；4 组深浅主题／宽窄窗口检查通过。保存设置在窄窗口上下排列，旧偏好文案和路径不会挤占按钮。

生成前按真实输出选择文件／目录和其他独立入口仍待后续阶段，整个目标尚未完成；统一任务的数据源绑定见第四阶段。

第三阶段已接入统一任务入口的本次操作菜单：导出工具正文和商城表情不再挂载 `ExportSaveControl`，商城多选也不展开它；聊天／频道／空间／名单／收藏、生成对话、表情包和商城下载的按钮可传入本次 `before`／`after` 意图，不修改长期偏好，普通按钮重新使用全局默认。意图在任务配置提交时冻结，不借可变草稿改写在途请求。

Web 的 `before` 在需要时展示服务器子目录弹窗，确认前不发保存准备请求；取消或卸载会结束等待，路径仍交由服务端做导出根约束。相册／群文件的独立下载、明文数据库、助手卡片和其他独立资源入口，以及生成前的输出形态与数据源绑定仍不在本阶段完成范围。

第三阶段的 56 项相关桌面回归、渲染层类型检查通过；导出工具、商城及 Web 位置弹窗共 12 组深浅主题／宽窄窗口离线渲染检查通过。未打开真实系统选择器，也不把这些检查算作所有下载入口已统一。

第四阶段补齐统一任务的准备／创建绑定：

- 保存草稿按 QQ 号与配置 id 隔离，目录与单文件位置不会带入另一个同号数据源。旧回包只在原来源仍有效时可继续使用；Web 位置弹窗在来源切换后取消。
- 保存准备请求携带预期身份，服务端在等待选择器前后核对 QQ 号、配置 id 与服务实例；纯全局位置操作仍可在未登录账号时使用。
- 聊天、频道、收藏、计划、商城及表情包创建入口接受预期来源，名单／空间／生成对话沿用已有身份边界。频道读取元数据后再次核对实例，聊天批次每个目标创建前检查来源。
- 聊天批次固定调用时的目标、精确消息 id、格式、选项、保存位置与身份；批次中途来源失效时不回滚已创建任务，停止后续目标并注明已建数量。
- 偏好读取失败明确报错，不能当成取消或猜测默认目录。本阶段未改造其余独立下载路径，也未完成生成前按输出形态选择位置。

该绑定阶段 72 项相关桌面回归、桌面主进程／渲染层及 Web 服务端类型检查通过。验证使用模拟来源和传输，不读取真实聊天库，不打开系统选择器。

1. 两种常用默认模式与旧偏好兼容；新使用场景优先询问位置，后台无交互任务明确保留稍后保存语义。
2. 页面保存栏与多选自动展开改为下载／导出按钮菜单，提供本次另存和先生成，临时路径不写全局。
3. 开始生成前按输出形态选择单文件或目录，处理目录失效和单次覆盖，并把身份保护扩展到其余独立入口。
4. 核对商城表情、消息／名单／收藏／群文件／相册、克隆与助手、独立资源下载和 Web 保存入口，复用现有格式、发布和任务能力，不另建第二套导出引擎。

## 验证原则

使用合成内容、临时文件夹和模拟原生选择器，不读取真实 QQ 数据、不打开用户的系统保存框。检查单文件、旁附报告、重名冲突、取消、缺盘／目录失效、生成结果保留、旧保存位置、Web 根目录约束与账号绑定；界面同时检查深浅主题和窄窗口。

第一阶段验证：59 项服务回归、36 项桌面回归通过；桌面主进程／渲染层、服务与 Web 服务端类型检查通过，4 组深浅主题／宽窄窗口检查通过。未运行全量 CI，未打包安装，也未打开真实系统保存框。
