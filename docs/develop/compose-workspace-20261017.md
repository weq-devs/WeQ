# 合成工作窗口与归档

日期：2026-10-17（北京时间）。需求来自 UX 补充 S33–S34。完整施工目标仍包括独立工作窗口、方便添加现有消息、素材库/合成记录双 tab，以及条目的发送、转发、复制、导出和拖入合成。

## 当前状态

本批先实现归档底座与账号绑定接口，**尚未完成独立窗口和素材库界面**。既有可修改草稿继续由 `MergeForwardDraftStore` 管理；不把它的覆盖保存当作合成历史。

新增 `MergeForwardArchiveStore`：

- `material` 为可跨合成复用的素材快照，`history` 为每次明确归档的合成内容快照；两者分开列出，追加时生成新 UUID，不覆盖旧条目。
- 记录保留来源草稿 ID、发送者、节点顺序、时间、来源消息 ID 和原始装扮字段。节点和分段先深拷贝，后续编辑源草稿不影响历史。
- 永久数据位置为平台应用数据目录下的 `merge-forward/<configId>/archive/`，不放入可清理的预览缓存，也不写 `unknown` 目录。
- 已下载图片、语音、视频、文件及视频封面流式复制并计算 SHA-256，按内容身份复用媒体文件。副本以私有权限写入并在关闭流时刷盘，随后原子写元数据。
- 媒体归档前核对当前账号的媒体访问权限，不能用任意本机路径读取服务端文件。归档内媒体允许再次复用；嵌套媒体递归处理并限制深度。尚未下载或只有媒体占位的内容明确报错，不把远程链接冒称永久副本。
- 删除条目不删除共享媒体，避免破坏另一份素材或历史。失败只清理本次临时文件；不通过扫描名称删除未知文件。独立媒体回收策略仍待后续设计，当前不宣称已有自动回收。
- 归档写入失败直接抛错，不沿用旧草稿静默吞掉落盘失败的策略；损坏的元数据也不冒充空列表。

## 接口

`mergeForward.archiveList`、`archiveAppend`、`archiveRemove` 均要求 `expectedAccountUin` 与 `expectedAccountConfigId`，以区分同一 QQ 号的不同数据源。新接口没有未绑定账号的兼容入口。

创建请求时捕获当前账号对应的存储与媒体服务，异步媒体复制不在中途重新读取可变的全局服务对象。未打开账号不允许使用旧草稿接口创建 `unknown.json`。

列表读取会登记归档内媒体为可预览，重启后仍使用独立副本。非媒体分段即使携带 `path` 字段，也不能将该路径加入预览信任名单。
