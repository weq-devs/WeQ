# Web / Remote 体验优化（2026-10-26）

## 范围

修改共享 renderer 的 Web 连接反馈、手机导航及重型工作区加载。不修改手机原生壳、
配对协议、设备凭据或服务开关；不重启现有服务。桌面端同样复用工作区按需加载，
连接提示和恢复补查仅在 Web 目标启用。

## 实现

- `transport.web.ts` 使用已安装的 tRPC 10.45.4 `createWSClient.onOpen/onClose` 回调记录
  连接状态。订阅恢复仍由 tRPC 处理；不另建连接、不重放 mutation。HTTP 批次设置
  `maxURLLength: 2048`，避免多个查询叠成过长 URL；不是单个大查询输入的长度保证。
- `WebConnectionStatus` 延迟 1.5 秒显示连接提示，成功即收起，卸载清理计时器。
  首次握手不补查；只有成功连接后的断线恢复才使活动 React Query 查询失效并补查。
- `MainView` 在恢复时标记会话窗口缓存待校准，调用已有的会话头、未读和当前消息窗口
  刷新路径，覆盖断线期间遗漏的推送。保留现有历史合并、定位和草稿逻辑。
- 手机导航在外部视图切换或详情隐藏状态变化时关闭更多菜单。底栏增加未读可访问名称，
  选中与按压反馈使用现有主题 token，深色会话选中背景单独调整。
- 年度报告、分析报告、关系图和克隆工作区改用 React lazy / Suspense，继续放在原有
  RetainedTabs / WorkspacePage 生命周期内，不提前挂载。分析页原本静态引用年度报告，
  因此两条入口同时拆分，避免仅增加动态导入却仍把模块打入首屏。

## 构建测量

同一工作区、同机 Vite 生产构建，读取 HTML 的入口脚本、样式和 modulepreload 并合计；
gzip 使用 Node zlib 默认参数。不计运行时请求的头像、媒体与业务数据。

| 首屏入口 JS + CSS | 改动前 | 改动后 | 减少 |
| --- | ---: | ---: | ---: |
| 原始字节 | 6,096,039 | 5,556,885 | 8.8% |
| gzip 字节 | 1,555,763 | 1,424,411 | 8.4% |

该结果是资源体积而非手机加载时间。首屏入口仍较大，构建仍有大 chunk 提醒；没有通过
提高告警阈值隐藏。未运行全仓 CI，未进行真机蜂窝切网或首次打开耗时验收。

## 验证

- 5 个针对性测试文件共 14 项：状态转换、首次连接不补查、重复回调去重、提示延迟和
  计时器清理、实际传输回调接线、批次设置、手机导航回归与既有视口测试。
- 桌面 renderer TypeScript 检查、Web 生产前端构建、指定文件 Biome 检查。
- Web 服务既有鉴权、HTTP 和安全测试，以及 Electron 依赖隔离守卫。
- Playwright 合成夹具通过 320 / 390 / 760 / 1180px、浅深色、绿色 / 浅黄色主题、
  paper / dots 背景及减少动态效果检查；覆盖列表、更多、进入聊天与返回、连接提示和
  重连时草稿保留，无横向溢出或页面异常。仅验证页面和状态注入，不代表真实网络重连。
  夹具与截图位于本机 `~/Agents/2026-10-19-WeQ会话交互/work/web-remote-optimization-20261026/`，
  不连接真实 QQ、不读取聊天记录。
