# WeQ 存储管理

设置 → 存储与网络 → WeQ 存储管理，统一显示应用自身的数据占用。

## 统计范围

- 平台 WeQ 数据根：配置、模型、日志、托管 QQ、诊断、合并转发归档等。
- 当前缓存根与默认缓存根：即使改过缓存目录，仍统计默认目录里遗留或继续写入的数据。
- Electron 提供的 userData、sessionData、logs 目录，以及系统缓存、更新下载与安装资源目录。开发态不扫描源码、node_modules 或构建产物。
- Web 宿主的导出目录。
- 上述目录中新出现或未识别的文件/目录自动接入，只读展示，不因名称带 cache 就允许删除。

不扫描 QQ 原始聊天数据库、用户任意选择的外部导出目录或整个系统临时目录。它们不属于应用可自动接管的数据根。

数字是文件逻辑字节数，不是卷实际分配空间；符号链接只计链接本身，不遍历目标。显式配置的数据根先解析真实路径，目录别名去重，嵌套根按最具体归属统计，避免重复。扫描有访问上限，权限错误或达到上限时明确标记统计不完整，不提供该项清理。

## 清理边界

可清理白名单为 avatar、media、marketface、marketpack、voice、linkpreview、sysemoji，包含旧默认目录对应内容。voice 为语音解码文件，不是持久识别结果。

OCR、漫游消息、克隆体、导出、API 用量、装扮、修复数据等保留；搜索索引和运行中的模型/浏览器数据也不直接删除。保留数据没有复选框，不参与多选、预计释放量或清理请求。

`bootstrap.listStorageUsage` 返回路径、占用、是否可清理、原因与统计完整性。旧 `listClearableCache` 继续只返回可清理子集。`clearWeqCache` 在后端重新计算白名单，忽略未知或只读 ID；显式空数组不删除任何内容，省略 ID 才代表全部可清理项。前端始终发送明确的目标 ID。

删除使用异步文件系统 API；仅删除并重建成功的目录进入成功列表，失败项单独返回，不将失败删除前的估计值报成已释放空间。界面的预计值和清理结果均为近似逻辑字节数，并发写入可能造成差异。
