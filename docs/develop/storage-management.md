# WeQ 存储管理

设置 → 存储与媒体 → WeQ 存储管理，统一显示应用自身的数据占用。

## 统计范围

- 平台 WeQ 数据根：配置、模型、日志、托管 QQ、诊断、合并转发归档等。
- 当前缓存根与默认缓存根：即使改过缓存目录，仍统计默认目录里遗留或继续写入的数据。
- Electron 提供的 userData、sessionData、logs 目录，以及系统缓存、更新下载与安装资源目录。开发态不扫描源码、node_modules 或构建产物。
- Web 宿主的导出目录。
- 上述目录中新出现或未识别的文件/目录自动接入，只读展示，不因名称带 cache 就允许删除。

不额外扫描其它 QQ 数据目录、用户任意选择的外部导出目录或整个系统临时目录。应用数据根中的托管 QQ 目录会计入，但可能包含该托管实例自己的聊天库，不能当成普通缓存。

数字是文件逻辑字节数，不是卷实际分配空间；符号链接只计链接本身，不遍历目标。显式配置的数据根先解析真实路径，目录别名去重，嵌套根按最具体归属统计，避免重复。扫描有访问上限，权限错误或达到上限时明确标记统计不完整，不提供该项清理。

## 清理边界

普通缓存包括 avatar、media、marketface、marketpack、voice、linkpreview、sysemoji、collection、qqshow、dress_shared，包含旧默认目录。voice 为语音解码文件，不是持久识别结果。共享装扮资源清除会提示当前字体、气泡与挂件可能暂时不可用，需重新进入账号按需下载，不删除账号装扮设置。

`dress` 是混合目录：下载器生成的顶层 `<sha1(URL)>.(png|jpg|gif|webp)` 图片单列为预览缓存；目录、链接、未知文件和自定义背景不混入普通缓存清理。其余装扮数据可单独选择风险清除，两项统计不重复。

其余已识别的业务数据，包括 OCR、漫游消息与任务、收藏历史、克隆体、助手、导出、闪传、API 用量、意图分析、搜索索引、容错数据、修复工作区、模型、配置、日志、诊断及托管 QQ，可明确选择后清除。每项带有具体损失说明，例如识别原图过期无法重建、云端漫游过期、失去修复回滚能力、密钥与登录状态丢失。宿主显式声明拥有的浏览器会话、桌面运行和更新下载数据也支持退出后清除。安装资源由系统卸载管理；未知业务目录、符号链接、嵌套受保护根及不完整统计仍不开放。

风险项不参与未勾选时的默认缓存清理。用户明确选择后，按钮变为「退出并清除所选」，确认框逐项展示风险。桌面宿主在独立助手就绪后正常退出，助手仅收到 will-quit 的明确提交、且确认宿主进程消失后才删除。未提交或宿主未退出不执行。修复／回滚、导出及模型下载在途时拒绝提交。执行期间阻止新实例打开账号和后台服务，结果写入 userData/storage-maintenance/last-result.json，下次在存储管理显示成功项数、失败原因与逻辑清除量。未自动重启应用；报告不冒充磁盘实际可用空间变化。

Web／远程宿主没有本机退出清除能力时只展示这些项目，要求在电脑桌面端操作。不扫描或额外清理其它 QQ 数据目录、用户任意外部导出目录。注意 `managed-qq` 内可能含托管实例的本地聊天库和媒体，并非单纯安装缓存；此项单独警告本地记录可能永久丢失，用户需先退出托管 QQ 并备份。不会为了测试功能实际删除用户数据。

`bootstrap.listStorageUsage` 额外返回 requiresExit、confirmation 和混合目录清理模式。旧 `listClearableCache` / `clearWeqCache` 始终只处理普通缓存，即使客户端传入风险项 ID 也不删除。退出清除使用 `clearStorageData`，只接受明确 ID 和 acknowledgeRisk=true，后端重新生成目标，拒绝任一无效、只读或不完整项，不接受客户端路径。

删除使用异步文件系统 API；仅删除并重建成功的目录进入成功列表，失败项单独返回，不将失败删除前的估计值报成已释放空间。界面的预计值和清理结果均为近似逻辑字节数，并发写入可能造成差异。
