# 群分类目录读取修复

本阶段是清单 Part 2.3 的前置正确性修复，**不是群标签应用已完成**。

## 数据与作用域

既有官方结构及真实回包表明：`0x967C_0` 请求只包含分类编号，响应条目可能只带 `name@2`，没有 `id@1` 与 `type@3`。
原实现使用通用 `toInt` 将未返回的两个字段补成 0，制造了不存在的数字身份与类型；现在用 `null` 保留未知，显式返回的 0 仍保留为 0。
同名条目不在协议层去重，不因名称相同就推断它们的服务器身份相同。

界面的创建／删除请求按分类和名称操作，没有目标群参数。对于同名返回记录，界面按操作名称显示一行及条数，底层仍保留全部记录。
这避免用不存在的身份编号或不稳定数组索引作为键，也避免出现多个指向同一名称的删除按钮。
目录项创建成功与当前群应用成功是不同状态，不能复用目录读回证明绑定生效；目录所有权及完整作用域尚未验证。

## 局部帧检查

既有 protobuf 解码器对声明长度超出实际字节的输入可能返回部分结果。本阶段只为该目录加入口检查，不改变共享解码器或其他协议的兼容性。

- 校验外层目录及目录项的实际帧边界、varint 长度和整数范围。
- 已知字段必须使用正确 wire 类型；重复单值字段视为歧义回应，不悄悄选最后一个。
- 名称必须存在、非空且为有效 UTF-8；不使用替换字符制造另一个操作名称。
- 未知合法字段仍可跳过；名称等任意 bytes 不递归当作 protobuf。
- 合法空回应仍返回无目录项，不由此推断当前群没有应用标签或目录完整性。

## 验证与剩余需求

先新增 15 项离线黄金样本回归，旧实现 14 项失败后再修复。用手写 wire 字节覆盖缺省／显式零、同名记录、未知字段、截断、错 wire、溢出、重复字段及非法 UTF-8，不以被测编码器生成畸形输入。
UI 回归覆盖同名记录的计数展示及刷新后数量变化，没有修改布局或颜色。

最终协议 43、服务 7、桌面 UI／IPC 96，共 146 项定向回归通过；protocol／service 与桌面 node／web 类型检查通过。
没有读取真实 QQ 数据或执行分类目录／群标签写入，没有运行全量 CI、Native 或打包；同名条数复用原样式，本阶段未重跑浏览器主题矩阵。

群标签显式选择、绑定请求和生效读回仍未闭环。已确认 `0x89A_0` 可写标签名称集合且清空使用单个空字符串；但普通标签原值的读取格式／缺省语义、集合替换效果和实际权限仍需验证。
不使用分类目录、目录 id/type 或带来源／时间的标签记录替代这些验证，Part 2.3 保持未完成。
