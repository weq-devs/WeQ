# 会话列表重排与点击目标

## 行为边界

列表继续实时按活动时间、置顶状态排序，不因鼠标悬停、按压或操作而暂缓更新。
只在一次普通轻点内部保存 `pointerdown` 命中的会话 ID；仅当原会话的列表位置确实变化，且后续
`click` 落到其他行或列表公共祖先时，才将点击交给原会话的选择入口。目标行未改变时保留原有行级点击路径。
React 移动按下节点时，浏览器也可能不再派发 `click`；松开目标已改变时先完成原会话选择，
随后若仍收到 `click` 则只消费事件，不重复打开。
点击时原会话已不在结果中则不打开替代项；克隆会话仍使用克隆会话入口。

键盘和程序化点击不使用指针快照，修饰键与多选仍交给既有多选逻辑。滚动、超过轻点容差的移动、
`pointercancel`、窗口失焦、搜索或范围切换会清理快照；下一次按压也不会沿用上一次目标。

## 核验

2026-10-25（北京时间）使用本机 Chromium 系浏览器和两条合成行核对事件：
在 A 行按下、不移动指针、将 B 行移到同一位置再松开，原生 `click` 的目标可以是列表公共父元素，
不能假设它一定是行按钮。离线回归同时覆盖公共祖先和另一行两类点击落点，断言排序立即变化而选择仍为 A。
真实 `ConversationList` 的 React 重排还核对了移动按下节点后没有 `click` 的情形。

回归使用合成会话，不访问真实 QQ 数据库，不联网；覆盖触摸取消、滚动、拖动、会话移除、
连续点击、键盘与修饰键多选。不将这些检查表述为真实 QQ 会话的端到端验收。

最终 9 个相关测试文件共 56 项通过，3 个改动源码／测试文件的 Biome 检查和新 hook 的独立严格类型检查通过。
使用真实 `ConversationList` 的无头浏览器验证中，排序立即变为 B、A，原次点击仍选择 A，下一次点击正常选择 B；
键盘 Enter 与手机触摸重排也通过。本轮浏览器使用独立临时上下文并已关闭，没有操作用户浏览器或真实 QQ 会话。
