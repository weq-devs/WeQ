# 公司、个人说明与邮箱读取

资料扩展中的「详细资料」通过 `account.profileExtras.details` 按需查询，自己的 QQ 资料、联系人、群成员和个性主页共用已有入口，不增加资料首屏请求。

## 内容字段

| 字段 | 线上 TLV key | 返回属性 |
| --- | --- | --- |
| 公司 | 24008 / 0x5dc8 | company |
| 个人说明 | 20019 / 0x4e33 | personalDescription |
| 邮箱 | 20011 / 0x4e2b | email |

这三项是用户资料，不是好友扩展备注中的公司／描述。个人说明不复用签名字段 102，也不复用旧的签名参数 `personalNote`；展示范围设置中的字段号同样不是内容字段号。

## 传输与结果

使用 Android 详细资料的 `OidbSvc.0x480_9_IMCore`，OIDB command=0x480、serviceType=9。业务请求按大端写入目标 uint32 UIN、保留字节 0、uint16 字段数及三个 uint16 字段号；不将超出 uint32 的目标截断。

外层启用严格 protobuf 解码。业务体复用已有 `parseLegacyProfileBody`，核对返回 UIN、字段数、长度、重复 key 与尾部，再按字段解码 UTF-8。不接受错误目标、业务拒绝、截断或重复字段作为空资料。Android 对回包 UIN 后的保留字节只读取跳过，本实现不猜测其业务枚举。

返回 `targetUin`、三个 `string | null` 属性及字段级 `errors`。`null` 表示没有返回，空字符串表示明确空值；不能由缺失推断未填写、隐藏或不存在。单项 UTF-8 无效只标记该项错误，其他字段仍返回。邮箱按原始文本保留，不强制改写为标准邮箱；正文通过 React 文本节点展示，不执行 HTML。

服务及只读路由复用账号／数据源／QQ 进程的前后核对，同目标在途请求合并。界面五分钟缓存按账号、数据源和目标隔离，关闭详情后不再订阅；刷新失败保留已读内容，不覆盖 QQ 本地数据库或原有昵称、备注、签名缓存。切换账号、数据源或目标关闭旧详情。本次不新增任何写操作，已有本人邮箱编辑入口保持不变。

## 验证

2026-11-11 当前 Mac QQ 会话上，生产读取成功查询当前账号与另一已保存的自有账号，返回身份均由业务体核对。当前账号公司非空，个人说明／邮箱为空；另一目标三项均为空。含一次已有资料卡获赞正对照，共三条只读请求，写入 0；未将实际公司、邮箱或说明正文纳入源码、日志和测试夹具。

定向回归覆盖三项字段、换行文本、未返回与空值、单项非法编码、错目标、重复／截断 TLV、错误 OIDB、uint32 上界，以及在途合并、失败重试、切号迟到响应、前端懒加载和纯文本渲染。浏览器夹具为 `apps/desktop/test/browser/profile-extras.html`，复用 `run-profile-extras.mjs` 检查深浅色、主题色与桌面／手机宽度。
