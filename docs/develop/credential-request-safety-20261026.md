# 在线取票并发与安全验证处理

针对设备风险反馈的保守修复。日志不足以证明腾讯的具体检测规则，本记录不宣称已复现或消除 QQ 风控。

## 不改变的行为

- 不删除空间、收藏、邮箱、频道、会员、媒体下载或消息功能，不重置已有偏好。
- 不修改 QQ、不改写设备 GUID、不增加签名或注入能力，不用随机抖动规避检测。
- 保留正常的自动刷新、过期重认证、网络故障恢复和用户手动重连。
- 邮箱与会员继续使用宿主当前的 `allowOnline` / `fullModeAllowed` 门控；不以旧的自动偏好替代运行态。门控由当前完整功能实现提供，本次不另造授权状态。

## 只合并在途读取

`createNativeSingleFlight` 按原生实例分组，只在读取尚未结束时共享 promise，成功和失败均释放条目。不缓存完成结果，不猜测或延长凭据 TTL。

- Web 凭据：键为 PID、账号、域；`WebCredentialProvider` 与窗口 `fetchWebTokens` 共享在途读取。因此首页装扮和会员等不同业务重叠取同域票据时只发一次 native 请求。
- clientKey：键为 PID、账号。
- rkey：键为 PID、账号、显式媒体类型。`fetchDownloadRkeys` 新增可选第四参数 `uin`；账号 monitor 传入归属，兼容调用未传账号时不合并，避免按 PID 猜测账号。
- 不合并不同账号、进程、域、原生实例或媒体类型，不重发写请求。

## 失效与来源变化

Web provider 换 PID 时清掉旧进程的 live 缓存，保留原有显式 seed 的离线兜底语义。`invalidate` 和 seed 更新推进域内代数；未完成读取即使稍后返回也不能覆盖新状态。失效同时撤销该共享在途条目，新请求不必接着等待已失效的旧票据。

原生读取本身不可取消时，不擅自终止原生任务；消费者检查 PID、运行态和代数，丢弃迟到结果。

## 邮箱安全验证

当前 native 对认证失败通常只提供 `errorKind=auth`，不能把所有 auth 错误都当作风控。只识别已有 native 明确返回的「邮箱需要二次验证」及「邮箱拒绝了当前登录环境」提示，以及结构化的 `verification-required` 标记。

这些提示在 `MailAuth` 边界转为 `MailFailure.businessCode=MAIL_VERIFICATION_REQUIRED`。邮箱 service 收到后停止后台恢复计时器和 socket 重连，保留未读与通知偏好及原错误。凭据就绪事件不会自动解除这一状态；用户通过已有连接入口手动重试，成功后按原偏好恢复未读与提醒。

普通网络错误、离线与会话过期仍走原恢复路径。该规则不覆盖未知的腾讯安全码，不把一般的 `WebAuthError`、缺 skey/Cookie 或 socket 断线猜成安全封禁。

## 验证范围

纯离线 Vitest：并发与失败清理、账号/PID/域隔离、PID 变化、取票中失效和 seed 更新、明确验证拒绝后停试与手动恢复、普通错误自动恢复；并回归已有凭据、邮箱、会员及 monitor 测试。未连接真实 QQ 或用户账号，不据此承诺线上风控结果。

本轮 service 12 个文件共 169 项、desktop 4 个文件共 27 项测试通过；service TypeScript 检查、本轮 10 个 TS 文件的 Biome 检查通过。桌面回归覆盖邮箱路由/通知、凭据就绪订阅及完整功能运行态，不是完整打包或真实 Windows QQ 验收。

这些是 service 主进程改动，开发模式需要重启 WeQ 主进程；未自动重启或安装应用，不需要为加载 TS 修改重启 QQ。
