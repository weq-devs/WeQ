# 好友免打扰云端读取（2026-10-22）

## 契约依据

- 官方 Mac QQ `DeCodeBuddyListRespones`／`DeCodeFriendList` 的静态证据确认：`0xFD4_1` 好友项在根 tag 101，UID／UIN 为子 tag 1／3，SNS 在子 tag 10002，属性 key／bytes value 为 tag 1／2。
- `relation_flags_codec` 将 13579 映射为免打扰；已验证的开启格式为八字节，后四字节全 FF。关闭后的同一好友在完整查询中不再返回此属性。异常长度／尾部不扩展解释为定时免打扰。
- 既有独立协议研究完成指定测试好友的关闭→开启→恢复及独立读取；研究报告及脱敏回执位于本机所属 Agents 项目，真实身份和票据不进入仓库。
- 本次产品请求的首次页和带二进制游标页，分别为 77／82 字节，与既有已实发研究构造逐字节相同；未猜测新请求参数，也没有新增业务写入或真实登录。

## 产品路径

`GetFriendSnsPage` 只解析每页，保留免打扰属性的存在性，不在单页解析器内将缺失属性转换为关闭。
`AccountWriteService.getFriendDisturb` 每次从无游标开始完整查询，遍历到空游标再返回目标状态。
请求始终明确包含 SNS 13579；不复用增量、未声明字段过滤或其他读取结果。

只有目标 UID 与本机好友关系匹配、UIN 一致且查询完整结束，才将缺省属性解释为关闭。
这一处理依据既有完整查询的真实往返；多页遍历目前通过合成反例验证，尚未在产品环境执行真实多页回归。
不将这条缺省规则外推到增量数据、目标缺失、仅局部页或其他 SNS 属性。

账号回显存在时必须匹配。每页返回后和下次请求前重新检查运行时绑定；拒绝跨页重复 UID、重复属性、循环游标与超过 100 页的结果。
这些错误不返回部分状态，也不写 QQ 原库或持久缓存。

新增独立 `qqWrite.friendDisturbState` 在线查询，首尾复核账号和数据源绑定、响应目标。
原 `peerState` 保持本机缓存语义，供其余会话设置使用；UI 免打扰不再使用该缓存值兜底。

开关沿用原布局。在线读取在途、未取得数据或读取失败时禁用，失败提供重试。
已取得非规范值时保留未知，允许用户显式选择；保存后复用现有最多四次只读核对，不重发写请求。
结果只有云端值与请求相符才确认，不以未确认写回执冒充生效，也不宣称跨设备通知效果已经验证。
完整名册查询不因每次窗口聚焦反复执行，无后台轮询。
