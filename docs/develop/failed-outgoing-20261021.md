# 失败发送占位移除（2026-10-21）

## 范围与状态

普通消息、Ark 和合并转发的失败占位只在当前 MainView 的内存中；没有失败消息数据库。
成功消息缓存仍由 MessageSendService 在成功且有有效序号时写入，拒绝或无有效序号的回执
不进入该缓存。本次不建立新的落盘删除表，也不删除素材草稿、附件或真实消息。

- 右键「移除失败消息」和多选删除允许清理明确失败的本机占位，不调用原库删除接口。
- 发送中、已受理待同步、漫游／成功缓存及已有序号、random、发布文件身份等确认信号的
  条目不走失败移除。功能更新器再次核对当前状态与会话，防止菜单打开后状态已改变的竞态。
- 同一批清理三类占位，附带会话摘要与当前消息窗口读取按微任务合并；读取失败不回滚
  已完成的清理，也不重发消息。MainView 卸载后取消排队读取。
- 外层发送异常仅能为尚未创建占位、也未受理的准备阶段补一条失败记录；已移除或已经对账
  的条目不能被迟到异常重新插入。切回会话和刷新视图继续使用清理后的状态。
- 若之后真正收到该内容的已发送记录，仍正常展示真实消息，不按旧失败占位的身份隐藏它。

## 定位与序号

原来所有无序号占位都追加到时间线末尾，因此失败条目会一直挡在后到消息之后。
现在最新窗口会记住发起前的已知序号水位，同一秒内的新消息也能排在失败占位之后。
历史窗口、其他会话或存在未定位发送时回退到创建时间，不猜序号；私聊未核对的协议序号
不作为本地水位。该水位不是本条消息的序号或发送成功证明。

真实消息的顺序和已确认序号处理保持原逻辑。失败占位不占序号，缺口检测会跳过它，
不会因把失败条目放回中间而遮住真实消息之间的缺口。未知时间的条目保留显示，不伪造位置。

## 验证

桌面 85 项定向回归通过，覆盖单条／多选入口、成功保护、当前状态复核、三类占位、
视图重开、卸载取消、读取失败、迟到补写、同秒排序及缺口保留。另运行服务层 2 项既有
拒绝／无序号不缓存回归，均通过。桌面主进程／渲染层类型、9 个 TS／TSX 的 Biome 与
diff 检查通过，未运行全量 CI。

4 组真实浏览器合成数据交互检查覆盖 390／1200 宽度、深浅主题与主题色：菜单在视口内，
移除后只剩真实消息，草稿保留，摘要读取一次，无业务写请求。实际 QQ、刷新与应用重启
补测记录在本机测试清单，不将合成数据检查冒称真实发送验收。
