## 1. 已确认的目标与边界

- 以用户给出的九个一级分类为目标，采用下方最终目录与顺序。
- 两层导航：左侧一级分类，右侧顶部二级分类；第三层及以下是正文分区、设置项或工具入口，不继续增加导航层。
- 工具从设置打开时，不关闭、不替换、不卸载设置页面，不顶掉侧栏；关闭后恢复原页面现场。
- 日志设置和日志查看器继续在日志页面内，不弹窗、不增加查看器入口页。
- 数据库修复保留现有独立窗口；重复打开聚焦已有窗口，不静默换账号。
- 复杂工具使用遮罩弹窗；窄屏可铺满可视区域，但不转换成会丢失设置现场的主页面导航。
- 后台服务不加入新设置目录。本轮不停止、卸载或删除守护进程，不改开机启动、Release 监控等依赖它的能力。
- 重组、改名不能遗漏原有参数、名单、模式、状态、错误重试、风险确认和平台限制。
- 不新增依赖，不重新实现 QQ 协议、数据库读写、导出引擎或删除引擎。
- 当前工作区已有其他改动；实施时保留现场，默认留在当前分支，仅提交本任务完成且已验证的改动，不推送。

本方案中标出的“状态”“条件”“入口”等是实现标注，不作为界面文案。原清单中的“原两项合并”等编辑备注也不显示在产品中。

## 3. 页面与弹窗契约

### 3.1 呈现规则

| 内容 | 呈现方式 | 关闭后的目标 |
| --- | --- | --- |
| 普通设置、名单、用量、FAQ、反馈、日志查看器 | 右侧正文 | 不适用 |
| provider、TTS、克隆体配置、验证器绑定 | 保留并适配现有模态表单 | 原设置控件 |
| 密钥扫描、其他设备密钥、QQ 账号管理、抓包、逆向 | 设置之上的工具弹窗 | 原入口及原滚动位置 |
| 防撤回记录目录及某会话记录、容错记录 | 设置之上的工具弹窗；同一弹窗内返回上下级 | 原设置入口 |
| 数据库管理、资源查看、QQ 占用分析与清理 | 大尺寸工具弹窗 | 原设置入口 |
| 数据库导出 | 复用公共导出表单/请求通道 | 来源工具或设置入口 |

公共工具从其他位置打开时，保留其他位置原有呈现方式。新规则只改变设置来源的工具，不把全局撤回查看器、资源页或任务工作区一律改成模态。

### 3.2 设置现场保留

1. 打开工具不得调用 `setSettingsOpen(false)`，不得使用替换设置主内容的 `WorkspacePage` 呈现。
2. 工具关闭只清理工具状态，不再通过“设定返回分类 + 重开设置”模拟恢复。
3. 设置组件及当前正文保持挂载；工具打开前后的一级分类、二级分类、正文滚动、导航滚动、展开状态、未保存输入、搜索高亮不丢失。
4. 设置后续需要切换二级页时，至少保留每页滚动及未保存草稿；优先复用已有页面保留/草稿机制。不要同时激活全部 35 页的查询与订阅。
5. 工具状态记录来源和完整账号/数据源身份，不能只用 QQ 号作为身份。异步扫描、选择与迟到结果不得串入其他来源。
6. 更换账号/数据源、退出账号、锁屏时按现有生命周期失活或关闭敏感工具，不能把旧来源结果留给新账号。独立修复窗遵循自身现有规则。

### 3.3 模态、键盘与资源生命周期

- 复用 `OverlayLayer` 的模态路径和 `overlayStack`，不写固定 z-index，不用透明遮罩或 `presentation="page"` 冒充模态。
- 补齐/验证工具内焦点约束与背景不可交互；若现有容器未完整实现，只补所需公共能力并覆盖原有使用者的回归，不宣称现成组件已全部满足。
- Escape 和点外关闭只交给最上层；有未保存内容时复用现有确认，危险执行中不能因点遮罩直接中断或丢失结果。
- 关闭后焦点返回入口；入口已不存在时回到当前设置页合理位置。
- 工具内部的目录/详情、清理选择/确认/结果尽量使用同一弹窗内的步骤，不重复叠工具壳。系统文件选择、高风险确认、认证和公共导出允许必要的子模态。
- 公共导出打开时暂停下层工具交互，取消后恢复；提交导出继续由已有任务系统管理，关闭表单不等同取消任务。
- 隐藏或关闭工具后停止其无必要的轮询、Observer、键盘和尺寸监听；已经提交的后台任务按原任务生命周期执行。
- 扫描按需启动，同一来源避免分析与清理各扫描一次；关闭后取消尚未开始的扫描，已在途结果用请求身份隔离，不伪称底层 I/O 已被取消。
- 日志查看器只在日志页活动时订阅/跟随，切走停止活动监听，回来保留文件、筛选及滚动偏好。

## 4. 需要明确实现的行为变化

### 4.1 合并已读同步

已核对现状：自动阅读使用 `reportReadEnabled`，手动标记使用 `manualReadReportEnabled`；两个字段均为全局配置，默认关闭。它们不能仅用文案改名合并。

本次采用“一行总开关 + 旧混合状态摘要”，不自动改写用户已有选择：

| 原自动 / 手动 | 新开关展示 | 未操作时的行为 |
| --- | --- | --- |
| 关 / 关 | 关闭 | 仍均不上报 |
| 开 / 开 | 开启 | 仍均上报 |
| 开 / 关 | 开启，摘要“仅自动阅读同步，沿用原设置” | 保持原组合 |
| 关 / 开 | 开启，摘要“仅手动标记同步，沿用原设置” | 保持原组合 |

- 开关的开启态表示至少一类同步已启用；部分同步时必须显示摘要，不能暗示两类均已启用。
- 用户关闭总开关，一次原子配置提交将两个字段均设为 `false`；明确重新开启时，先确认会同步自动阅读和手动标记，随后一次提交均设为 `true`。
- 不增加第三个持久总开关，不产生三个字段互相覆盖的问题。新增统一设置入口，底层保留两个旧字段供已有配置/备份兼容。
- 不用连续调用两个旧 mutation 模拟原子提交；失败保持旧值，重新读取后显示实际状态。
- 旧 API、旧备份再次写入混合值时仍按上述规则展示；读取页面、升级、导入预览都不能自动补成“开 / 开”。
- 默认仍关闭。受限/离线时不能因开关显示开启就发送；“标为未读”仍只在本地生效，不能声称可恢复其他端已清除提醒。

### 4.2 输入状态与防撤回

- 输入状态只迁位置和改标题，保留全局默认、账号/数据源隔离的会话特例、删除特例后回到默认的语义；不改变当前默认值。
- 防撤回不再作为二级分类，也不保留“保护/通知/记录”三页签。
- 聊天消息页中使用一个防撤回分区，直接显示总开关、保护模式、触发器状态、撤回通知总开关，以及保护/通知会话选择摘要和编辑入口。
- 大型会话选择器在工具弹窗编辑，保留搜索、多选、保存选择与未保存确认；避免将两份长会话列表直接铺满聊天消息页。
- “查看撤回记录”打开会话目录，点击会话在同一工具弹窗查看记录并可返回目录；复用现有消息投影、气泡及筛选，不重新实现记录读取。
- 保留静态 PC 快照不可拦截、QQ 正在运行时可能需重启等真实状态提示；UI 重组不改触发器或通知传输机制。

### 4.3 监听、受限提醒与完整功能

- “自动启用完整功能”只控制自动进入策略，不再直接等同于原 `autoAttachQq` 完整功能总开关。保留原全局偏好作用域与默认值，另设宿主内存中的本次运行启用状态；文案仍需说明会读取凭据及启用在线能力。

| 自动启用偏好 | 本来源在本次运行内已手动启用 | 行为 |
| --- | --- | --- |
| 关闭 | 否 | 保持受限模式，不主动尝试完整功能；状态详情仍提供“进入完整模式” |
| 关闭 | 是 | 允许本次运行使用完整功能，自动启用偏好仍关闭 |
| 开启 | 任意 | 满足条件时自动尝试进入完整模式；实际就绪前仍显示受限、待提权或进入中 |

- 手动“进入完整模式”只提交本次运行的请求，不能调用持久自动开关将其重新打开。成功后显示完整模式，关闭并重新启动 WeQ 后仍按关闭的自动偏好进入受限模式。
- 自动偏好和手动请求只表示允许尝试，不是“已经完整”的证据；继续依据 QQ 在线、当前会话、凭据、授权和原生连接等实际能力判断结果。失败/取消保留真实原因和重试入口，不误报成功，不改自动偏好。
- 自动偏好关闭且没有本来源手动请求时，不因已有缓存凭据、前台恢复、定时轮询或重新登录 QQ 而偷偷启用在线能力。“重新检查”只检查状态，不暗中升级为手动进入。
- 关闭自动偏好停止由自动策略发起的后续进入/重试；若本来源已经手动启用，则保留该次运行的选择，不把关闭自动策略误当成撤销手动请求。
- 手动启用状态由实际运行 QQ 能力的宿主统一持有，绑定完整账号/数据源身份，不持久化、不写备份、不由 renderer 的状态副本决定。切换来源不能继承另一来源的手动请求；显式退出该账号或宿主进程结束后清除。
- 同一宿主的窗口或 Web 客户端读取相同有效状态；刷新页面、重开设置或 renderer 重载不等于宿主重启，也不能把手动请求变成永久偏好。重新进入仍遵守真实平台授权，不能把内存标记当成系统权限。
- 原 `autoAttachQq` 的直接读取点必须逐项改为正确语义：启动策略读取持久自动偏好，凭据采集/在线请求/已读上报等能力门控读取宿主提供的有效启用状态；不能只改设置页和受限提示，导致手动进入后后端仍被旧开关拦住。
- 旧配置/备份中的 `autoAttachQq` 仅迁移为自动启用偏好，值和默认值不变；恢复预览不得创建手动请求。旧“启用完整功能”动作分流到本次运行请求，旧自动设置调用则按自动偏好处理，不混用同一 mutation。
- “进入受限模式时横幅提醒”为新增偏好，默认开启以保留现状；关闭只抑制进入受限状态的被动横幅。
- 标题栏状态、详情入口、真实管理员授权请求、主动操作错误、进入完整模式的任务进度不受此开关隐藏。
- 恢复完整模式的成功回执沿用现有行为；关闭被动提醒期间仍更新去重基线，不能恢复开关后把全部旧事件补发。
- 复用 `RestrictedMode`、状态 store 和现有能力判断，只接入新的有效启用状态，不另建一套互相冲突的受限判定器。异步就绪/失败回调核对来源与本次请求身份，关闭策略、取消或换来源后的迟到结果不能错误恢复完整模式。

### 4.4 隐私模式与菜单截图

- 将隐私模式从应用锁拆成独立二级分类；介绍明确其是视觉遮罩，不加密、不改原数据和普通导出内容。
- 新增“在菜单中截图瞬间临时启用隐私模式”，默认关闭以保持旧截图行为；存入设备级界面偏好，纳入现有设备偏好的备份/恢复范围。
- 开启后，菜单截图流程为：关闭菜单、临时隐私覆盖生效、等待 DOM/CSS 完成绘制、调用现有窗口截图 IPC、在 `finally` 中撤销临时覆盖。
- 临时覆盖不写永久隐私偏好，不通过持久 `set(true)`/`set(false)` 来回修改 localStorage。
- 原本隐私模式已开启时，截图后仍开启；用户在截图期间修改持久偏好时，以最新偏好为准，不用旧快照覆盖。
- 防重复触发或使用带所有权的临时覆盖，保证并发截图、取消、异常、窗口销毁不提前解除其他请求的遮罩。
- Web 无原生窗口截图能力时不提供可执行控件；不扩展为屏幕录制、系统截图或所有内容导出的全局拦截。

### 4.5 邮箱与凭据

- 邮箱红点文案调整不得顺带删掉原未读数量或改变已有计数语义；横幅提醒保留账号作用域、去重和实际通知生命周期。
- 数据库密钥扫描继续复用已有在线会话和其他设备扫描工具，不增加直接内存访问或 SQL 路径。
- 敏感值默认掩码，显示/隐藏/复制/重试、过期时间和未获取原因完整保留；离开页面、切账号、锁屏后重新掩码。
- 搜索目录只含公开名称/别名，不收集凭据值、配置值、账号实际资料；错误、日志、反馈、截图夹具不写入真实秘密。

### 4.6 自启时显示窗口（新增需求）

- 位于开机自动启动开关下方，默认关闭；自启关闭时保留偏好但禁用其控件。
- `showWindowOnAutostart` 存入通用设置，缺字段的旧配置默认关闭，随通用设置备份恢复；不代替系统登录项注册状态。
- Windows/Linux 自启项带 `--weq-autostart`；macOS 使用实际 `wasOpenedAtLogin` 状态，不用“已注册自启”推测本次启动来源。
- 隐藏自启从创建窗口开始即不显示，ready-to-show、加载结束和延迟兜底均不重新弹出；托盘创建失败时显示窗口，避免无法找回。
- 手动打开、托盘/Dock 唤出及普通重启仍显示；手动重启不继承自启标记，Linux 自动切换窗口后端的重启保留原启动身份。
- 既有无标记的 Windows/Linux 登录项升级标记，不重新启用任务管理器或 XDG 禁用的项。标记升级前已发生的无参数 Windows 启动不靠猜测归类为自启。
- 依据：[Electron 登录启动状态](https://www.electronjs.org/docs/latest/api/app#appgetloginitemsettingsoptions-macos-windows)、[窗口创建与显示](https://www.electronjs.org/docs/latest/api/browser-window#showing-the-window-gracefully)。操作系统登录的实际启动仍须单独实机验证，不以单测代替。

## 5. QQ 占用分析与清理融合

### 5.1 一套工具，一次连续流程

工具标题为“QQ 存储管理”。内部保持“占用概览、分类明细、清理选择、确认、执行结果”的连续流程，概览与明细是同一工具的视图，清理不再打开第二个完整工具窗口。

- 概览保留总逻辑占用、文件数、有内容分类、覆盖月份、大小/数量切换。
- 保留分类分布、原文件/缩略图/其他占比、文件修改月份分布、分类明细、扫描进度、重新扫描和错误重试。
- 清理选择保留全部五个现有预设及自定义：完全安全清理、清理原图、清理缩略、清理 File 目录、全部清理。
- 自定义保留逐目标选择、原图/缩略/全部变体、预计逻辑清理量、风险标记。
- 确认页保留目标、路径/范围摘要、变体、损失说明及最高风险操作的确认短语；执行后逐项目显示成功/失败及逻辑删除量，并刷新统计。
- 分析可显示但后端不支持清理的类别只读；不能为了统一外观扩展删除白名单。
- “资源查看”复用 `CacheView` 的全部现有资源分类、浏览、搜索、筛选、下载等能力，仅修改设置来源的容器及标题，不删除内部页签。

### 5.2 能力并集与分类映射

实施前以运行代码再次核对以下清单，不能仅凭两个组件的标题判断覆盖完整：

| 现有来源 | 必须保留的分类/目标 |
| --- | --- |
| 分析 `TREES` | 图片、视频、语音、表情、头像、图片墙、QQ 空间、文件 |
| 清理 `TARGETS` | `avatar`、`marketface`、`photoWall`、`qzone`、`emojiRelated`、`pic`、`video`、`emojiRecv`、`personalEmoji`、`ptt`、`file` |
| 清理变体 | `all`、`ori`、`thumb`，仅向支持变体的目标提供后两者 |
| 只读边界 | 用户主动下载保存的文件、系统表情资源以及现有后端未开放清理的内容 |

分析的聚合 `emoji` 与清理的多个表情目标不是一对一；建立显式映射并核实真实目录关系。不得同时累加聚合父项和子项造成总数重复；关系不明时分别保留原口径并说明范围，不猜目录包含关系。

优先复用现有服务结果，以明确映射组合 UI；若确需扩展聚合接口，只扩展统计视图，不让前端传任意路径删除。清理仍走原白名单、真实路径边界及服务端校验。

### 5.3 与 WeQ 存储管理隔离

- 常规下的 WeQ 存储管理继续调用 `bootstrap.listStorageUsage` 等现有接口，QQ 工具继续调用账号资源分析/清理接口。
- 两者可复用展示控件，但不合并清理指令、范围或确认；任何“清理缓存”都必须能看出正在清理 WeQ 还是当前 QQ 数据源。
- WeQ 风险数据、退出后清除、受保护/未知/不完整统计条目和回执全部保留。
- 统计只声明逻辑文件量，不把预计值当实际磁盘释放量；存在并发写入、失败和统计不完整时如实显示。
- 静态账号当前不可用的 QQ 资源工具不因换入口而变为可用；外部媒体关联不自动授权删除外部原件。

## 6. 数据库导出复用

- 设置中的旧“导出明文数据库”入口归入数据库管理；工具内导出动作走公共导出组件和已有请求/任务链路。
- 复用 `ExportTool`、`DatabasePlainExport`、保存策略和任务结果，不新增第二套格式选择、另存、重试或下载流程。
- 从数据库管理发起时带入准确的数据源和所选数据库；默认选中当前数据库，但用户扩展选择时仍只能在同一来源范围内选择。
- 先核对公共导出的实际输入类型；现有 `ContentSelection` 若不能表达数据库目标，仅补充所需类型和校验，不能把路径字符串塞进其他内容类型。
- 不使用 `initialMode="database"` 代替完整来源约束，不把“全部数据库”和“当前数据库”混为同一请求。
- 取消后回到来源工具；提交后由公共任务系统继续管理。跨账号迟到结果、重开、重复提交和失败重试必须覆盖。
