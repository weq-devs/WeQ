# 我的好友备注资料

好友备注编辑弹窗内的「我的备注资料」用于读取和修改**当前账号为好友填写的公司、电话和描述**。
它不是好友公开资料，不参与会话名称、云端名片昵称或公开资料缓存的更新。

## 协议

Android QQ 9.3.75 的 `BusinessCardEditActivity` 同时调用普通备注名保存和
`BusinessCardServlet`；后者使用旧 OIDB `0x43c`。`CardInfo` 中公司为 tag 4 string，
电话为 tag 6 repeated string，描述为 tag 7 repeated string。

- 关联读取：`SummaryCard.ReqSummaryCard` 的 `RespSummaryCard` JCE tag 62，解析为 CardInfo。
- 完整详情：`OidbSvc.0x43c_5`，请求 card_id@1；响应 card_id@1、card_info@2。
- 修改：`OidbSvc.0x43c_3`，请求 card_info@1。
- 新增：`OidbSvc.0x43c_1`，请求 card_info@1，不设置本人名片 isMine；响应为 card_id@1。

不使用 `_4` 列表推断好友没有备注资料；历史线上样本已出现列表为空、详情仍存在的反例。
SummaryCard 要求返回成功且目标 UIN 一致，再接受 tag 62 显式为空；缺失 tag 62、错误码、错目标、截断或格式错误
都不能作为空名片的基线。SummaryCard 的响应兼容 UniPacket v2/v3，保留 uint64 精度。

## 保存

打开弹窗不自动查询扩展资料，展开「我的备注资料」后才读取。已有卡再按真实 ID 读取完整详情，
核对两层 ID 与 bind_uin；不把 ID、原始名片传给前端。前端仅持有三项备注及内容修订摘要。

保存前重新读取并比对修订摘要，过期草稿需刷新。修改只替换 tag 4、6、7，其他字段逐字保留，
包括姓名、图片、附加 QQ、OCR、未知字段和显式默认值。公司清空显式编码空字符串，电话及描述
清空移除相应 repeated 项。不能将 `_3` 当作任意单字段 patch：历史线上实测省略公司会清空公司。

仅成功读取为空名片时允许新增，新增前还需明确读到普通备注名。同一好友的并行保存只放行一个；
写入超时不自动重发。界面通过独立读取核对最终三项值，不把空 ACK 当作保存完成。

## 验证状态

静态来源是 Android QQ 9.3.75 的编辑页、Servlet 与协议生成类。历史研究已完成 `_1/_3/_5`
的公司、描述读写与删除实测；电话未做真实写入。此前当前 Mac 登录态的 SummaryCard 请求返回
过 151，本实现保留该失败并停止编辑，不声称该登录态已读通。

本次集成使用合成数据检查协议、服务、IPC 与界面，不修改真实好友资料。JCE 请求及两种响应封装
的黄金字节由独立编码器生成；测试覆盖错误响应、保全未知字段、旧快照、清空、切号与超时。
