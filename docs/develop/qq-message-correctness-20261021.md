# 消息正确性与邮件导出修补（2026-10-21）

本轮只做相关路径的离线回归与隔离组件验证，不将其等同于真实 QQ 接收端验收。

## 合成与转发

- 合成消息时间共用北京时间控件，修改 MfNode／嵌套节点已有 time 字段；预览、持久化和发送继续同源，不写原库。
- 逐条转发原间隔取相邻消息非负时间差；不重排、无效时间按零处理，单条无等待。预估与发送共用算法。
- 撤回图文重新编辑复用原图片重发代理，先准备完整资源再确认当前草稿未变；缺图不降级成纯文字。
- 频道私聊复用共享多选、框选、复制菜单和公共导出请求，不展示无实现的写操作。

## 未读与顺序

- dataline 的 8／134 类型不归一为普通私聊 1，监听独立设备表，按设备伪 UID 及 40013 来源接入本地未读。
- 设备未读不以序号差推断，避免电脑发送／回声扩大计数；查询与阅读绑定具体账号配置。
- 监听挂载即对齐基线，正文落后最近会话水位时只推进实际观察水位，后续文件变化仍可补到。
- 监听、缓存和时间线按会话序号、时间、真实 ID 排序，不通过 Number 比较 64 位标识；同序号不同消息仍保留。
- 刷新只接受最新请求，来源与窗口身份继续独立核验，旧响应不能覆盖较新结果。

## 邮件导出

读取、下载沿用 QQMailService，公共资源任务负责原子发布与保存策略。每封邮件包含基本信息 JSON、静态正文和附件，索引与缺失清单分别保存。导出不额外提交已读操作；正文不携带活动内容、外部图片或邮箱票据。会话展开及每步操作均有边界和来源检查。

## 图片资源保留复现

实际 ChatPane 组件连续八次发送 256 KiB 图片并模拟失败，再移除失败消息：旧实现仍持有 8 个 Blob URL，共 2,097,152 字节。原因是 failedSendImagesRef 只在组件卸载时释放，消息移除不会清理原 File 和 URL。

改为只保留当前消息草稿引用的 URL，不额外持有原 File；消息移除或离开后释放。再次编辑从已有字节重建独立预览，保留原草稿快照，不依赖已撤销 URL。新预览在取消、替换、成功发送、失败消息移除及卸载时分别释放。

相同组件回归释放至 0；隔离浏览器八轮测试每轮仅保留当前失败消息的 1 个 URL／262,144 字节，清理后均为 0；释放旧消息后，重新编辑图片仍解码成功且可再次生成发送。这里统计的是实际 Blob 资源，不把它冒称进程 RSS 或完整堆快照；未重做装扮帧缓存限制，也不宣称已排除全部潜在增长来源。
