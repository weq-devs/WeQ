# 消息正确性与邮件导出修补（2026-10-21）

本轮只做相关路径的离线回归与隔离组件验证，不将其等同于真实 QQ 接收端验收。

## 合成与转发

- 合成消息时间共用北京时间控件，修改 MfNode／嵌套节点已有 time 字段；预览、持久化和发送继续同源，不写原库。
- 逐条转发原间隔取相邻消息非负时间差；不重排、无效时间按零处理，单条无等待。预估与发送共用算法。
- 撤回图文重新编辑复用原图片重发代理，先准备完整资源再确认当前草稿未变；缺图不降级成纯文字。
- 频道私聊复用共享多选、框选、复制菜单和公共导出请求，不展示无实现的写操作。

## 未读与顺序

- dataline 的 8／134 类型不归一为普通私聊 1，监听独立设备表，按设备伪 UID 及 40013 来源接入本地未读。
- 设备未读不以序号差推断，避免电脑发送／回声扩大计数；查询与阅读绑定具体账号配置。
- 监听挂载即对齐基线，正文落后最近会话水位时只推进实际观察水位，后续文件变化仍可补到。
- 监听、缓存和时间线按会话序号、时间、真实 ID 排序，不通过 Number 比较 64 位标识；同序号不同消息仍保留。
- 刷新只接受最新请求，来源与窗口身份继续独立核验，旧响应不能覆盖较新结果。

## 邮件导出

读取、下载沿用 QQMailService，公共资源任务负责原子发布与保存策略。每封邮件包含基本信息 JSON、静态正文和附件，索引与缺失清单分别保存。导出不额外提交已读操作；正文不携带活动内容、外部图片或邮箱票据。会话展开及每步操作均有边界和来源检查。

## 图片资源保留复现

实际 ChatPane 组件连续八次发送 256 KiB 图片并模拟失败，再移除失败消息：旧实现仍持有 8 个 Blob URL，共 2,097,152 字节。原因是 failedSendImagesRef 只在组件卸载时释放，消息移除不会清理原 File 和 URL。

改为只保留当前消息草稿引用的 URL，不额外持有原 File；消息移除或离开后释放。再次编辑从已有字节重建独立预览，保留原草稿快照，不依赖已撤销 URL。新预览在取消、替换、成功发送、失败消息移除及卸载时分别释放。

相同组件回归释放至 0；隔离浏览器八轮测试每轮仅保留当前失败消息的 1 个 URL／262,144 字节，清理后均为 0；释放旧消息后，重新编辑图片仍解码成功且可再次生成发送。这里统计的是实际 Blob 资源，不把它冒称进程 RSS 或完整堆快照；未重做装扮帧缓存限制，也不宣称已排除全部潜在增长来源。

## 反馈修补

- CI 暴露统计夹具遗漏新增读取的 40013，补齐真实表列，不放宽 SQL、类型或测试断言。
- 最新会话页独立刷新，与已加载分页按精确序号去重，避免旧分页副本覆盖新消息；已保存草稿时间与消息／会话活动使用同一排序口径，置顶仍优先。查询绑定账号配置，迟到结果不跨来源。
- 合成器复用按钮及悬停宿主：独立工作窗使用对应 Document 和构造器，原生 disabled 保留，并明确说明不能操作的原因。
- 合并转发对账兼容 Ark／XML／multiMsg，按客户端 random、可信序号和有界时间内的 resId 匹配；真实卡片先到、回执后到也重新计算。渲染时即时隐藏已匹配占位，一条真实回声只消费一次，不吞掉同卡连续发送或别的会话的消息。

## 多选与加载

- 首次快速框选不依赖浏览器一定投递中间 `pointermove`：`pointerup` 用最终位移补判拖拽阈值，再计算选区并提交。回归覆盖未进入多选、共享选区首次提交与小幅点击不进入多选；原取消／切会话、正文选字与追加框选用例保留。
- 内容选区按 `(kind, container)` 分别保存，多选模式、Shift 锚点和已选消息快照都属于对应会话／页面。只在明确退出时清除此选区；搜索、日历窗口替换和普通导航不清除。账号配置变化整体清空，未选择的闲置 owner 元数据和取消加载的临时快照会释放。
- 时间线将缺口作为独立选择项；它不会冒充真实消息 ID 交给分析、导出或删除。未补全的缺口须先取消选择或继续拉取，不能悄悄只处理已加载部分。
- Shift 跨未显示窗口或缺口先确认读取本地范围，按现有索引和 seq 分页，补全同序号边界。已选记录保存在轻量快照中，不将整个大范围强塞进当前显示窗口；可见窗口内新增内容正常补入。
- 选中缺口另行确认漫游，复用已有 `fetchGapMessages`、缓存和私聊 NT 序号校验；失败、过期或未确认的记录不伪装成成功。加载横幅按去重后的实际消息条数更新，支持停止，切换会话／来源会中止旧请求，保留原选择。
- 没有可信序号的跨窗口范围不猜测边界；保留原选区并提示。所有新范围和漫游请求均绑定账号配置，异步读回后再次检查。

## 转发与群助手

- 合并／逐条转发共用目标选择器，群助手单独进入，已选 ID 集合在内外共用，不把聚合入口当成真实收件群。
- 文本长度和原消息间隔模式新增 `maxIntervalMs`，默认 `-1` 不限；设置非负上限时在抖动后封顶，估算和执行共用算法。固定模式不受此项影响，单条仍不等待。
- 逐条发送同时显示已进行／预计用时与消息条数，结合配置等待和已观察的发送耗时估算；尚无依据时显示待估，完成／停止清理计时器。消息加载横幅仍只按实际加载条数显示进度。
- 群助手日期明确按北京时间显示月日与时分，跨年增加年份；置顶读回状态优先于过期本地覆盖，列表与混排使用相同排序函数。
- 置顶表的 `41103` 只记录执行置顶的时间，不能当作置顶组内的排序键。列表两层仅以置顶状态分组，两组内部均按消息／已保存草稿活动时间排序；先前按 `41103` 排序的实现与旧置顶表文档已更正。回归覆盖置顶先后与活动先后相反、新消息、草稿更新／清除及过期本地偏好。
- 逐条转发在选择后立即按小时／分／秒估算一条目标队列，各目标并行、不按数量累乘；每个目标独立横幅和停止控制，目标内仍串行等待真实回执。时间和条数同时显示，整条横幅从等待到完成均可跳转，关闭／展开／停止不会触发跳转。所有队列退出时移除计时器与取消监听。
- 发送参数界面统一为秒，内部保持毫秒；最大间隔默认 `-1` 不封顶，其余有效上限在抖动后生效。默认错误策略改为跳过失败、继续下一条，仍默认仅尝试一次，不自动重试未知回执。
- 发送预检与真实重发复用元素转换器，无法等价发送的混合消息整条跳过；图片和超级表情的运行时准备不被误判为类型不支持。确认页复用 `GapMessagesModal` 的预览私聊模式，展示消息气泡／灰条和逐条原因，按 50 条向前加载，不对真实消息内容作降级改写。
