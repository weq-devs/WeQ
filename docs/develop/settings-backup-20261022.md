# 备份与恢复底层（2026-10-22，开发中）

本阶段只完成内部服务与离线测试，**尚未接入设置页、主进程路由和真实启动流程，不是已交付功能**。完整需求仍包含导出、导入、恢复默认、账号配置／API／克隆数据选择、冲突处理和应用后的反馈。

## 已有底层

- `bootstrap/backup_bundle.ts`：版本 1 ZIP 清单，逐项 CRC／SHA-256、严格逻辑路径、体积与 JSON 结构边界。校验和用于损坏检测，不认证来源。
- `backup_settings.ts`／`backup_data.ts`：全局偏好与 API 分区、账号接入记录、克隆／助手真实存储形状校验。全局 TOTP、缓存根、QQ 根覆盖和自动进入不作为设置文件直接导出；账号包保留 DB key，但不携带别处的在线进程／票据缓存。
- `backup_refs.ts`／`backup_clones.ts`：persona、群聊及群会话动作中的表情引用共用处理；参考语音、生成语音和助手报告按真实关系收集，恢复时定位到当前根。正文与模型上下文中的路径文本不做搜索替换。助手会话、断点与中文报告有独立类型，不冒充 persona。
- `common/backup_client.ts`：界面偏好键白名单与业务形状；不导出令牌、草稿或恢复现场。写失败恢复旧值，当前偏好损坏也可以被重置；回滚失败明确抛错，不确认成功。
- `backup_service.ts`：四分区快照、无敏感值清单、最多一份输入归档和冻结的预览 ID。新源、关闭预览、过期确认不混用；恢复默认只暂存偏好，不删除账号、API 或克隆数据。

包内文件单项最多 64 MiB，总展开数据最多 256 MiB，ZIP 最多 260 MiB、8192 项。超限明确失败，不生成不完整成功结果。模型、QQ 原库、漫游 SQLite、导出产物和 bot 运行入口不混入上述四分区。

## 恢复事务

`backup_restore.ts` 只能在服务构造前调用，不能直接接成运行中立即应用的 RPC。

1. 暂存分为 `writing`／`ready`，未完成的归档写入不因重启而被应用。
2. 当前目标由逻辑类型解析，包内路径不是任意落盘目标。本机路径与锁密钥通过合并保留；账号覆盖涉及旧自动进入目标时清除该目标，避免悄然打开别处来源。
3. 先在目标同卷创建私有工作区，文件独占写入、同步并校验；所有准备完成后才进入 `applying`。工作区标记避免每准备一项就重写整份事务，减少二次方元数据写入。
4. 旧文件／目录先改名为 `before`，新内容从 `next` 原子移入；校验成功且 `committed` 标记落地后才回收旧副本。配置合并保护未选的本机字段，准备／替换期间的新修改不被旧快照覆盖。
5. 异常恢复原件；无法回滚时保留现场，设置 `needsRecovery`，不得在混合数据上构造业务服务。提交标记写失败仍进入回滚，不因内存中的阶段值误判成功。
6. 已提交后的清理失败仍报告“已应用、待清理”，下次重试清理不重复导入。界面偏好只在服务器提交后交接，确认幂等，清理重试不能把已确认的偏好变回待确认。

文件与目录同步使用可用的系统能力，目录同步不受支持的平台保留尽力行为。测试使用真实临时文件与故障注入验证进程中断类恢复；没有做真实断电、真实 QQ 数据或跨设备安装验收，不能将其宣称为绝对断电保证。

## 路径修补

共用 `path_sanitize` 的 Windows 设备名判定。扩展名以及 COM／LPT 的上标 1、2、3 不能规避保留名，依据 [Microsoft 文件命名说明](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)。备份逻辑路径拒绝这类名字；不通过改名破坏包内引用。

## 仍需接入

- 账号级意图／推荐、反撤回、宽容和装扮偏好，及自定义背景关系；不能误称只备份 `AccountConfig` 就覆盖所有账号设置。
- 原 configId 的目录哈希在跨机重选数据源后会变化，需要显式映射到同 QQ 号的本机数据域；映射时保留本机接入信息，不把旧 DB key 覆盖到另一份本地库。
- 本机路径选择与缺失资源提示；不要因恢复外机路径而创建替代外盘目录。
- 启动前恢复与失败提示、`needsRecovery` 的可见处理；不可用 Native 不是读取文件型备份的审批门禁。
- RPC 文件选择／上传／保存、真实设置入口、确认与待重启状态；界面偏好交接应先应用再确认，并考虑多个窗口及确认失败的重放。
