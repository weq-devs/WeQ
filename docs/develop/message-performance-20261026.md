# 消息性能续作（2026-10-26）

## 实现边界

本轮继续[原方案](./message-sync-performance-plan-20261025.md)的 S0、S3、S5。留在当前分支，不重写消息模型，不裁掉逻辑历史，不修改独立手机仓库。业务回归使用合成消息、临时媒体及明文 SQLite；没有为了制造测量样本发送、撤回或标记真实 QQ 消息。

## 动态时间线

新增固定版本 `@tanstack/react-virtual@3.14.22`，复用其动态测量、稳定 key、滚动锚点及索引定位，不自建滚动引擎。[上游 API](https://tanstack.com/virtual/latest/docs/api/virtualizer)和本机已安装源码已核对；升级须重新运行浏览器回归。

- 短列表和长列表采用同一行分组与测量缓存；超过 150 条时仅减少挂载行，而不是切换两套布局。视口前后各预留六行，加载数据、选择快照和导出范围不受此阈值限制。
- `timelineViewport.ts` 是宿主定位桥。已加载但未挂载的目标先按索引进入视口，再校准真实消息位置；搜索、引用、日历和阅读恢复走同一入口。新请求、用户滚动、切会话和卸载取消旧定位。
- 缺口映射到后继消息块，灰条仍保留独立真实 ID；相同 msgSeq 不合并不同消息。框选使用整个逻辑窗口的位置，挂载行以 DOM 校准；键盘焦点可进入未挂载目标。
- 分开处理“块完全在阅读位置上方”与“当前正在读的块变高”，使用引擎原有补偿；禁用浏览器的第二套自动锚定，精确定位后结束旧滚动目标。
- 隐藏前保留可见锚点，隐藏时的零尺寸不回灌缓存，也不误判为读到底部；恢复后按真实 ID 重定位。正常输入、阅读状态和整个聊天页仍保留。
- 动画与普通媒体离屏后释放。正在播放的语音／视频额外保留对应行，避免滚动打断播放；结束后下一次范围更新可释放。页面隐藏仍遵循既有暂停语义。
- 行级事件用稳定回调转发最新已提交实现，再对 `MessageRow` 加 memo；反应交互拆成稳定函数及标量，避免新对象使 memo 失效。未变普通消息不因输入草稿重画。

## 后台与索引

`query_schedule.ts` 按 native 绑定和数据库串行执行 JS 侧请求。损坏观察与 salvage 代理显式指向原始绑定；独立绑定不被误当成同一个执行器，保留 QQ／并发夹具独立写入的语义。

排队交互先于后台，每最多八个交互任务给后台一个机会；批间让出事件循环，不抢占已经执行的 SQL。年度报告、普通导出、服务号导出和容错窗口使用后台上下文。每库队列限额 4096，溢出明确失败；AbortSignal 只撤销未执行任务，不假装中止已经开始的原生工作。

年度预热的三秒定时器只触发检查；创建每个缺失索引前，还需队列为空且交互安静五秒。持续活跃时可以延后，不用停用未读校准换取空闲。已有索引只读检查，不重复写入；两个缺失索引之间重新让出。关闭／切号取消排队检查和后续 DDL，报告服务也取消尚未执行的读取并拒收旧结果；已经开始的原生 SQL 仍须等待完成，取消不等于回滚。既有两项索引定义不变。

合成 SQLite 运行真实 `C2cMsgDb.listAfter` 并检查 EXPLAIN：sortNo 路径命中既有 `(40027,40003)` 索引，UID 路径保持正确结果但确实需要扫描。这个实验不是生产大库耗时基准，运行中的分区计数才可用于判断实际回退比例。

## 脱敏测量

主进程新增账号绑定的只读 `account.messagePerformance`。字段包含 JS 队列等待、等待 native Promise 的总时长、返回行数、失败、队列长度／最老等待、分区回退及固定阶段的样本分布。每项只保留最近 256 个耗时样本，数据库指标至多保留 64 个来源；不保存 SQL、参数、正文、UID、群号、路径或 URL。

渲染侧可在目标文档发送 `weq:message-performance-request` 事件，从 `#weq-message-performance` 的 JSON 读取固定字段快照。它包含查询、映射、状态提交、提交至下一动画帧、长任务及 DOM 数。来源切换丢弃旧请求的迟到耗时；跨设备浏览器不把未校准时钟差当成通知延迟。

`commitToFrame` 不是像素已绘制的证明；`nativePromiseAwait` 包含 native 内部等待，不等于原生执行耗时。没有对应接口证据的 `nativeQueueMs`／`nativeExecutionMs` 明确为 null。

只读运行指纹：

```bash
node scripts/probe-message-runtime.mjs
```

可选第二个参数为新 JSON 文件位置（独占创建，不覆盖原文件）。脚本流式计算构建产物及原生候选的 SHA-256，记录进程启动时间、源码 commit 和工作区是否有未提交内容；不打开聊天库、不登录 QQ、不重启、不 GC。磁盘候选与进程存在都不能证明模块已经加载，因此 loaded identity 字段保持 null，不能据此声称日常实例已升级。

## 滚动补偿修复（2026-10-27）

- 恢复 React Virtual 默认的同步提交：ResizeObserver 写入高度补偿后的 scrollTop 与虚拟行位置应在同一帧生效，避免先移动视口、后更新布局产生闪跳。
- 实时刷新只有真正替换消息数组时才捕获临时阅读位置，避免无变化刷新遗留快照，等下一次发送时才恢复。
- 实时刷新、入场补页与向上翻页的临时快照绑定当前视口及滚动意图版本；滚轮、触摸、键盘、滚动条拖动、主动定位、跳到底部和隐藏都会使旧补偿失效。补偿本身不增加版本，允许同一轮布局再次校准。切会话保存的持久阅读位置不附带此守卫。
- 浏览器夹具追加绘制前的动态高度校验、合成发送后迟到刷新和滚轮后迟到补偿检查；仍不操作真实 QQ 消息。
- 新消息提示只统计他人发送的追加消息；分离历史窗口改用 `UnreadInfoService` 已排除自己的入站未读增量，消息序号只用于拒绝回退快照，不再以序号差推算消息数。私聊、群聊、自发与入站混合追加均有回归。

本轮验证：desktop 6 文件 51 项、service 入站未读 21 项通过，渲染进程类型检查及本次 9 个 TS/JS 文件的 Biome 检查通过。浏览器回归验证 16 次绘制前/帧间采样、实时与分离窗口发送、迟到补偿取消、阈值切换和原有选择/导出路径；1280px/390px 深浅主题截图已检查。浏览器仍产生一次 `ResizeObserver loop completed with undelivered notifications` 通知延后错误事件，单独记录在报告 `windowErrors`，不能称为零浏览器错误；位置断言通过，没有未捕获 JS 异常。未运行全仓 CI、打包或重启日常实例，未将合成发送当作真实 QQ 验收。

## 聊天负载优化（2026-11-10）

- 聊天图片缓存只持有同源独立图片，不再持有带 React Fiber 和事件闭包的挂载节点；淘汰与清空时释放独立节点的源，不影响可见图片。
- 未读统计仍每页最多扫描 512 条，但只回传自己的消息序号和分页汇总游标。索引分区支持向前增长的区间复用，完整校准时间不因追加而延后，最多 60 秒；同水位显式校准、阅读回退、身份变化及到期重新扫描。缓存最多 256 个区间、32768 个序号，关闭账号时释放；UID 无索引回退保持原逻辑。
- 会话基础资料与角标／排序分开计算，按 ID 复用等值会话及嵌套资料，避免其他会话未读变化使当前聊天的行级 memo 失效。头页请求合并短时重复通知；未知库变化的辅助目录与草稿校准仍保留。
- 时间线虚拟化启动点从 150 条提前到 40 条，仍保留全部逻辑记录、阅读锚点、多选与播放行；浏览器夹具从实际常量读取阈值。

这些改动不代表所有原生内存保留已定位，也不构成正式包长时间运行或真实端到端延迟验收。

## 快速滚动露白回归（2026-11-11）

提前虚拟化仍保留 40 条启动点，但预挂载不再只取固定六行：根据已测行高，滚动方向前方预留约两屏、后方约一屏，保留最少行数和每侧最多 48 行的有界扩展。沿用桌面同步测量与滚动补偿，不把测量整体推迟一帧；图片仍由现有可见性机制按需加载。

`test/browser/run-timeline-scroll.mjs` 检查跨阈值补页与快速双向滚轮中逐帧的视口覆盖，并支持通过 `WEQ_TIMELINE_BASELINE_REF` 从本地 Git 读取旧钩子作同场景对照。原提交在 50 个样本中出现 1 帧视口空档；本次桌面 52 个、窄屏 48 个样本无空档，最多挂载 46／27 行。常规时间线的锚点、选择、复制、导出及播放保留断言通过；仍有 ResizeObserver 通知延后事件，不能视为布局循环已解决。

行高回调后续消除重复布局读取：ResizeObserver 已交付正的 border-box 高度时直接采用该值，不再逐行调用 `getClientRects`；无观察结果的首次挂载仍同步测量，只有一个矩形时复用其子像素高度，多个布局片段保留原来的整体边界测量。隐藏节点的零尺寸仍回退到已测值／估计值，不新增跨挂载尺寸缓存，不把同步测量或补偿推迟一帧。这项减负本身不证明通知延后事件已全部消失。

同日根据实际界面仍有露白的反馈继续调整：固定行高列表在消耗缓冲时同步交付新窗口，不逐像素重渲；原生滚动位置因数据缩短被钳制时，在绘制前同步。消息头像及会话／联系人列表的小槽位使用本地缩略图与 100 像素 CDN 回退，大图与名片保留原图入口。目录事件型 Context 保持引用并转发至最新已提交回调，联系人目录 ID 等值复用，逐行成员判断改为集合查询。合成检查不能替代三处真实界面的露白反馈。

好友列表进一步收窄会话数据到私聊并使用 memo 边界，私聊引用未变时不随群消息重绘；群助手集合成员未变时保持同一引用，分组控制器的事件型 Context、侧栏选择、引用跳转与群消息预览回调保持稳定。操作仍转发到最新已提交实现，真实好友未读、资料、分组和选择状态变化继续更新；没有缩小滚动缓冲或延后桌面测量。

展开分组中的好友也按行 memo 化，只接收当前行的活动／选择、拖拽能力、未读／静音、资料和指标记录；不把整个选中集合、会话或指标表传给每一行。切换活动项只重画新旧两行，单个好友的未读或指标变化不重画其他行，打开右键菜单不重画列表正文。事件复用现有已提交回调转发，未重画行的多选捕获事件仍在调用时获取最新范围、模式和锚点，保留重复分组中的范围选择与拖拽行为。原有行节点、头像及展开范围不因这项优化移除或延迟挂载，没有新增跨轮次强引用缓存。

好友与群目录排序沿用会话排序的本轮键预计算：每个元素的指标值、生日有效性或群创建时间等仅在进入本次排序时计算，不在每次比较中重复读取、解析。比较器保持原来的空值沉底、升降序、生日同日年龄次序、拼音与 ID 打平规则，返回原对象且不修改输入数组；键只在本轮存活，下一轮重新读取资料，不引入长期缓存。

最近会话摘要转换按不可变 wire 对象使用 WeakMap 复用，头页单行变化不再重解其他行的预览。本地账号、群名、机器人集合、预览名称及资料映射上下文变化时重建缓存，避免名称更新被旧转换结果遮住；缓存不强持有已离开查询缓存的 wire 对象。

同一映射上下文内，群资料转换和成员归属覆盖也按不可变输入复用。群资料对象与基础会话对象共同决定投影，基础列表和带角标的目录行各有弱键条目，避免同一资料在两层输入交替时反复失效；成员归属只在状态变化时替换。资料、会话或映射上下文变更仍重新转换，不拿消息序号／时间判断资料是否相同。所有资料和会话索引均为弱键，不新增长期强引用目录；不改变查询、排序、列表挂载范围或首帧交付。MainView 回归先复现一条会话预览更新时另一个群资料被转换两次，再确认降为零，真实群名变更仍更新。

固定行高列表的视口级额外缓冲由主会话列表通过 `bufferScreens={1}` 显式启用；分析／导出等选择器保持紧凑的默认 DOM 预算。滚动事件内同步交付窗口对两种模式都保留，不因修复选择器预算而缩小主列表缓冲。

## 离屏动画资源（2026-11-11）

动态表情和浮屏挂件仍在挂载时预取资源并准备 SVG，不等到进入视口才加载。播放器关闭自动播放，由现有近视口观察、标签活动状态及所属文档可见性决定播放／暂停。只暂停，不销毁当前帧、重置进度或移除已加载的内容；骰子等交互表情保持前奏次数，结果完成后重新可见不会重播。换源和卸载中止 JSON 请求，仍由对应组件销毁播放器。

使用的是单实例 `play()`／`pause()`，不调用全局冻结。已核对安装版本 `lottie-web@5.13.0` 的初始帧、完成事件与播放管理实现；[官方 API](https://github.com/airbnb/lottie-web/wiki/Usage)明确暂停保留当前帧、播放从当前帧继续。

头像与图片加载占位的 CSS 动画按文档共享一个 IntersectionObserver 和可见性监听。仅接近视口时保留闪光动画，离屏或文档隐藏时移除该动画实例，静态占位、图片节点、尺寸、源及原有加载策略不变；这条路径不增加逐图片 React 状态。图片就绪、失败或卸载时解除观察，最后一个使用者离开后释放共享观察器。缺少 IntersectionObserver 时仍显示占位并跟随文档可见性，不留下永久空白。

这轮不改变时间线及固定列表的预挂载预算，也不把桌面测量延后；并非已证明所有真实滚动露白或原生内存增长均已解决。

## 会话预览解码复用（2026-11-11）

实时头页每次返回最多 500 条会话，原先每次都重新容错解析预览的 protobuf。`RecentContactDb` 现在仅缓存预览解码结果，以会话类型和标识隔离，完整原始字节相同才复用；消息序号和时间不作为正文未变的依据。同序号编辑、撤回等预览变化仍即时重新解析，备注、昵称、头像、置顶、免打扰等元数据每次从本轮查询取值。

头页、搜索和按目标读取共用实例内 LRU，最多 1024 项、2 MiB 原始预览字节，单项超过 64 KiB 只是不缓存，返回内容不裁剪。先复制适合缓存的原始字节，再基于独立副本解码，避免缓存字节或解码出的字段持有原生查询返回的其他缓冲区。解码对象还占有内存，2 MiB 是原始字节预算，不是整个缓存的堆占用承诺。关闭账号时清空缓存；不同账号实例不共享。返回行的预览字段清空时会清掉该项，容量淘汰只影响下次是否重新解码，不影响完整会话目录。

该路径没有改 SQL、查询频率、分页、实时通知、草稿校准或滚动策略。数据库回归覆盖精确字节更新、元数据刷新、原生缓冲区被复用的反例，以及条数／字节淘汰、超预算完整返回和关闭清理；不能将这些机制检查替代日常运行实例的长时间内存验证。

## 补入消息与引用行复用（2026-11-11）

刷新合并先按稳定消息 ID 对齐并复用未变对象，数组层只检查长度及逐项引用，不再按数组下标对整个窗口做第二次深比较。后者会在中间补入、删除或前插消息时打散已经按 ID 复用的后续行，使模板缓存及行级 memo 失效。有界刷新仍保留未查询到的旧历史，同序号灰条、覆盖范围内的修改／删除及完整刷新清空语义不变。

引用回复不再因任意窗口变化而整条重新转换。已有缓存行仍根据最新原文索引校准引用元素，元素未变时保留同一 Message；只在引用真正变化时替换该行的元素，不重复解析未变正文。原文迟到、编辑、移出窗口或变成重号歧义时仍重新补全／撤掉回退摘要，已有内嵌摘要不被索引结果覆盖；账号、会话及资料上下文继续使用原有缓存失效规则。没有新增长期强引用缓存。

定向回归通过实际 MainView 的私聊／群聊刷新路径检查引用对象及摘要变化，另在真实 ChatPane 中检查 MessageRow 计数：前面补入一条消息只增加一行重绘，不重画旧消息。未改预挂载、测量、锚点或媒体加载策略；这些检查不替代三处真实快速滚动及原生内存保留的持续定位。

群成员、资料或机器人名单的引用变化也不再整批清空模板缓存。未变 wire 的正文与基础字段继续使用原转换结果，身份输入变化时只重新校准发送者和撤回操作者，引用仍校准最新原文及群名片；值相同保留整条 Message，变化才替换对应对象。缓存仍以 wire 为 WeakMap 键，并随会话身份／账号资料上下文失效；条目仅保存轻量身份版本符号，不持有历史资料 Map。普通窗口追加且身份版本未变时，不额外解析旧发送者。

群消息发送者的 QQ 号回退使用同批只读成员快照的延迟索引：UID 及自身身份命中时不建立，首次回退只遍历一次，随后命中和未命中均直接查表，重复号码沿用原 Map 遍历的首项。主时间线、范围加载、已删除／已撤回窗口和预览均复用本批索引；单条调用的无索引路径直接遍历而不复制成员数组，也不跨调用缓存。成员合并以 UID 集合判断重复，不对每个补全成员扫描已有列表。索引只跟随当前快照，不是全局强引用缓存。

小回归通过实际 MainView 的资料追加、备注修改／移除、机器人名单增删和定向群名片修改／清空检查消息引用及名称更新；引用抬头与撤回操作者同步变化。另用成员 getter 计数确认一批 200 条回退只读 200 个成员号码，重复未命中不重扫，下一份快照读取新值。未重启日常实例或运行长时间原生采样，不据此宣称完整内存目标已解决。

消息预览按消息页、会话资料、账号、群成员、机器人与本地资料依赖复用整页转换结果。无关 MainView 更新以及加载更多的状态切换不重新构造每条 Message，已有 MessageRow 的行级 memo 可以继续生效；翻页和真实资料更新仍同步重新转换，不延后消息。每页预览只建立一次引用索引，不让每条引用再次过滤整页；主时间线索引单独随 wire 窗口变化，不在仅身份校准时重建。关闭预览或切号后不保留旧预览结果，没有新增全局缓存。实际私聊／群聊入口回归覆盖 50 条首屏、重复渲染、前插原文的第 51 条和本地备注更新，沿用原有序号／客户端序号与发送者、时间的重号消歧规则。

## 开发性能条目保留（2026-11-11）

当前 React 19.2 开发构建默认生成 Performance tracks，组件 props 变化明细经 UserTiming 写入性能记录；正式构建默认不启用这套开发插桩，见 [React 官方说明](https://react.dev/reference/dev-tools/react-performance-tracks)。这些明细会保留原生序列化缓冲，普通 JS 堆和图片缓存统计不足以覆盖它们，不能仅凭 JS 堆回落排除持续保留。

渲染根的 TrpcProvider 在原有诊断生命周期中安装 `installDevelopmentTiming`，只在开发模式启用。通过 PerformanceObserver 观察当前安装 React 使用的组件记录命名格式（零宽前缀 `\u200b`），以 64 条作为批次清理触发点，按名称清理组件明细历史。首次安装也处理已经缓冲的记录，大批提交可在观察回调前超过触发点，但不继续累积历史。清理器只保留名称与计数，不读取 `detail`，避免把明细再次反序列化到 JS 堆。

没有替换 performance API 或关闭 React 插桩。其他 PerformanceObserver 仍能收到原始记录及明细，非组件命名空间的应用性能条目保留；卸载／重装释放观察器及剩余组件记录，正式构建不安装。历史查询不再承担无限期记录组件 props 的用途，需要长时间分析时使用显式性能录制。

除了模拟批次、卸载与不读取 detail 的回归，还通过实际安装的 React 开发构建验证生成格式，避免实现和测试只共享同一个前缀假设。真实 Electron 对照中，两组均交付 199 条组件记录、明细可读，清理后的时间线保留从 199 条降至 7 条。这项修复不改变列表虚拟化、预挂载、滚动锚点或媒体加载，也不能据此把正式构建和所有卡顿路径一并标为完成。

## 数据库监听释放（2026-11-11）

`DbWatchService` 的句柄卸载与整体销毁共用按 entry 登记状态判断的释放路径，关闭文件监听并调用任务自身的 `dispose`。消息 hook 自己安排的补齐／失败重试不属于共享轮询，必须一起停止，避免切号、关闭实时监听或取消订阅后继续查询旧会话。已移除的 entry 及其旧句柄不再次释放，其他任务继续运行。

文件 watcher 报错不等于任务卸载：只关闭失效的 watcher，保留原任务接受共享轮询。原代码在此处调用 `dispose`、却在真正卸载时漏调，两种路径的生命周期相反。使用真实消息 hook 和模拟文件、数据库的小回归复现：旧实现卸载后推进五秒，水位读取从两次增到四次；修复后保持两次且无残留计时器。另覆盖 watcher 错误后的轮询、独立任务和重复销毁。未读取真实 QQ 数据库或用这些计数代替日常实例的长期内存测量。

同一 `DbWatchService.tick` 内，相同规范化数据库路径只读取一次文件快照，供各任务与自己的变化基线比较；不跨轮缓存，也不改变文件事件与轮询间隔。回调仍收到独立的文件数组和文件描述对象，不能让一个 hook 的修改污染另一个 hook。三个任务、两条路径的夹具中，每轮同步目录扫描从三次降到两次，并覆盖不同时间挂载的基线、下一轮文件增长和 payload 修改的反例。读取内容仍仅为文件元信息，不读取数据库正文。

消息 hook 的启动基线和后续补齐读取也绑定自身生命周期信号，卸载时撤销尚未执行的数据库排队工作；已进入 native 的单次读取仍非抢占，返回后不再建立旧基线、交付旧批次或读取整页的同序号边界。迟到失败不重新登记已退出任务的重试状态。复用数据库层 `withDatabaseSignal` 仅补充取消条件，继承调用方的优先级并合并已有父取消信号；没有用延迟启动基线或降低实时查询优先级来换取减负。真实 JS 调度器与模拟查询回归覆盖启动／补齐排队取消、迟到 500 条整页不补查边界，以及后台优先级和父取消的反例；原有多页补齐、首条入站、重号与失败重试继续保留。

## 后台推送批次（2026-11-11）

SSE 推送的每次整理／发送由独立 AbortController 持有。停止、停用目标或修改目标地址／鉴权时取消旧批次；水位读取、批量预览、合并转发缓存读取的异步边界检查取消，HTTP 同时合并原有超时信号与批次取消信号。迟到结果不能推进水位、消费队列、重建重试或覆盖新批次的运行状态；正常失败仍沿用原有退避，切换目标则保留待推行并立即由新目标接续，停用期间不接收新的积压。

整理中的数据库读取接入现有 `withDatabasePriority('background', ..., signal)`，取消时撤销尚未开始的排队读取，不把后台推送当成交互查询。已经进入 native 的单次读取仍遵循现有非抢占语义，其返回后不继续处理旧批次。测试使用真实 JS 数据库调度器与模拟读取确认，停止后排队工作不会在阻塞查询结束后补执行；没有由此声称能中断 native 内部工作。

发送确认按本批 PendingRow 对象消费，不再按开始时的队列长度截断头部。发送期间若超过原有 maxPending 并裁掉旧头部，尚未发送的新行仍保留；原有容量及溢出丢最旧的策略未扩大或改写。小回归涵盖停止、快速重启、换目标、停用、迟到成功／失败、各整理阶段取消、队列溢出和正常失败重试；只用合成消息及 fetch 桩，不真实推送或读取 QQ 原库。

群关键词提醒不再对整页消息逐条 `void evaluate`。命中通知串行等待，并将整个交付 Promise 返回给 `NtMsgHook` 原有的页级背压及失败重试；未配置规则的群直接跳过。成功行沿用去重，失败行删除对应标记后由 hook 重试，不因失败放行后续整页，也不产生无人接收的异步拒绝。挂载批次绑定运行代次，停止／重启后旧批次在当前通知返回时退出，旧失败不删除新代次的去重；已经交给宿主的单次通知不声称可被强行撤销。规则内容、成员范围、通知摘要和去重容量不变。100 条合成命中夹具确认峰值回调并发从 100 降到 1，仍交付全部消息，并覆盖失败重试和迟到失败的代次隔离。

## 撤回只读监听（2026-11-11）

撤回监听的挂载代次与基线读取各有生命周期保护。停止时取消排队读取，重启或重新启用时换掉旧读取上下文；迟到结果不能通知、继续分页或覆盖新游标，已排队的旧挂载回调也不能借用新上下文。基线未完成时，文件变化等待同一个 Promise，不再并发重复建立基线；失败后仍保留下一次变化重新建立基线的路径。监听未启动时修改配置不额外读取通知基线，启动时仍即时建立，历史记录不会作为新撤回通知。

`AntiRecallDb.close()` 会关闭同路径共用的 native 连接，不是只释放临时 JS 包装。撤回监听、状态、记录列表与目录因此与原有消息页批量标记入口一致，只借用账号连接，不在每次只读查询后关闭；账号退出仍由 `AccountSession.dispose` 中同库的消息读者关闭连接。触发器写入路径的 `try/finally close` 以及 QqDb 写入后的锁释放逻辑未改。

明文 SQLite 与模拟在途读取的小回归覆盖：旧整页在停止后不通知／续页、旧基线不覆盖重启或重新启用后的游标、启动排队取消、并发基线复用、正常 201 条分页、大整数游标不重复、私聊／数据线合并及空会话过滤。只读连接不调用 close，另以模拟 reconcile 检查写入路径仍关闭；这不是对真实 QQ 触发器或锁状态的长测验收。
