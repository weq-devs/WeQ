# 消息性能续作（2026-10-26）

## 实现边界

本轮继续[原方案](./message-sync-performance-plan-20261025.md)的 S0、S3、S5。留在当前分支，不重写消息模型，不裁掉逻辑历史，不修改独立手机仓库。业务回归使用合成消息、临时媒体及明文 SQLite；没有为了制造测量样本发送、撤回或标记真实 QQ 消息。

## 动态时间线

新增固定版本 `@tanstack/react-virtual@3.14.22`，复用其动态测量、稳定 key、滚动锚点及索引定位，不自建滚动引擎。[上游 API](https://tanstack.com/virtual/latest/docs/api/virtualizer)和本机已安装源码已核对；升级须重新运行浏览器回归。

- 短列表和长列表采用同一行分组与测量缓存；超过 150 条时仅减少挂载行，而不是切换两套布局。视口前后各预留六行，加载数据、选择快照和导出范围不受此阈值限制。
- `timelineViewport.ts` 是宿主定位桥。已加载但未挂载的目标先按索引进入视口，再校准真实消息位置；搜索、引用、日历和阅读恢复走同一入口。新请求、用户滚动、切会话和卸载取消旧定位。
- 缺口映射到后继消息块，灰条仍保留独立真实 ID；相同 msgSeq 不合并不同消息。框选使用整个逻辑窗口的位置，挂载行以 DOM 校准；键盘焦点可进入未挂载目标。
- 分开处理“块完全在阅读位置上方”与“当前正在读的块变高”，使用引擎原有补偿；禁用浏览器的第二套自动锚定，精确定位后结束旧滚动目标。
- 隐藏前保留可见锚点，隐藏时的零尺寸不回灌缓存，也不误判为读到底部；恢复后按真实 ID 重定位。正常输入、阅读状态和整个聊天页仍保留。
- 动画与普通媒体离屏后释放。正在播放的语音／视频额外保留对应行，避免滚动打断播放；结束后下一次范围更新可释放。页面隐藏仍遵循既有暂停语义。
- 行级事件用稳定回调转发最新已提交实现，再对 `MessageRow` 加 memo；反应交互拆成稳定函数及标量，避免新对象使 memo 失效。未变普通消息不因输入草稿重画。

## 后台与索引

`query_schedule.ts` 按 native 绑定和数据库串行执行 JS 侧请求。损坏观察与 salvage 代理显式指向原始绑定；独立绑定不被误当成同一个执行器，保留 QQ／并发夹具独立写入的语义。

排队交互先于后台，每最多八个交互任务给后台一个机会；批间让出事件循环，不抢占已经执行的 SQL。年度报告、普通导出、服务号导出和容错窗口使用后台上下文。每库队列限额 4096，溢出明确失败；AbortSignal 只撤销未执行任务，不假装中止已经开始的原生工作。

年度预热的三秒定时器只触发检查；创建每个缺失索引前，还需队列为空且交互安静五秒。持续活跃时可以延后，不用停用未读校准换取空闲。已有索引只读检查，不重复写入；两个缺失索引之间重新让出。关闭／切号取消排队检查和后续 DDL，报告服务也取消尚未执行的读取并拒收旧结果；已经开始的原生 SQL 仍须等待完成，取消不等于回滚。既有两项索引定义不变。

合成 SQLite 运行真实 `C2cMsgDb.listAfter` 并检查 EXPLAIN：sortNo 路径命中既有 `(40027,40003)` 索引，UID 路径保持正确结果但确实需要扫描。这个实验不是生产大库耗时基准，运行中的分区计数才可用于判断实际回退比例。

## 脱敏测量

主进程新增账号绑定的只读 `account.messagePerformance`。字段包含 JS 队列等待、等待 native Promise 的总时长、返回行数、失败、队列长度／最老等待、分区回退及固定阶段的样本分布。每项只保留最近 256 个耗时样本，数据库指标至多保留 64 个来源；不保存 SQL、参数、正文、UID、群号、路径或 URL。

渲染侧可在目标文档发送 `weq:message-performance-request` 事件，从 `#weq-message-performance` 的 JSON 读取固定字段快照。它包含查询、映射、状态提交、提交至下一动画帧、长任务及 DOM 数。来源切换丢弃旧请求的迟到耗时；跨设备浏览器不把未校准时钟差当成通知延迟。

`commitToFrame` 不是像素已绘制的证明；`nativePromiseAwait` 包含 native 内部等待，不等于原生执行耗时。没有对应接口证据的 `nativeQueueMs`／`nativeExecutionMs` 明确为 null。

只读运行指纹：

```bash
node scripts/probe-message-runtime.mjs
```

可选第二个参数为新 JSON 文件位置（独占创建，不覆盖原文件）。脚本流式计算构建产物及原生候选的 SHA-256，记录进程启动时间、源码 commit 和工作区是否有未提交内容；不打开聊天库、不登录 QQ、不重启、不 GC。磁盘候选与进程存在都不能证明模块已经加载，因此 loaded identity 字段保持 null，不能据此声称日常实例已升级。

## 滚动补偿修复（2026-10-27）

- 恢复 React Virtual 默认的同步提交：ResizeObserver 写入高度补偿后的 scrollTop 与虚拟行位置应在同一帧生效，避免先移动视口、后更新布局产生闪跳。
- 实时刷新只有真正替换消息数组时才捕获临时阅读位置，避免无变化刷新遗留快照，等下一次发送时才恢复。
- 实时刷新、入场补页与向上翻页的临时快照绑定当前视口及滚动意图版本；滚轮、触摸、键盘、滚动条拖动、主动定位、跳到底部和隐藏都会使旧补偿失效。补偿本身不增加版本，允许同一轮布局再次校准。切会话保存的持久阅读位置不附带此守卫。
- 浏览器夹具追加绘制前的动态高度校验、合成发送后迟到刷新和滚轮后迟到补偿检查；仍不操作真实 QQ 消息。
- 新消息提示只统计他人发送的追加消息；分离历史窗口改用 `UnreadInfoService` 已排除自己的入站未读增量，消息序号只用于拒绝回退快照，不再以序号差推算消息数。私聊、群聊、自发与入站混合追加均有回归。

本轮验证：desktop 6 文件 51 项、service 入站未读 21 项通过，渲染进程类型检查及本次 9 个 TS/JS 文件的 Biome 检查通过。浏览器回归验证 16 次绘制前/帧间采样、实时与分离窗口发送、迟到补偿取消、阈值切换和原有选择/导出路径；1280px/390px 深浅主题截图已检查。浏览器仍产生一次 `ResizeObserver loop completed with undelivered notifications` 通知延后错误事件，单独记录在报告 `windowErrors`，不能称为零浏览器错误；位置断言通过，没有未捕获 JS 异常。未运行全仓 CI、打包或重启日常实例，未将合成发送当作真实 QQ 验收。

## 聊天负载优化（2026-11-10）

- 聊天图片缓存只持有同源独立图片，不再持有带 React Fiber 和事件闭包的挂载节点；淘汰与清空时释放独立节点的源，不影响可见图片。
- 未读统计仍每页最多扫描 512 条，但只回传自己的消息序号和分页汇总游标。索引分区支持向前增长的区间复用，完整校准时间不因追加而延后，最多 60 秒；同水位显式校准、阅读回退、身份变化及到期重新扫描。缓存最多 256 个区间、32768 个序号，关闭账号时释放；UID 无索引回退保持原逻辑。
- 会话基础资料与角标／排序分开计算，按 ID 复用等值会话及嵌套资料，避免其他会话未读变化使当前聊天的行级 memo 失效。头页请求合并短时重复通知；未知库变化的辅助目录与草稿校准仍保留。
- 时间线虚拟化启动点从 150 条提前到 40 条，仍保留全部逻辑记录、阅读锚点、多选与播放行；浏览器夹具从实际常量读取阈值。

这些改动不代表所有原生内存保留已定位，也不构成正式包长时间运行或真实端到端延迟验收。

## 快速滚动露白回归（2026-11-11）

提前虚拟化仍保留 40 条启动点，但预挂载不再只取固定六行：根据已测行高，滚动方向前方预留约两屏、后方约一屏，保留最少行数和每侧最多 48 行的有界扩展。沿用桌面同步测量与滚动补偿，不把测量整体推迟一帧；图片仍由现有可见性机制按需加载。

`test/browser/run-timeline-scroll.mjs` 检查跨阈值补页与快速双向滚轮中逐帧的视口覆盖，并支持通过 `WEQ_TIMELINE_BASELINE_REF` 从本地 Git 读取旧钩子作同场景对照。原提交在 50 个样本中出现 1 帧视口空档；本次桌面 52 个、窄屏 48 个样本无空档，最多挂载 46／27 行。常规时间线的锚点、选择、复制、导出及播放保留断言通过；仍有 ResizeObserver 通知延后事件，不能视为布局循环已解决。

同日根据实际界面仍有露白的反馈继续调整：固定行高列表在消耗缓冲时同步交付新窗口，不逐像素重渲；原生滚动位置因数据缩短被钳制时，在绘制前同步。消息头像及会话／联系人列表的小槽位使用本地缩略图与 100 像素 CDN 回退，大图与名片保留原图入口。目录事件型 Context 保持引用并转发至最新已提交回调，联系人目录 ID 等值复用，逐行成员判断改为集合查询。合成检查不能替代三处真实界面的露白反馈。

好友列表进一步收窄会话数据到私聊并使用 memo 边界，私聊引用未变时不随群消息重绘；群助手集合成员未变时保持同一引用，分组控制器的事件型 Context、侧栏选择、引用跳转与群消息预览回调保持稳定。操作仍转发到最新已提交实现，真实好友未读、资料、分组和选择状态变化继续更新；没有缩小滚动缓冲或延后桌面测量。

最近会话摘要转换按不可变 wire 对象使用 WeakMap 复用，头页单行变化不再重解其他行的预览。本地账号、群名、机器人集合、预览名称及资料映射上下文变化时重建缓存，避免名称更新被旧转换结果遮住；缓存不强持有已离开查询缓存的 wire 对象。

固定行高列表的视口级额外缓冲由主会话列表通过 `bufferScreens={1}` 显式启用；分析／导出等选择器保持紧凑的默认 DOM 预算。滚动事件内同步交付窗口对两种模式都保留，不因修复选择器预算而缩小主列表缓冲。

## 离屏动画资源（2026-11-11）

动态表情和浮屏挂件仍在挂载时预取资源并准备 SVG，不等到进入视口才加载。播放器关闭自动播放，由现有近视口观察、标签活动状态及所属文档可见性决定播放／暂停。只暂停，不销毁当前帧、重置进度或移除已加载的内容；骰子等交互表情保持前奏次数，结果完成后重新可见不会重播。换源和卸载中止 JSON 请求，仍由对应组件销毁播放器。

使用的是单实例 `play()`／`pause()`，不调用全局冻结。已核对安装版本 `lottie-web@5.13.0` 的初始帧、完成事件与播放管理实现；[官方 API](https://github.com/airbnb/lottie-web/wiki/Usage)明确暂停保留当前帧、播放从当前帧继续。

头像与图片加载占位的 CSS 动画按文档共享一个 IntersectionObserver 和可见性监听。仅接近视口时保留闪光动画，离屏或文档隐藏时移除该动画实例，静态占位、图片节点、尺寸、源及原有加载策略不变；这条路径不增加逐图片 React 状态。图片就绪、失败或卸载时解除观察，最后一个使用者离开后释放共享观察器。缺少 IntersectionObserver 时仍显示占位并跟随文档可见性，不留下永久空白。

这轮不改变时间线及固定列表的预挂载预算，也不把桌面测量延后；并非已证明所有真实滚动露白或原生内存增长均已解决。
