# 首次进入会话优化（2026-10-29）

## 目标与实现

首次进入也以真实正文可读为目标，继续复用已有窗口缓存、消息优先队列和动态时间线。
不改版本号，不重启日常实例，不对真实 QQ 消息做测试操作。

### 点击前准备

- 主消息列表报告实际可视行，不使用虚拟列表的预留行。列表稳定 300ms 后，串行准备最多
  三个真实会话的首屏；悬停或键盘聚焦 80ms 后优先对应目标。克隆、频道聚合、设备和其他
  合并入口不使用普通消息源预取。
- 同时最多一个首屏读取，沿用群 25／私聊 50 条。结果进入原来的 12 窗口／12 MiB 估算缓存，
  不创建第二份消息缓存；不会提前加载媒体，也不发送已读包或写入已读状态。
- 每个目标有 15 秒尝试间隔，尝试记录最多 16 个。滚离目标会撤销未接用的读取，隐藏页面、
  未连接的 WebSocket 和账号切换会停止相应准备工作。
- 从第一条未读开始阅读的偏好确认前不进行预取；开启该偏好后不使用预取尾页作为阅读现场。
  原有历史阅读缓存、搜索定位与阅读位置继续按原规则处理。

### 点击接用

`ConversationFirstPage` 让点击接用同一在途读取，包括已到达的本地阶段，不重复启动消息 SQL。
接用通过 `promoteMessageRead` 将同一信号下的排队 SQL 及后续 SQL 提升到交互优先级，
不抢占已经执行的 native 工作。提升先于订阅到达也能生效，旧提升不会复活取消的窗口。

切走、取消和来源变化都拒收旧结果。来源版本在读取期间改变时，不将该结果标为新鲜预取缓存。
预取失败不影响用户点击后的普通读取。

### 冷首屏分阶段交付

新订阅 `account.latestPage` 并行启动本地页与离线漫游缓存读取：

1. 非空本地页完成后立即交付，包含本地撤回与删除状态；引用媒体仍按原来的后补路径加载。
2. 漫游缓存完成后，用现有身份、排序、隐藏与去重规则交付完整结果。
3. 完整结果与本地页相同时，只发送 `reuseLocal` 收尾标记，避免重复传输和映射正文。

空本地页不提前显示“没有消息”。中间页保持读取未完成，不触发已读收尾或开放分页；
合并完成时复用已有刷新合并规则保留较早上下文，并保留阅读锚点。关闭自动跟随后，入场分批
交付仍按现有规则贴底，用户主动上滚后停止跟随。

已有完整窗口缓存不会被本地中间页替换。WebSocket 未连接、连接中断或旧主进程尚无新接口时，
退回现有独立 HTTP／IPC 消息页，继续接入当前窗口的取消与来源检查。

### 新私聊索引补查

`UidMap` 仍在账号打开时加载完整映射；对后续缺失的 UID，消息页先按需补查小映射表，成功后
常驻复用。补查按读取信号合并，不让一个窗口的取消传播到另一个窗口。没有唯一有效分区时，
普通阅读继续使用原有 UID 回退；后台预取跳过该目标，避免推测性地扫描大消息表。

新增查询只读 `nt_uid_mapping_table`，不改 QQ 表或索引。在线账号和静态账号使用相同补查路径。

## 诊断与验证

现有消息诊断增加预取启动、完成、接用、缓存命中、前台分阶段请求与回退次数。
`entryFirstRows` 测量入场读取开始到首份非空行交付，不冒充点击到像素绘制的端到端耗时。

专项测试使用合成消息、受控异步返回和明文 SQLite，覆盖空页、慢缓存、收尾复用、快切与
迟到结果、优先级提升、取消隔离、真实可视范围、未读偏好切换和缺失／歧义 UID 映射。

固定快照检查发现既有提交将 5 行转写参数检查错放进宽容配置和隔离目录读取路由，导致语法及
类型错误。本轮只纳入当前工作区删除这 5 行的必要修订，并回归未打开服务时的空快照返回；
旁边的转写、导出与空间功能改动不纳入本次提交。
另将既有语音配置对象中交错的 TTS 条件表达式恢复为完整属性，并验证原有语音配置测试；
不改变该功能的设置与行为。

浏览器入口继续使用：

```bash
node apps/desktop/test/browser/run-page-cache.mjs
```

其中首次会话场景使用真实 ChatPane、入场加载器和预取调度器，分别模拟本地 100ms 与
完整结果 800ms 的延迟，记录有预取与无预取时的正文 DOM 提交时间、读取次数、完成时序和
入场贴底。它们是合成路径验证，不是实际 QQ 大库的 P50/P95。

本轮相关回归共 24 文件、131 项通过（desktop 84、db 16、service 31），主进程与 db／account／
service 类型检查、源码快照 Web 构建通过。最终独立渲染层类型检查未完成重跑，不能记为最终全绿。
浏览器合成样本中，冷首屏 DOM 提交约 136–141ms，预取命中约 41–47ms，各只读取一次，
无横向溢出，最终底部距离为 0。记录到一次已有 ResizeObserver 通知延后事件，未冒称零浏览器错误。
