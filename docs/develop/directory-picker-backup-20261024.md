# 目录选择与本地备份导入（2026-10-24）

本文记录源码实现，不代表已发布、安装或通过真实 QQ 联调。

## 目录发现

- `apps/desktop/src/main/directory_scan.ts` 提供共享的异步分层遍历：先检查所选目录，无命中才深入下一级；递归模式由界面确认后另发请求。
- 命中后不继续进入该分支的媒体树，不跟随遍历中发现的目录符号链接。选择入口会解析真实路径。最多遍历 4096 个目录、返回 64 项；无法读取的子目录和截断会单独返回，根目录错误直接报告。
- 导出查看器保留原来的文件解析与基线去重。旧基线索引还会返回子目录，因此分层扫描按来源根目录过滤，避免先发现一个新基线就遗漏同层旧 JSON 导出。
- 查看器递归请求只接受本次选择生成的一次性 token，不接受任意路径；token 十分钟过期，待确认项最多保留 16 个，取消会撤销。

## 账号与媒体

本地备份对每个候选目录依次尝试当前层、`nt_db` 和 `nt_qq/nt_db`，因此不依赖运行系统，也不强制根目录叫 Tencent Files。实际平台路径依据 `packages/platform/src/{win32,linux,darwin}/paths.ts`：

| 来源 | 账号数据库相对布局 |
| --- | --- |
| Windows | `<uin>/nt_qq/nt_db` |
| Linux、macOS | `nt_qq_<UID哈希>/nt_db` |
| 已解密或 Android 平铺备份 | 当前目录下的数据库文件 |

Linux/macOS 的目录身份匹配复用平台包的 `linuxAccountDirName`；macOS 默认数据根为 QQ 沙盒容器内的 `Data/Library/Application Support/QQ`。扫描候选的 `dirPath` 指向完整账号根，`dbDir` 独立保存内部数据库位置，`mediaDir` 指向同账号媒体树；即使用户选中 nt_db，也会上溯到已知布局的完整账号根。界面展示账号身份（可解密时）、数据库数量/体积、完整账号路径与媒体目录状态；不能验证身份时明确标记待验证。

保存的静态配置新增 `backupAccountDir`，但原有 `dataDir` 和配置 ID 仍沿用数据库路径，以保留设置、缓存，并避免与同根目录的在线配置相互覆盖。重开时兼容账号根和旧 nt_db 路径，备份恢复映射保留本机账号根。

多个候选通过独立 `Modal` 选择，不再平铺在登录侧栏。弹窗最大高度受视口限制，头部和确认栏固定，只有候选列表滚动；选项为草稿，「使用此目录」后才更新主面板，取消/关闭/Escape 不更新。单个候选保持自动选中，切换入口仍可重新打开列表而不重复扫描。弹窗通过 portal 离开登录布局，颜色单独适配主题 token。

`nt_db` 的同级 `nt_data`，或平铺备份自己的 `nt_data`，会映射到既有 `withResourceRoots`。静态会话每次重开都会重新识别，媒体优先使用备份；缺失时保持原有本机目录关联和在线补全行为。平铺备份不借用父目录下可能属于其他账号的媒体目录。

## 密钥路径

1. 优先检查明文数据库和 Android 自动推导，再验证已有配置密钥。明文资料库可读不代表消息库明文，两个路径都必须验证。
2. 需要在线密钥时先复用与当前 QQ PID 匹配的已有 SSO 物料；缺失时通过现有 `attachHook` 和 `attachAndRegisterSsoSession` 读取内存，必要时进入平台已有的提权流程。同批扫描对同一 PID 至多尝试一次读取，取消后不因其它备份反复弹出提权。
3. 沿用 `requestDecryptKeyFromInstance` 读取数据库头的 salt 并请求 OIDB，不另造协议。所得密钥必须通过消息库校验，且解密后的资料身份与配置一致。
4. 明确的数字账号或 UID 哈希目录只使用对应账号配置；无法从路径识别身份的平铺备份由服务端核对 salt，成功后再验证资料身份。完全离线不触发在线请求或提权；失败仍可手工输入。

本地备份与维护工具的「其他设备密钥」现在共同调用 `fetchOtherDeviceDatabaseKey`，而非各自实现一条相似链路。它从真实在线实例补齐旧配置缺失的 UID，优先复用匹配 PID 的已有票据，必要时走现有 attach；同批备份共享已登记会话，避免第一份读取成功后，其余备份因“一次读取”标记而无法继续取密钥。

旧备份资料主表经实盘确认包含 `profile_info_v2`。静态预览与账号会话均探测实际的 `profile_info_vN`，排除依赖 QQ 私有 tokenizer 的 FTS 表；旧表缺失的新字段明确投影为 NULL，不能让 SQLite 的双引号字符串回退把列号伪装成字段值。使用同账号配置/服务端密钥时，预览精确查询该 UIN，不再被更新时间更晚的联系人抢占。

## 弹窗位置

桌面宿主将确认的位置原子保存到 Electron `userData/dialog-locations.json`，不保存密钥、消息或文件内容。文件夹按用途标题分组，文件按标题和扩展名分组，保存框按 `HostBridge.pickSaveTarget.locationKey` 分组；分析长图也使用同一存储。取消不更新，保存框保留本次建议文件名。目录消失时退到仍存在的父目录，不创建替代路径。

## 原生探测隔离（2026-10-25 修复）

真实备份复现确认：带 QQ 包装头和 WAL/SHM 的加密库进入无密钥 `execute_sql` 时，可在 native 的 `walIndexPageRealloc` 崩溃。此类 SIGSEGV 不能由 JS 异常捕获，不代表已确认备份损坏或 NTFS 是唯一原因。

- `backup_probe_core.ts` 先只读检查主库和资料库的固定长度头，只承认偏移 0 或 1024 处完整的 `SQLite format 3\0`。非明文库直接进入 Android 推导/已有密钥/其他设备密钥流程，不用 SQL 猜测格式。
- 原生推导、密钥校验、资料预览和明文消息库校验全部在 `backupProbeWorker.mjs` 中执行。主进程通过既有 `runOwnedChild` 管理短命进程；请求经 stdin 传递，密钥不进入命令行或错误日志。
- 输出上限 64 KiB，默认超时 60 秒；异常退出、信号、无效响应均报告失败，等待进程关闭后才返回。失败项不在主进程回退重试原生查询；批量扫描仍可继续处理其它项。
- 真正打开或重开静态账号前，也先执行隔离预检并核对账号身份；实际会话继续使用原有账号服务，不声称已把所有聊天查询迁到子进程。
- worker 作为 electron-vite 独立入口发出，并通过 `extraResources` 放到 asar 外；Zod 协议校验随共享 chunks 打包，避免依赖 asar 内的 node_modules。

仅隔离修复时的早期回归：`Sunrise/Backups` 在现有 4096 目录限制内找到的六项均返回需要密钥，不再崩溃；列表有截断，不宣称完整扫描全部备份。合成标准明文 SQLite 经真实 native 返回账号预览。后续自动取密钥及 native 根因修复结果见下节。

### 后续 native 根因修复

后续实盘确认：只读挂载会使 SQLite 选择 `nolockIoMethods`，其 I/O 版本仍可为 3，但 `xShmMap` 是 null。旧 offset VFS 无条件公布自己的 WAL 回调，再对底层空回调 `unwrap_unchecked()`，才是此次 SIGSEGV 的直接原因。

`nt_helper` 的 `offset_vfs.rs` 现按每个已打开文件的底层版本和非空回调构造方法表，不再伪造共享内存/mmap 能力；可选转发也有缺失保护。只读且确实不支持共享内存的连接通过 SQLite 的 exclusive/heap WAL index 读取待合并帧；没有设置 immutable、删除 SHM/WAL 或执行 checkpoint。正常支持共享内存的连接及写连接不改变锁模式。

本机 macOS 开发组件已离线构建并更新，正式 pin 和上游发布未改变；Windows/Linux 二进制尚未重建。直接重放旧的无密钥查询已返回普通错误而非异常退出。native 回归覆盖 v1/v2 能力边界及明文、密文的 pending WAL 读取，并核对合成源库/WAL 字节不变。

进一步实盘已使用同账号已有配置，自动取得三份历史备份的其他设备密钥并识别账号；其中一份还实际打开静态会话，读取自身资料、消息，并从备份媒体树解析和读取本地文件。其它无匹配配置或未在线的账号保持手动密钥入口。本轮没有保存聊天正文、账号密钥或修改备份原件。

## 验证范围

### 旧备份页面查询兼容补充（2026-10-25）

账号识别成功不能视为全部页面可用。真实 2023 年备份还缺少群成员头衔/等级列、群资料的退群标记及部分可选表。群成员查询按实际列投影缺失的可选字段为 NULL；群资料不能把不存在的 `60340` 当作 SQLite 双引号字符串读回，误报退群。旧群目录缺少的通知/命名状态列同样显式投影 NULL。

群精华、等级定义、扩展资料、删除会话和在线状态先检查可选表是否存在；文件查找分别判断 v1/v2 表。只有确认缺表才返回空结果，存在的表发生查询错误或损坏仍向上报告，不能用宽泛 catch 吞掉。

补充实盘验证覆盖最近会话、私聊/群聊近期消息、135 个群目录、群成员、文件列表及缺失可选表。该备份的群消息完整年份扫描仍报 `database disk image is malformed`，执行计划为全表扫描，显式 `NOT INDEXED` 也失败；这项未修复，不能据此声称全库健康或所有消息可读。验证未改写备份、启用宽容或自动修复。

### 旧图片串图修正

旧版图片元素可能只有 `md5Bytes` 而没有 `fileName`。渲染层已经能将 MD5 字节转为 hex，但协议的本地文件查找未使用该哈希，空文件名通过 `includes('')` 匹配了目录第一项，导致不同消息同时显示无关的原图/缩略图。

`FileSearchService.findFile` 的图片/表情查询现在接受可选 MD5，合法完整哈希优先于显示文件名；没有任何身份时直接 miss。文件匹配只接受完整文件名/主干或主干后的数字变体，不再使用任意子串。协议透传 MD5，时间线图片 URL 增加定位版本参数，避免继续命中旧错图缓存。缩略图和原图选择规则保留。

真实问题窗口的 13 个图片元素在修正前均选中相同文件，修正后不再选错。所查 NT 月目录内未找到这些目标哈希，故不宣称已经恢复其图片。旧版 `Image` 目录的只读有界检查发现部分其它消息对应的文件，但检查有截断，不能断言备份完全缺少目标图片，也没有在本次请求链增加全盘扫描。

新增测试覆盖分层/递归、混合新旧导出、一次性递归授权、链接循环、截断、原生弹窗位置隔离与取消、三端目录布局、媒体映射、已有密钥/会话复用、必要提权回退、完全离线和错误账号拒绝。相关导出、备份与平台路径测试一并回归。
