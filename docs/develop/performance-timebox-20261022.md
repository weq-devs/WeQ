# 本版限时性能优化（2026-10-22）

按用户 22:13（北京时间）的最新要求，外观停止扩展，随后用半小时处理本版性能热点；更深入优化留到下版本。
性能窗口从 22:18 左右开始，截止 22:48。本轮不改正在并行开发的 MainView／Remote／Web，不接触真实 QQ 数据。

## 已实施

- 会话排序每轮预计算置顶与活动时间，再比较缓存键；复用现有排序口径，不缓存跨轮次对象。
  已读回置顶优先级、草稿／消息时间、无效时间、同时间 ID 顺序、重复 ID 行与输入不变性保持。
- 联系人默认空分组使用稳定引用，选择 ID 按分组快照记忆；仅切活动项不再重新扫描全量联系人。
  新联系人快照仍重新归类，未引入依赖、隐藏条目或降低数量上限。

## 验证

先在原实现复现：2000 条会话排序读取时间键 36314 次；稳定联系人切换还会重复读取分组与 ID。
优化后组件回归要求时间键读取不超过 2100 次，稳定联系人切换的分组／ID 读取为零。

Node v26.11.1 合成排序基准，预热后 7 次中位数，输出顺序与原算法逐项相等：

| 输入 | 原计算 | 优化后 |
| --- | --- | --- |
| 2000 条乱序 | 8.53 ms | 0.73 ms |
| 10000 条乱序 | 82.03 ms | 8.23 ms |
| 30000 条乱序 | 236.49 ms | 16.43 ms |
| 10000 条已排序 | 5.70 ms | 3.42 ms |
| 10000 条近乎有序 | 5.93 ms | 3.33 ms |

同时检查有序／近乎有序输入，避免仅用最有利的乱序数据。10000 条乱序的时间解析从 462212 次降至 20000 次。
以上是特定计算基准，受本机后台负载影响，不代表整应用、数据库请求或帧率有同等倍数提升。

真实浏览器通过 Vite 只读载入提交 `0d45a8a4` 的旧组件，与当前组件对照，未回退工作树：

- 5000 条会话：桌面时间键读取 86006→5044，窄屏 86000→5041；DOM 仍为 24／21 行，顺序与点击目标一致。
- 5000 名联系人：稳定切换时重复分组／ID 读取 5000／5000→0／0；10 次同步更新平均桌面 1.13→0.25 ms，窄屏 1.49→0.38 ms。
- 1280 浅色、390 深色，共 8 个新旧／会话／联系人场景通过，无页面异常。数据与 RPC 均为合成或隔离返回。

桌面端 9 文件 47 项及 service 排序口径 10 项测试通过，desktop node／web 类型检查与 3 个本轮代码文件 Biome 通过。
