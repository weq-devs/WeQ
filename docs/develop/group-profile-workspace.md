# 群资料页与成员预览

快速群名片和完整资料由 `groupProfile` 下的统一组件承接；`GroupProfileDialog` 保留为现有入口适配。联系人与群共用 `ProfileWorkspace` 的响应式目录、已访问章节保留、滚动位置和 `TabActivity`，各自提供内容，不共享展示设置。

## 与联系人共用同一套基座（2026-11-12 收口）

群侧不另起基础框架，全部直接复用联系人侧的共享实现，只提供群特有内容：

| 关注点 | 共用来源 | 群侧用法 |
| --- | --- | --- |
| 名片外壳 | `.weq-member-pop` + `.weq-contact-card` | `GroupProfileSurface` 的快速名片同时挂 `weq-group-card` 变体，宽度/圆角/内距/渐变继承，不自建 |
| 数据行 | `components/contactProfile/ContactRow.tsx` | 群事实行、详细资料 7 行、扩展资料、标签来源全部用 `ContactRow`；仓库里不再有群专用 `<dl>` 行模型 |
| 技术详情 | `ContactTechnicalDetails` | 冻结原因代码、头像编号/版本、排序指标 |
| 局部失败 | `ContactInlineError` | 群资料读取失败、成员预览失败都用「一行 status + 文字重试」 |
| 空态 | `ContactEmptyState` | 扩展资料等章节的空态 |
| 目录/章节标题/正文宽度 | `ProfileWorkspace` + `profile-workspace.css` | 群只传 10 个章节；标题与 `max-width: 720px` 由容器输出 |

`styles/group-card.css` 只保留群特有样式：身份区排版、群标签 chip、成员预览（八位；窄屏两行四位，热区 ≥44）、简介三行折叠、页头与页内操作行；禁止再定义卡片底、行、目录。

群资料页页头目前由 `GroupProfileSurface` 渲染占位结构（「群资料」+ 关闭，位于文档流、不再绝对定位压住标题），等共用 `ProfilePageHeader` 契约落地后替换。

## 数据与加载

- `useGroupReadScope` 仅读账号配置，不为查看资料创建写操作轮询；缓存键包含账号配置及目标群。
- 名片先显示传入对象，本地群资料用于补全；名称不由云端覆盖会话缓存。只读指标快照中的成功值可显示好友数或已知异常状态，不因开卡计算指标。
- `account.groupMemberPreview` 要求当前账号与配置 ID，在读取后再次检查来源。服务端先取最多 32 位本地候选，与当前已知好友关系排序去重后选最多八位。
- 缺少成员时可复用现有完整名单缓存，仍不足且在线能力可用时调用 `FetchGroupMemberListPage` 一次，不追 token、不调用完整名单刷新方法。协议没有八人请求参数，响应是服务端的一页，只有显示结果截到八位。
- 预览缓存按会话服务实例、群与在线可用性隔离，60 秒有效，并发请求合并，最多保留 200 项。失败保留已有成员，不缓存失败结果；预览从不写完整名单或投影好友总数。
- 公告、相册、文件、精华、打卡支持页内宿主和原有独立浮层，复用同一内容逻辑。完整扩展资料只在详细资料章节读取，保留原有服务端缓存和请求合并。
- 章节使用 `TabActivity` 暂停读取，资料历史的迁移状态轮询也随章节停止。公告草稿、文件操作及相册上传向所属资料页注册离开状态。

## 导航与兼容

群资料导航目标增加 `section`、`albumId`、`folderId`、`fileId`，旧调用默认概览。资料页独立持有目标，不依赖当前聊天群。原消息、相册、文件等直达浮层仍可使用原调用形式。

本地生成群只提供适用的本地分区，不向真实 QQ 群查询。缺少明确入群证据时保持未知，不依据成员预览或目录缺项判断退群。
