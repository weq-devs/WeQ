# 统一 SSO 历史读取

日期：2026-10-17（北京时间）。用户同意去掉独立 `sso500` 选项和聚合层，将必要的数据完整性改进整合进单一 SSO 路径。不是新增服务器大页命令，不继续协议逆向。

## 当前路径

- 新任务统一记录 `transport=sso`。界面没有通道选择器、不宣传 500 条页；RPC 只接受新 `sso` 值。普通缺口读取、导出补全与批量任务共用 `GapHistoryService.fetch`。
- 每次调用只派发最多一个、跨度不超过 30 个 seq 的物理请求，使用现有群聊/私聊命令与上游签名修复。`sso_history_window.ts` 为产品共享的单窗解码/核验函数，不含研究采集入口、请求循环、聚合数组或聚合页游标。
- 批量任务管理器负责选择下一小窗、共享 FIFO/冷却、预算和断点。真正派发前，传输调用预约回调；计数和在途窗口先持久化，保存失败不派发。缓存命中和队列等待不算网络请求，时长只统计传输部分，不混入解析与落盘。
- 每个响应完整核对账号、会话、NT 序号、精确 ID 和范围；保留原始 protobuf，分别保存 newId/原始 msgId 与 random。同 seq 不同 ID 全部保留，不能按 seq 覆盖。
- 有合法群号/序号但缺少身份的不完整群观察，独立写入现有观察表，不作为正常消息、导出消息或恢复覆盖。错误身份仍拒绝，不凭形状判定撤回/删除。
- 全窗核验并完成缓存写入后才返回成功；写盘失败不再 best-effort 假成功。批量任务仅扣除可信观察的覆盖，按实际检查边界推进；短页/空页不证明缺口已恢复。
- 在途取消仍保存有效响应，不发下一窗；未确认失败保留预约和在途窗口。普通界面离线可读既有缓存，部分缓存伴随网络错误时保留原有明确错误提示。

## 旧任务与缓存

- 旧 `sso30` 或未写 transport 的任务保持原选项、hash、请求计数和待检查区间，可继续原有小窗调度；执行时使用统一核验与保存实现，不迁移任务文件配方。
- 旧 `sso500` 任务可查看、取消、移除，但禁止继续/重试；明确提示创建新 SSO 任务。旧 `native500` 仍遵循 SDK 删除决定，不能续作。不会自动修改原 options hash 或清除未确认的在途窗口。
- 旧 `gap_msg`、`protocol_gap_msg`、`protocol_gap_observation`、`native_gap_msg` 都不删除、不搬库；旧协议缓存继续参与时间线与导出。没有原始字节的旧行不伪造补齐。
- 新界面通过 `historyVersion=2` 识别新后端，旧后端显示重启提示并禁用创建，防止新旧参数契约混用。移除此前聚合通道专用的能力导出门禁，不代表旧 native 自动获得压缩支持；组件仍按上游 pin 更新。
- 研究源码、脚本、研究专用测试和原始研究记录已整体撤到仓库外，不再随本仓库保存或分发；产品测试与单窗读取实现保留。旧原件和统计回执不改写。
