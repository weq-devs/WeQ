# 页面自动更新（2026-10-21）

## 范围

在群待办、公告、打卡、加群设置、收藏表情与申请列表的第一阶段基础上，迁移了其余
常驻刷新入口：空间、群相册与空间相册、邮箱、收藏、生成对话导出、搜索结果、QQ
资料和会话设置、凭据、容错账本、修复状态、后台服务、版本信息及本地账号工具。
漫游任务、用量和助手附件回执的既有轮询也遵循页面活动状态。

不自动执行扫描、获取密钥、登录账号、修复、保存、发送或删除。模型的「换一批」和
报告重新计算仍是用户主动命令，不把它们当成普通列表刷新。

## 读取边界

- `useQQReadActivity` 合并窗口恢复、可见性与联网变化，并继承 `RetainedTabs` 的
  活动状态。连续的可见性／焦点事件合并；没有为自动更新增加轮询。
- React Query 页面复用 `useQQAutoRefresh`，进入和前台恢复时更新，失败最多重试
  两次。原有状态轮询仅在页面可见且可用时保留；隐藏不暂停后端已经启动的业务任务。
- 手写异步页面复用 `readWithRetry` 与各自的 `AbortController`／请求序号，取消等待
  和后续尝试。已下发且无法取消的读取可以自然结束，但不得回填到已关闭或更换来源的页面。
- 重试包装只用于幂等读取，不包装写入、连接或认证操作。失败时显示的「重试读取」
  不等同于重发上一次保存、发送或扫描。
- 本地账号工具、数据库表格和收藏本地缓存不以联网作为读取前提。收藏的网络补充
  另受联网状态控制，恢复联网后校准，失败不以旧本地摘要覆盖已显示的云端内容。

## 状态保护

- 群设置、收藏备注与邮件草稿不因自动读取重建；QQ 资料继续沿用既有草稿保护。
- 表格的单元格编辑、新增行、保存和 BLOB 查看期间延后自动校准，结束后补读。
  换数据库或表时清掉旧结果，取消旧读序列，不按旧行位置套用新内容。
- 空间恢复只触发一轮说说读取；媒体预览保留原对象与顺序。搜索结果在列表头部恢复时
  校准，翻页现场继续保留原游标、滚动与返回焦点，查询失败仍有单独重试入口。
- 本地账号概况读取不清掉扫描结果，不触发扫描或修改登录物料。
