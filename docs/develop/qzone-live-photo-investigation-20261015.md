# Live Photo 分类证据

## 当前接入（2026-11-12）

说说及好友动态的可见视频媒体已增加 V4 详情类型补全，Web 列表与分页不变。命令为 `QzoneV4Service.trpc.qzone.feeds_reader.FeedsReader.GetFeedDetail`，复用现有原生 SSO 发包及中央签名策略；当前真实验证平台为 macOS QQ，会话不可用时不影响 Web 内容。

请求采用 QWeb 包装（业务体 tag 4、`fc-appid=101`），将作者、appid=311、发布时间和说说 ID 写入 CommonUnionID 的已核扩展项。响应必须匹配作者、业务及说说 ID，再沿 `QWeb.body@4 → detail@2 → feed@1 → media@5 → items@1` 解出媒体 `isLivePhoto@18`。普通视频与实况都可能是 `type=1`，缺失标记不补成 false；关联只使用精确视频 ID，重复冲突保留未知。

协议实现为 `packages/protocol/src/qzone/feed-media-detail.ts`；服务在 `account/qzone_media_types.ts` 中保留五分钟、最多 128 帖的账号实例缓存及在途去重，最多两条原生查询并行，失败冷却 30 秒。界面接近视口才调用 `account.qzone.mediaTypes`，隐藏、暂停或卸载后不接收迟到结果；纯图片与无定位信息的内容不发补全请求。

实测通过已知普通视频的显式 false、12 张实况全部为 true，以及缓存去重；另发现 Web 顶层 `video[]` 同样可能是实况。原历史三项混合帖、可靠短普通视频负样本和图片文件级配对仍未补齐；这次不接相册独立分类、原件合成或修改导出文件形式。

同日交互修正：Web `pic[]` 与好友动态 HTML 投影保留视频的 `mediaIndex`，网格和预览按同一顺序混排；未知类型先展示封面，补全失败恢复通用视频入口。实况按钮独立于照片预览按钮，缩略图内显式调用 `play()`、静音循环，失败保留封面并允许重试，离开页面、打开预览或卸载时暂停。预览通过文档捕获阶段处理最上层 Esc，避免原生视频控制条截断冒泡。视频与封面地址统一规范化，流式代理保留分段响应并移除逐跳头。

播放核验使用既有 12 张已知实况帖：12 段 CDN 文件均为有效 H.264/AAC MP4；其中一段通过浏览器和独立 Electron 自定义媒体协议实际播放，开发运行时及播放器焦点下 Esc 也已验证。但同一样本在旧代理下亦可播放，故不能据此认定用户报告的“实况实际无法播放”已复现或已定位根因；逐跳头处理和地址规范化只作为已覆盖的兼容性修正，具体失败帖仍需进一步核对。

## 历史 Web 调查（2026-10-15）

结论：2026-10-15 的已知样本能区分静态媒体与携带视频的媒体，**不能可靠区分普通视频和 Live Photo**。没有新增自动 Live Photo 分类。

## 反例

最初一个纯视频帖使用顶层 `video[]`，另一个已知 Live Photo 帖使用 `pic[].is_video=1/video_info`。但随后明确标注“普通视频、Live Photo、静态照片”的混合帖中，前两项均进入 `pic[]`，两者的字段集合相同，`videototal=0`。因此不能把 `pic[]`、`videototal`、封面配视频或 `pic_id` 的有无当分类规则。

对该混合帖的其它读取结果：

| 配方 | 有效观察 | 不能推出的结论 |
| --- | --- | --- |
| R01/R02 | 两种动态项都含 `is_video/video_info` | 普通视频与 Live Photo 有不同已验证类型标记 |
| R04 | 附图封套使用 `result.code`，返回静态图定位 | 顶层 `code` 足以判断所有接口成功 |
| R13/R14 | 精确帖身份出现在主页元数据与 HTML 中 | popup topic 一定是相册 ID |
| R15 → R21 → R22 | 由真实相册和照片键，经精确 vid 将两种动态项分别绑定 | 数组顺序或相似封面可替代身份绑定 |
| R22 | 两者均为 `phototype=1`、`is_video=true`、`video_type=0`，还返回下载/尺寸信息 | 时长、格式、大小或下载 URL 是语义类型 |
| R27 | 两种动态项均在独立视频列表中 | 视频模块收录即可排除 Live Photo |

R03 与移动端 B02 在该次读取失败，不证明端点永久不可用。R13 的空字符串业务码也不能写成数值 `code=0`。

## 后续依据

分类需要经已知普通视频/Live Photo 对照验证的官方类型字段或明确配对协议；不能硬编码样本身份、位置、时长或文件名。上述证据仅覆盖当时的 Web 变体，不声称所有 QQ 接口都缺乏类型。
