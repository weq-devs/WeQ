# 未读补算短任务化（2026-11-05）

## 范围

针对已定位的 `UnreadInfoDb.loadOutgoingSequences` 队列占用问题，先实施最小方案的第一批：缩短单条统计 SQL、让完整补算以后台优先级执行、接入取消。不拆 UI、不改轮询周期、不增加连接/索引/依赖、不改版本号，也没有改变未读计数口径。

核心实现只涉及 `packages/db/src/msg/unread_info.ts`、`packages/service/src/account/unread_info.ts` 及两个已有导出文件，约百行实现改动；测试和文档另计。

## 实现

- 已有水位批量读取保留。群聊与有 sortNo 的私聊改为单会话轻量分页，每页最多交付 `UNREAD_OUTGOING_PAGE_SIZE`（512）行，只读 rowid、序号和 SQL 计算的自己发言标记，不读正文。
- 发送者条件仍由 SQL `CASE WHEN` 判断，保留原 UID/UIN、NULL 与转换语义。限制发生在自己发言过滤之前，因此零条自己发言也不会变成一条跨大量未读区间的查询。
- 分页结果在会话完整读完后才写入 `outgoingSeqs`；使用 Set 去重，固定本次 read/latest 上下界。失败或取消不作为零未读返回。
- 普通页按序号范围读取。满页后先以“同 seq + rowid 大于游标”续读尾段，再前进到下一序号范围，避免同序号多行漏读或反复从该序号起点扫描。
- 合成 SQLite 的计划确认排序索引；同序号续读额外核对三字段索引键的 SeekGT，覆盖 64 位 rowid。它不是原库的 EXPLAIN。
- 无分区索引保证的私聊 UID 回退保留原单次查询，避免逐页重新扫描；这条次要路径没有在本轮新增索引或重写。
- 服务层完整补算使用既有 `withDatabasePriority('background', ...)`；轻量水位仍走原通道。分页逐页提交，复用现有同库调度和批间让出，不并发堆积查询。
- 服务生命周期 AbortController 与调用方信号合并；账号关闭取消排队工作，已开始的原生查询仍需结束，但之后不再启动下一页。关闭后的新读取保留 `readError` 约定，不伪造零条计数。

## 代价与结果缓存的决定

短任务显著增加 SQL 往返次数；本轮观测到的统计原生等待总量约 25.25 秒与 25.37 秒，未明显下降。这里的历史采样有界，不能将这两个数当作完整 CPU 总量，但足以说明不能声称已减少全部统计工作量。

因此本轮交付的收益是首屏不再被一条长统计 SQL 挡住，不承诺 CPU 节省。没有加入第二批结果缓存：虽然水位重复率高，真实未知 DB 变更下可安全复用的比例和失效接线尚未验证。为保持最小改动与计数准确性，后续另做有界结果复用，而非直接按水位或 TTL 认定内容未变。

## 回归与生效

专项覆盖：零条自己发言的大未读区间、同 seq 跨页、64 位 rowid、UID/UIN 与 NULL 判定、边界/跨群隔离、新尾页不越过冻结水位、失败/取消不交付部分结果，以及同绑定首屏在统计页间执行；原有水位、手动未读、撤销、持久化与已读上报继续回归。

只运行相关包专项测试、类型检查与改动文件 Biome，不运行全仓 CI。真实读取与单测分开，单测只用合成数据与明文 SQLite，不连接 QQ 或外网。后端改动需重新编译并重启 WeQ；安装版需后续包含该提交的构建，无需重启 QQ。
