# 原窗口现场恢复（2026-10-28）

## 恢复流程

沿用主进程 `render-process-gone` 与 `webContents.reload()`，保留同一个
BrowserWindow 和 WebContents，不退出主进程，不重新建立账号服务。
`SIGTRAP / exitCode=5` 这样的 renderer 原生终止由仍存活的主进程处理，
不通过 JavaScript 异常捕获来继续运行已经终止的进程。

桌面与 Web 首屏都先读取 `bootstrap.currentAccount`。有后台账号时直接接回，
桌面补充账号配置及既有查询预热；不调用验密钥、打开账号或自动进入目标。
没有后台账号时才走既有启动流程。启动探测不先设置首页窗口布局，
主进程按窗口记录已经应用的布局，相同布局重复请求不重置用户尺寸与位置。

主栏目、联系人通知页、会话分区、设置及装扮页开关复用账号/配置 ID 隔离的
`usePageState`。设置没有显式跳转目标时恢复已有分类，不覆盖成外观页。
其余页面继续使用已有显式登记的页面快照与滚动现场。目录尚未读齐时不清除
已恢复的会话选择，包括分页较后的会话、隐藏和删除会话。

聊天单独保存当前会话的稳定消息锚点、已核实的本地序号和相对像素偏移，
不保存消息正文窗口或媒体。滚动时至多每 150 ms 写入一次，挂载后也捕获初始位置，
不依赖崩溃时还能执行卸载回调。恢复历史位置时走既有 `loadConversationEntry`，
先读锚点前的上下文再补其后一页，即使未开启「从未读处阅读」也可恢复。
底部位置仍跟随最新消息；私聊漫游序号未经本地核实，不用作数据库游标。
已有正文及 IndexedDB 素材恢复保持不变，不回放发送、删除等提交动作。

## 就绪与失败

`did-finish-load` 不再单独判定本次恢复成功。账号来源、目标会话和首个消息窗口
就绪后，通过原有 preload 恢复 IPC 静默确认；恢复成功不再显示错误横幅。
账号工作区加载前保留既有载入过渡，不先显示主页再切回。
这里只等待工作区和首个消息窗口，不等待所有图片、后台分页或远程网页加载。

加载与工作区恢复合计最多等待 30 秒，超时/加载失败仍由主进程原生入口处理。
首次常见异常退出后延迟 1 秒自动恢复、10 分钟冷却和连续失败转手动的策略不变。
这些规则更新了 [10 月 27 日记录](./renderer-auto-recovery-20261027.md) 中
15 秒文档加载超时及恢复成功错误横幅的旧行为。

## 验证

11 个定向测试文件共 83 项通过：覆盖后台账号接回、无后台账号时原启动流程、
来源隔离、栏目/联系人及设置分类恢复、历史锚点、底部跟随、漫游序号反例、
窗口几何、文档加载完成但工作区未就绪、失败超时与原有草稿/页面快照行为。
本次修改文件的 Biome 检查、桌面主进程与渲染端 TypeScript 检查通过。

隔离 Electron 44.9.1 使用实际恢复状态机、IPC/preload、页面快照、主导航控制器、
阅读锚点 hook 和就绪组件，合成消息及独立 profile。对测试 renderer 注入
`SIGTRAP`，实际事件为 `crashed / exitCode=5`，自动恢复后：

- 主进程 PID 26687 保持，renderer PID 26706 → 26727。
- Window ID 与 WebContents ID 均保持 1，窗口总数保持 1。
- 原窗口坐标 `(135,125)`、尺寸 `1300×850` 不变。
- 原消息栏目、未发送合成草稿与滚动位置 `1377` 恢复，无手动对话框。
- 切换工具页再普通重载，仍回到工具页；浅/深截图均非空。

本次注入验证恢复链路，不复现 PartitionAlloc 分配耗尽，也不作为内存增长根因
已修复的证明。没有重载日常实例或访问真实 QQ 数据库。测试实例已关闭，独立
profile 与生成的 bundle 已清理；测试源码、截图及结果保存在本机 WeQ 项目
`work/renderer-inplace-recovery-20261028/`。
