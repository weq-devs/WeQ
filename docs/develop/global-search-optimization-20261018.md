# 全局搜索排序、默认范围与性能后续

## 本轮已实施

- 默认对象范围由原先的会话、好友、群友统一为联系人、群聊，分别合并通讯录与会话，其它内容范围保持原有设置。消息包括收发双方，不等于只搜索本人发送内容。
- 对象查询使用 `contact` / `group` 类别。联系人合并好友名册、资料缓存、私聊与临时会话、群成员及历史成员、删除会话；群聊合并群名册、群资料、现有与删除会话。本地身份先合并，再排序与分页，预览与更多共用同一路径。同 QQ 号跨来源与旧 UID 合并，缺少号码时以 UID 保留独立身份；群按群号合并。资料缓存与删除会话不充当关系状态证明，群名片来源保留真实群号。旧 `conversation` / `friend` / `groupMember` 查询接口仍兼容，默认 UI 不再显示三个独立范围。
- 可见范围固定为：功能与设置、联系人、群聊、消息、文件、群相册、收藏、空间、邮件、助手会话，默认全选；分类选择与功能开关保存到本地，重启后恢复。移除独立的频道私聊、克隆消息、商城表情范围，底层旧类别接口仍兼容。
- 联系人与群聊通过消息列表的显示范围决定是否纳入克隆体及克隆群；频道联系人并入联系人。原聊天记录改名为消息，合并真实消息、克隆消息及频道私聊消息。`all` 包含三类来源，`real` 仅真实，`virtual` 仅克隆，`guild` 仅频道；预览和更多分页均传递 `conversationScope`，切换范围立即隔离旧响应与返回现场。此范围只约束联系人、群聊、消息，不改变文件等其它分类。
- 消息列表在仅频道私聊视图直接显示一级会话，其它视图保留聚合入口；平铺行与聚合面板共用会话转换函数，选择后仍定位频道私聊。
- 空间统一为一个范围，包含个人与他人的说说和相册。底层保留 `qzonePost` / `qzoneAlbum`、`otherQzonePost` / `otherQzoneAlbum` 来源，不删除已有观察缓存，不联网扩充覆盖；点击仍按原有 target 定位。
- 联系人、群聊在合并来源和身份去重后按名称、备注、号码和名片的统一匹配度排序，同分使用稳定身份；匹配 SQL 中的 `%`、`_` 与反斜杠按字面量处理。旧分类接口保留原有排序口径。
- 聊天记录候选池优先会话名相关度，再按命中数；文件候选池优先文件名相关度，再按时间。缓存内容优先标题相关度，再按原始时间、观察时间和身份。
- 范围按钮保持上述固定顺序；下拉结果分组（包括功能与设置）先将有结果者放前面，再按各分类最佳结果的匹配度降序，同分按分类顺序。空结果、加载和失败分类不会挡住已有结果，三者之间按分类顺序排列。
- 匹配度统一为完整相等、连续命中、有序断开命中、不匹配四层；层级优先于长度，连续命中越短越靠前，同长度时出现位置越早越靠前；断开命中使用最紧完整窗口，再考虑长度。文本先做 NFKC、大小写与空白归一化，按 Unicode 字符计数；名称、备注和别名取最佳匹配，不累加重复别名刷分。此算法对已取得的候选排序，不代表 SQL 检索已经支持全库模糊召回。
- 每个勾选分类独立请求并同时发出，保留 200ms 防抖，独立维护结果、加载和失败状态；旧关键词、范围、账号或重试代次的响应不能回填。Web 的快速与慢速搜索不走 HTTP 批处理，避免最慢分类阻塞整个批次；其它 Web 请求继续批处理。

消息中的真实会话和文件仍使用既有有界候选池，本轮未扩大扫描范围，不把候选池排名冒称全库最相关结果。频道先按联系人名称相关度、再按时间排序，与合并消息排名保持一致，避免前缀分页重排；生成对话、收藏与商城的内部排序保持原有规则。

## 功能目录维护（2026-10-29）

功能与设置目录来自 `appSearchCatalog.ts`、`settings/navigation.ts` 和 AI 设置公开目录。设置分区自动收录，具体控件通过 `SETTINGS_ITEM_TARGETS` 或 `SETTING_ITEMS` 补充；改名保留旧称为别名，桌面专属项标记 `desktopOnly`。`settingId` 应与真实控件对应；没有稳定标记时按真实标签定位，不能填写页面里不存在的控件名称。

- 克隆列表已并入消息目录，搜索目标使用 `conversation-directory` 并指定 `virtual`，清空列表筛选与旧详情，不再指向隐藏侧栏的旧 AgentLab 首页。新建克隆复用已有创建入口。
- 导出子功能携带 `exportMode`，打开对应种类且不沿用当前内容的固定选区；漫游入口以可选择会话的方式打开。搜索导航本身不提交任务。
- 频道私聊有独立展开请求，关闭后重复点击仍会展开；装扮子功能携带真实 `DressKind`，不能用主页别名代替页签定位。
- QQ 资料、状态、SSE 推送地址等搜索定位到其设置分区或所属卡片。服务商编辑框、单个克隆的生成参数等需要先选择具体对象的内容，不伪装成可独立打开的全局设置项。

针对性检查：`settings_catalog.test.ts` 验证名称、目标和 Web 过滤，`app_search_settings_coverage.test.ts` 从实际设置行提取名称检查漏项，`app_search_navigation.test.ts` 执行实际导航处理器，`tool_search_navigation.test.ts` 验证工具宿主收到的导出种类和漫游选择模式，`channel_search_navigation.test.ts` 验证重复展开；`feature_search_ui.test.ts` 保留搜索选择和定位行为检查。新增设置页时同步扩充实际控件覆盖范围，不能仅以“每个分区都出现”证明具体项完整。

## 已定位的风险（尚未修复）

1. `packages/db/src/msg/search_index.ts` 的 `fullRebuild()` 直接同步调用原生解密。上层即使使用 `void ensureIndexes()`，仍会阻塞 Electron 主线程；大库还涉及峰值内存与磁盘空间。
2. `UnifiedSearchService.slowSearch()` 启动索引后立刻查询；索引未就绪时回退原库 LIKE，可能同时发生解密、建索引、聊天聚合与文件扫描。
3. 小于三个字符的关键词不走 trigram；单/双字中文会回退扫描。现有 `LIMIT 200000` 限制的是匹配行数，不限制为找匹配而读取的行数，冷门词仍可能扫完整库。
4. `useGlobalSearch` 仅有 200ms 防抖和响应隔离，不会中止已经派发的服务端工作。连续输入可堆积多个慢查询。
5. 消息排名缓存仅缓存完成值，不合并同关键词的在途读取；缓存 Map 也没有关键词数量上限。
6. 聊天私聊身份逐条回查、文件逐条查询会话名，存在重复 SQL；已有批量 `getByTargetUids`、`nicksByUids`、`detailsByGroupCodes` 可复用。
7. 频道私聊每个新关键词逐页读取和解码全历史，再累计所有命中；合并的消息分类仍需等待频道完成，但已不阻塞文件、收藏等其它分类。大库耗时及命中池内存都需处理。
8. 多种观察缓存每次查询会反复拼接并小写全文；生成对话也会遍历正文。本轮默认范围调整降低部分工作量，不等于解决卡死。
