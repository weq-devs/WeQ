# 全局搜索排序、默认范围与性能后续

## 本轮已实施

- 默认范围：会话、好友、群友、聊天记录、聊天文件、收藏、个人空间、他人空间、群相册、群文件、邮件、频道私聊。消息包括收发双方，群资料包括本账号参与的会话，不等于只搜索本人发送内容。
- 手动可选：克隆消息、助手对话、商城表情。公共商城目录和生成内容不再默认扫描，显式全选仍可查。
- 空间按当前账号 uin 分成个人与他人两个范围选项，默认都选中，每个选项包含说说与相册。底层保留 `qzonePost` / `qzoneAlbum` 作为个人来源，新增 `otherQzonePost` / `otherQzoneAlbum` 作为他人来源；按目标作者过滤，不删除已有观察缓存，不联网扩充覆盖。预览、更多与 coverage 的记录数采用同一范围，点击仍按原有 target 定位。
- 会话、好友、群友在 SQL 分页前按名称或号码精确、前缀、包含排序，并增加稳定同分顺序。会话同档按时间；好友与群友保持身份顺序。好友搜索的 `%`、`_` 与反斜杠按字面量匹配。
- 聊天记录候选池优先会话名相关度，再按命中数；文件候选池优先文件名相关度，再按时间。缓存内容优先标题相关度，再按原始时间、观察时间和身份。
- 下拉分组有命中者优先，名称相关度相同时采用常用类别顺序；失败、加载中、空类别依次靠后。

聊天记录和文件仍使用既有有界候选池，本轮未扩大扫描范围，不把候选池排名冒称全库最相关结果。生成对话、频道、收藏与商城的内部排序仍保持原有规则。

## 已定位的风险（尚未修复）

1. `packages/db/src/msg/search_index.ts` 的 `fullRebuild()` 直接同步调用原生解密。上层即使使用 `void ensureIndexes()`，仍会阻塞 Electron 主线程；大库还涉及峰值内存与磁盘空间。
2. `UnifiedSearchService.slowSearch()` 启动索引后立刻查询；索引未就绪时回退原库 LIKE，可能同时发生解密、建索引、聊天聚合与文件扫描。
3. 小于三个字符的关键词不走 trigram；单/双字中文会回退扫描。现有 `LIMIT 200000` 限制的是匹配行数，不限制为找匹配而读取的行数，冷门词仍可能扫完整库。
4. `useGlobalSearch` 仅有 200ms 防抖和响应隔离，不会中止已经派发的服务端工作。连续输入可堆积多个慢查询。
5. 消息排名缓存仅缓存完成值，不合并同关键词的在途读取；缓存 Map 也没有关键词数量上限。
6. 聊天私聊身份逐条回查、文件逐条查询会话名，存在重复 SQL；已有批量 `getByTargetUids`、`nicksByUids`、`detailsByGroupCodes` 可复用。
7. 频道私聊每个新关键词逐页读取和解码全历史，再累计所有命中；普通慢来源又等待频道完成才一起返回。大库耗时及命中池内存都需处理。
8. 多种观察缓存每次查询会反复拼接并小写全文；生成对话也会遍历正文。本轮默认范围调整降低部分工作量，不等于解决卡死。

## 建议实施顺序（TODO）

1. **主线程与构建隔离**：复用 `db_decrypt.ts` 已有的 Worker 解密路径，避免另造原生入口；串行构建两个消息索引控制资源峰值。核实现有异步 SQL 的实际线程行为。先测无索引冷启动、已有索引和构建失败。
2. **查询背压与取消**：每账号最多一个慢查询执行，只保留最新待查询条件；服务端按账号和查询代次取消后续扫描/翻页。中止 UI 请求不冒充已中止原生 SQL，不能取消的单条查询必须另设预算或隔离执行。
3. **索引就绪策略**：构建期间显示状态，避免并行全库回退扫描；完成后自动重查，不把未完成索引显示为零结果。失败保留明确错误与可用回退入口。
4. **短词策略**：保留中文单/双字搜索能力，评估支持短词的索引或可取消分块查询；不能简单要求输入三个字，也不能把扫描上限冒充完整总数。
5. **合并与批量化**：同关键词/来源在途请求 single-flight，缓存限制数量和有效期；批量读取会话身份、复用同一查询内的名称。切号/关闭后清理，禁止回填旧账号。
6. **来源渐进返回**：普通缓存来源先显示，频道等重来源单独返回；频道评估持久文本索引与水位增量更新，保留稳定消息 ID、完整分页、缺源和截断声明。
7. **验收与测量**：使用合成 SQLite 夹具覆盖冷/热索引、短词、无命中、高频词、连续输入、切号与失败；记录首结果时间、总耗时、主线程事件循环延迟、峰值内存和 SQL 次数。不触达真实 QQ 数据的单测先行，大库实测另列结果。
