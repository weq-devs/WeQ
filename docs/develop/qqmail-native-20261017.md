# 原生 QQ 邮箱页面

## 需求与 Issue 草案

用户已明确要求从 dev 新建分支，实现 WeQ 原生 QQ 邮箱页面。范围是复用当前 QQ 登录态，不要求 IMAP 授权码，不用远程网页替代原生页面：文件夹、分页/未读筛选、正文、写信/回复/转发、附件及新邮件提醒。

本地分支：`feat/qq-mail`，基于 `dev` 的 `d3c302ec`。本文同时保存上游新功能 Issue 草案；本轮未获远端发布授权，不自动创建 Issue、推送或提 PR。向上游提交前仍需按 CONTRIBUTING 走 Issue 讨论。

## 实现边界

- `packages/service/src/account/mail/`：账号级 Cookie、ptlogin、邮箱 sid、CGI、附件和提醒，凭据仅存在主进程内存。
- 独立 `mail` IPC 路由：每次请求校验当前账号，切号时取消请求、关闭连接并销毁票据。
- 原生三栏界面：文件夹、邮件列表、正文；独立写信视图，用户动作才触发发送/上传/标记/删除。
- HTML 正文用 DOMPurify 与隔离 iframe，默认阻断远程图片，不暴露 Node 或 IPC 到邮件内容。
- 发信结果区分明确失败与网络中断后的状态未知；不自动重发未知结果。
- 复用已验证的通用 clientkey jump，不能把失败的邮箱 appid jump 当作唯一登录方式。

## 依赖

- `ws`：现有工作区已经使用的 WebSocket 实现，邮箱服务显式声明直接依赖。
- `tough-cookie`：标准域/路径/HttpOnly/过期规则，避免再实现一套不完整的 CookieJar。
- `rusha`：QQ 附件分片需要未 padding 的 SHA1 累计状态，不能用每片独立 SHA1 替换。
- `dompurify`：邮件 HTML 的成熟净化器；iframe 与 CSP 另作纵深保护。

## 验证

纯逻辑、认证假传输、账号生命周期、发送状态、上传和通知均用离线夹具，不联网、不读真 QQ 数据库。UI 检查浅/深主题、主题色、背景和减少动态效果。真实只读验证单独记录；不自动发送测试邮件。提交前运行 `pnpm ci:local`，不以局部测试代替全仓门禁。
