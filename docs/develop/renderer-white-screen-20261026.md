# 白屏排查与恢复补漏（2026-10-26）

## 实际证据

本机日志记录北京时间 2026-10-25 10:26:28、14:45:12 主窗口 renderer 退出，均为 `reason=crashed, exitCode=5`；系统报告落在 Chromium 分配失败路径，不是单纯网络断开。14:45:07 的最后一份开发采样中，主文档有 45,937 个 DOM 节点、2,975 张图片元素，聊天区域虽已隐藏，仍挂载 1,843 条消息和 41,544 个后代元素。受管装扮预热仅保留约 8.4 MiB，不能把全部进程内存归因于该缓存。

这些是旧实例的证据，不证明当前源码仍有相同规模的 DOM 保留，也不能仅凭采样判定唯一 OOM 根因。此前提交已加入长时间线虚拟化，参见 [消息性能优化](./message-performance-20261026.md)。本轮没有重启日常实例或清理用户缓存。

## 本轮修复

- 聊天图片、接收的动画表情和商城表情对 `ShimmerImage` 显式启用离屏挂起。以所属文档的 IntersectionObserver 为准，额外预留 200px；离屏、所属保留标签停用或文档隐藏时移除 `src` / `srcset`，恢复可见后重新挂源。没有 Observer 的环境仍遵守文档可见性。其它调用方默认行为不变，不中断音视频播放。
- 成功加载后保存固有尺寸，移除源时保持图片比例，调用方指定的尺寸优先；挂起期间不显示扫光、不把释放产生的错误事件计作媒体失败。卸载或切换活动状态时断开观察器和文档监听，忽略已清理观察器的迟到回调。
- 根错误边界位于 tRPC、浮层和备份启动 Provider 外，捕获子树 render / effect 异常后显示独立恢复页，不渲染异常原文。只在用户点击后重新加载，不自动重挂子树、重放业务写请求或清配置；提示未保存内容可能丢失、在途操作需要先核对结果。

移除图片源解除当前 DOM 对解码图片的直接使用，不承诺 Chromium 缓存或驻留内存立即归零。错误边界也不能捕获模块导入失败、任意异步回调异常或原生 renderer OOM；原生进程退出仍沿用 [主进程恢复](./renderer-recovery-20261020.md)。

## 验证

- 图片释放回归先在旧实现上失败，再在修复后通过。专项覆盖 StrictMode 清理、离屏和标签 / 文档隐藏、恢复、srcset、显式与未知尺寸、无 Observer 回退及真实媒体错误透传。
- 恢复边界覆盖渲染和 effect 抛错、正常事件、异常原文不进入恢复页、禁止自动重试与手动重新加载。
- 真实浏览器离线夹具验证加载后 200×150 图片在标签隐藏及滚动离屏时移除源，尺寸不变，返回后重载成功；桌面 / 手机宽度、浅 / 深色、四组背景 / 主题色和减少动态效果下恢复页无溢出，浏览器无未处理异常。测试浏览器与 Vite 已关闭，独立 Vite 缓存已清理。
- 六个文件共 15 项专项单测、桌面渲染端 TypeScript 与本轮 11 个源码 / 测试文件的 Biome 检查通过。没有运行全量 CI。
- 既有 3,000 条消息浏览器回归通过：最终只挂载 17 行，保留阅读锚点、前插 / 追加、动态高度、阈值切换、跨窗口选择 / 复制 / 导出、播放行保留与隐藏后恢复。长列表测试也改用独立临时 Vite 缓存，结束后清理，避免与日常开发服务器共用优化器缓存。
- 可重复运行：`node apps/desktop/test/browser/run-renderer-recovery.mjs`；通过 `WEQ_PLAYWRIGHT_IMPORT`、`WEQ_BROWSER_EXECUTABLE` 指定已有 Playwright 和浏览器，`WEQ_RECOVERY_ARTIFACTS` 指定截图输出位置。不访问真实 QQ 数据，不外联网。
