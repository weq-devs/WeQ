# 消息气泡首帧与提前准备

## 目标

已缓存的气泡在消息首次显示时直接生效，不先显示默认气泡，也不通过隐藏正文、等待查询或等待 `Image.decode()` 延迟消息。字体与动画帧独立准备。

## 数据路径

1. `DressSharedCache` 创建后以四路异步读取准备气泡参数和静态九宫格。在线账号与静态账号在创建业务服务前接用这项并行准备；不在消息查询或 React 渲染中扫描磁盘。
2. `message_bubbles.ts` 从内存为首屏、分阶段首屏、双向翻页、漫游消息和合并转发提取本页所需装扮。同款底图每页只携带一次，分阶段复用时保留行身份。
3. 渲染进程收到消息页/预取页即登记并启动可选预热，随后照常发布消息。行上的静态样式通过 `useInsertionEffect` 在布局测量前注入，气泡 ID 从首次提交起就生效。消息不以预解码 Promise 或可见性通知为显示条件。

装扮状态只额外携带本地生效款与 QQ 当前气泡，本地覆盖样式也在布局前注入。发送预览复用同一预热表，命中时不再发起气泡解析查询。

静态底图内联受单张 512 KiB、累计编码字符串 32 MiB 的预算约束；超出时仍携带几何参数并使用现有本地媒体 URL，不阻塞消息。动画帧不随消息页传输，沿用可见时准备、隐藏时释放的共享资源机制。静态气泡不再重复申请完整样式，也不单独建立可见性观察。

## 行高与滚动

气泡样式必须早于虚拟列表的首次测量，不能先测默认气泡再异步改高度。未测行的预挂载估算采用当前实测行高；固定按 96px 计算会高估短气泡，造成实际预挂载距离不足。仍保留最多 48 行的单向预挂载上限，不恢复全量挂载。

## 回归入口

- `cached_bubble_readiness.test.ts`：图片预解码永不完成、可见性回调未到、未缓存与可选预解码失败；断言首个提交中的正文与气泡状态，不只检查最终结果。
- `message_bubbles.test.ts`：200 条同款消息只附带一份静态底图，消息热路径只访问内存，空页与嵌套转发。
- `message_bubble_cache.test.ts`：使用合成缓存文件准备内存；随后移除测试文件，确认读取仍不访问磁盘。
- `run-decoration-readiness.mjs`：宽窄屏、深浅主题、实际截图像素和 48 行批量挂载，字体与图片预解码可以一直不完成。
- `WEQ_SCROLL_CACHED_BUBBLES=1 node apps/desktop/test/browser/run-timeline-scroll.mjs`：真实 ChatPane、3000 条合成消息、双向快速滚动，逐帧检查视口覆盖与气泡回退，并报告帧间隔。沿用测试约定中的 Playwright 和浏览器路径变量。

这些入口不连接 QQ，不读真实聊天记录；并不替代运行安装版后的真实账号观感核验。
