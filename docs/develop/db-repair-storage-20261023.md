# 数据库修复空间优化

## 实现边界

WeQ 的编排改动与 nt_helper 的磁盘流水线改动分别维护。新版 native 导出
`databaseRepairStorageVersion()`，返回 1 表示支持本页的低占用流水线；方法缺失时
WeQ 按旧版预算检查，不能因为前端已更新就假设实际模块也已更新。

原库在最终替换前保留，指纹复核、自检、自动还原和历史回滚不变。不使用原库硬链接
充当备份，不为省空间跳过备份或在开修前淘汰仍在保留范围内的历史备份。

## 文件生命周期

- 重建返回、输入连接关闭后立即删除明文源副本；删除失败则中止，不按低预算继续。
- 加密使用已有 offset VFS。先写源库包装头，SQLCipher 的 attached 输出继承该 VFS，
  密文直接写到原库目录的半成品，仍显式应用 QQ 逻辑页布局。不再生成密文中间库后
  全量复制补头，也不再为读取包装头而载入整个源库。
- 加密结束删除重建明文；半成品落盘同步后 rename 为产物，继续原有自检与服务层替换。
- 半成品名称保留完整的上层产物前缀，便于既有中断产物清理识别；已有同名半成品
  不覆盖。正常错误通过清理守卫删除本次中间件。进程被杀不保证执行析构，不据此
  宣称已经清理历史崩溃留下的所有明文。

## 空间预算

记 `S = 主库大小 + WAL 大小`，备份预算 `B` 为 `S`（显式跳过备份时为 0）。
不假设重建后一定缩小，也不预支 CoW 克隆的物理节省。

| 阶段 | 新版缓存目录 | 原库目录新增量 |
| --- | --- | --- |
| 重建 | B + 2S | WAL 增长 |
| 直接加密 | B + S | S + WAL 增长 |
| 提交／回滚 | B | S + WAL 增长 |

旧 native 加密阶段按缓存 `B + 3S` 估算，提交时仍计入密文中间件。
按本次实际探测的文件系统身份合并同卷，逐阶段求和后取峰值；不同卷分别判断。
未创建的缓存子目录只读探测最近现有父目录；卷身份未知时按可能共卷的较高预算，
可用量未知如实展示，不伪称已确认空间充足。每卷的 `requiredBytes` 仅表示预计新增
峰值，`recommendedBytes` 再加 25% 余量和 64 MiB，两项分别展示。
恢复表、索引排序、文件系统共享池及异常膨胀可能超过估算，不是磁盘硬上界。

可用量低于任一卷的预计峰值时返回 `insufficient-space`，不允许覆盖。只有建议
余量不足时，面板仍允许打开修复确认，勾选接受风险后发送可选
`allowLowSpace: true`；未确认时服务返回 `space-margin`，不备份、不修改原库。
服务在实际开始前重新计算所有卷，先检查硬门槛再检查余量，防止强制标记绕过另一
卷不足。该标记不传给 native，不关闭备份、原库指纹复核或自检，开始日志记下
是否确认继续。确认不会跨取消重开、切库或缓存位置变更沿用。

在重建前，低占用版的同卷理论新增峰值约 3S，旧版约 4S；19 GB 级原库理论上
减少约一份库的并存占用。含余量的建议预留值与这个理论峰值分开，不以逻辑
文件大小、CoW 共享块或同时期系统后台变化冒称实际释放空间。

## 缓存与备份

`UserConfig.dbRepairCacheDir` 为可选路径，由桌面原生目录选择器设置，运行中禁止
更改（选择器返回时再次复核）。自定义位置下仍使用 `db_repair/<accountConfigId>`
分目录，重定向 `work` 与 `backups`；历史与报告沿用原应用缓存索引，记录保留
真实备份绝对路径。切换不搬迁历史备份，自定义目录失效不影响旧历史读取。

备份优先 `COPYFILE_FICLONE_FORCE | COPYFILE_EXCL`，克隆后读取备份计算指纹；
不支持／跨卷时排他分块复制，覆盖短写并关闭异常路径句柄。真实 I/O 错误不被
伪装成可回退，已有不同内容的目标不覆盖。元数据失败时删除本次新建的备份文件。
失败修复落记录后也执行既有默认三份保留策略；删除失败不标记为已清理。
每次操作的时间戳附加 UUID，同一秒重试不覆盖备份或历史；相同时间的记录按追加
顺序倒序保留，避免淘汰最新备份。

自定义缓存中的备份可能仍有历史记录引用，不能仅因缓存位置改变而删除。
本轮不访问、清理或迁移真实 QQ 数据和外盘缓存，也不替用户选择外盘或解除 hold。

## 开修前缓存按钮误锁

组件原先以 `busy !== null` 禁用缓存位置按钮。打开面板会自动体检，用户跳过体检
进入修复页时，当前大库的只读调用可能尚未返回，`busy` 仍为 `checkup`。这时即使
尚未开始修复，两个目录按钮也不可用；不能用后来正在修复的状态解释这一问题。

只读体检不读取或写入修复缓存，现改为仅在修复、回滚、备份或目录选择进行中时
锁定。空间不足仍只拦开始修复，目录选择和恢复默认不受其影响。主进程原有的
选择器打开前／返回后在途复核保持不变。

真实组件回归使用未结束的体检 Promise 复现旧代码失败，并覆盖体检未结束且空间
不足、体检结束但空间不足、真正开始修复后仍锁定；不访问用户数据库。

该补丁在隔离工作区先复现失败再修复，连同只备份写入锁定、系统修复窗口入口共
7 项测试通过，渲染层类型检查与定向 Biome 通过。当前开发实例有真实修复在途，
本轮不热更新或重启它；隔离提交与运行分支的合入状态分别记录，不冒称已生效。

## 建议余量确认继续的验证

后续按用户要求将预计峰值与 25%／64 MiB 冗余拆开，余量不足不再禁用开始修复。
确认区需明确接受风险，主进程只允许覆盖余量告警。新增回归先在旧实现失败，
再覆盖确认后保留备份、强制不能绕过另一卷峰值不足、取消重开不沿用确认。

最终服务侧 8 文件 160 项、桌面侧 2 文件 10 项定向回归通过；服务、桌面 node／web
类型检查与定向 Biome 通过。真实组件检查了 1200／390px、浅色／深色／跟随系统
共 6 组布局和风险确认，未发现横向溢出或页面异常。未运行全量 CI，未执行真实修复。

合回开发目录前重新核对实际进程与修复启动记录，不从旧任务状态推断当前仍在途，
也不从进程退出或窗口关闭推断旧修复成功。源码合入与运行实例重启、native 替换
分别记录，本轮不自动重启应用或替换运行模块。

开发热更新可能先更新渲染组件而主进程仍在运行旧代码。若预检未提供
`recommendedBytes`，界面明确标注旧版预检值与重启提示，不把含冗余的旧值冒称
新峰值，也不向旧接口提交强制继续；此状态不禁用缓存位置选择。

## 实际原生组件接入核验

“当前原生组件尚未提供低占用修复能力”表示实际加载的模块没有返回能力版本 1，
不是调整预算或隐藏提示就能解决。必须核对启动器的 `WEQ_NATIVE_DIR`、loader
日志与目标模块，不能用另一个目录下的编译成功替代实际安装。

2026-10-23 的本机后续维护已将原生提交 `5a7137a` 的 macOS arm64 本地 release
安装到开发目录，标为 `local-storage-5a7137a`。替换前确认开发实例未运行并保留
旧模块与安装标记；新实例启动后以 loader 日志和进程模块映射核对实际路径。
Electron 44.9.0 加载实际目标返回初始化状态 0、能力版本 1，合成库服务预检返回
`storageOptimized=true`、同卷预计新增峰值 3 倍。三份既有装扮数据完整解密内容
与资源源文件一致，三类原生查询均有非空匹配，因此本次保留原 `.dat`。

详细维护与回退回执由本机 `native/.installed.json` 的 note 指向，原生二进制及
本地安装标记不入库。未修改正式 pin 或安装版应用，也未执行个人数据库修复。
后续执行 `native:fetch` 仍可能装回正式锚点，需重新核验实际目标的能力版本。

## 跳过体检后的迁移入口

自动体检是逐库串行的只读调用；跳转到修复页不等于当前原生调用已经返回。
原先共用 `busy !== null` 的门槛会在空间足够时仍锁住布局迁移和通用修复，
而修复页没有显示后台体检，形成无解释的灰显。

进入修复页后停止后续数据库体检，保留当前调用的完成凭据。允许先打开并确认
布局迁移／修复，确认后显示等待状态，直到当前检查返回才提交真正的修复请求。
检查返回时不能清掉已确认操作的锁；等待期间不允许修改缓存位置或另起备份。
热更新前发起、无法取得完成凭据的检查仍等待旧调用返回，不提前替换原库。
回归使用悬而未决的合成体检验证迁移入口、提交顺序和等待期间的缓存锁定，
不对个人数据库执行修复或布局迁移。
