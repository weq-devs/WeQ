# 消息选择与框选（2026-10-22）

本轮处理用户追加的“框选未选中”，并对同一路径的长时间线重复扫描做定向优化。不是全应用性能或外观验收，原清单的全方位优化继续保持未完成。

## 框选状态

- 原路径只有矩形，没有拖动中的消息高亮。`useMessageMarquee` 现在返回独立临时 `previewIds`，ChatPane 用于消息、系统行及缺口的选中外观；不提前写入 ContentSelectionProvider。
- 松开仍按最终坐标同步计算并提交，适用于没有中间 pointermove 的快速拖拽；取消、失去捕获、切会话、退出多选或卸载清空预览，不提交临时选择。
- 指针移动与滚动将几何计算合并到每帧一次，松开不等待下一帧。边缘实际滚动后更新命中；停止或取消清理动画帧。实测 11 次连续移动从 33 次行布局读取降为每帧 3 次（3 行夹具），不是跳过最终命中。
- 预览时不用 `.message-line.is-selected` 的扩展边框尺寸，使用内描边保持原 rect；系统消息和普通模式下的缺口同样使用主题 token 高亮。实际组件在 390px 深色下，行 rect 的 x/y/width/height 前后完全相同。

## 索引与快照

- `useMessageSelectionFlow` 按消息快照缓存 ID→消息／位置及选择项索引。选区变化不重建全消息 Map，普通消息缓存只更新所选与锚点；漫游／发送占位同步的可靠身份替换仍保留原扫描与校验。
- `createSelectionGapIndex` 用起点排序＋前缀最大终点支持二分查询。完整缺口高亮仍要求**某一个原始区间**完整包含，不把两个相交选区的并集错误当作单个原区间；点计数保持开区间，64 位序号不经浮点数比较。
- 隐藏删除产生的缺口用有序序号索引查询，不对每条显示消息扫描整份隐藏列表；无效、倒序或非正端点不产生缺口。通用多选在 ID 数组不变时复用 key／value 快照，仍保留筛选外的选择和键盘契约。

## 验证

先用提交 `5634eec3` 的运行源码复现：2000 条稳定消息快照的单项选择读取消息 ID 8001 次；优化后的回归要求少于 20 次，且选择内容、顺序与锚点不变。基线用 Vite 读取 Git 原文件，没有回退工作树。

合成大整数缺口微基准（Node v26.11.1，预热后 3 次中位数）：

| 区间／查询数 | 原逐项扫描 | 建索引 | 索引查询 |
| --- | --- | --- | --- |
| 500 | 106.09 ms | 0.36 ms | 1.02 ms |
| 2000 | 1177.41 ms | 0.92 ms | 1.78 ms |
| 5000 | 7587.68 ms | 1.66 ms | 2.56 ms |

两种实现的全部查询结果一致；这是特定查询的离线微基准，不是整机帧率、首次页面渲染或所有消息操作的承诺。索引测试覆盖乱序、嵌套、重复、边界、超过安全整数及源对象后续修改。

定向组件回归保留复制、转发、分析、导出、跨会话选区、缓存身份升级、框选取消／缩小／最终提交及键盘行为。发现旧 `chat_selection_actions` 在异步分析返回前断言，已用提交前源码复现同样失败；改为等待异步 act，原精确 ID 断言不变。

Playwright 使用真实 ChatPane 和合成消息，阻断所有外部请求。验证普通状态及多选状态、Shift 缺口计数、拖动预览、松开保留、取消恢复、反向缩选与边缘滚动停止；1280px 浅色和 390px 深色、自定义深绿／浅黄强调色、paper／grid、减少动态效果下无页面异常或横向溢出。未操作真实消息删除或服务端状态。
