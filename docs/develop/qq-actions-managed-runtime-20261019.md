# QQ 写操作与托管运行时实施记录

## 目标与基线

分支：`feat/qq-actions-managed-runtime`，从 `d0eaf191` 创建，包含当时本地记录的全部 `origin/dev`。
用户要求先完成已研究的非只读功能，再完成统一 QQ 运行时接口及 macOS 托管 QQ。
不推送、不发布，不把研究候选或单测通过写成真机验收。

## 边界

统一运行时在 `@weq/service` 管理生命周期，复用 `nt_helper` 的探测、密钥、签名、SSO 等底层能力。
QQ 内核不得装载到 WeQ 主进程；托管宿主必须是真实进程，不以假 PID 兼容当前接口。
托管不是仅隐藏启动官方主窗口，最终须在 WeQ 完成登录、在线功能与恢复的闭环。
不复制第三方框架或原生桥接二进制作为新依赖，按必要性独立实现。

资料修改按字段 patch，不重写未编辑资料；备注、群名片、全局昵称分开建模。
群消息策略保留 1/2/3/4 四档，不把群助手/屏蔽静默改成普通免打扰。
服务端成功不等于其他端和本机缓存已经同步；不写 QQ 原库伪造成功，不在超时后自动重发写操作。
真实联系人、公开资料和群共享状态的验收使用明确的测试对象，不擅自改变任意真实目标。

- 普通用户进程内复用 `scanSessionMaterial(process.pid)` 的探测通过，无登录会话时不返回可用凭据；这是自身内存访问证据，不代表已验证登录后的票据读取。必须先载入注册桥及 QQ wrapper，再载入 `nt_helper`，避免它的同名空注册符号遮住桥接入口。
- 打包探测同时发现父进程的 Node 启动参数会干扰独立 Worker，已显式清空 `execArgv` 并补充真实本地子进程回归。
- 托管桌面工厂已接入私有会话交接：会话初始化并连接后，Worker 按主进程签发的读取序号调用 `scanSessionMaterial(process.pid)`；票据只经过私有 Node IPC 进入原生 SSO 登记器，不进入运行时观察事件或界面快照。缺票据最多读取三次，不触发真实写操作重试。
- 主进程使用启动时确认的真实 PID、wrapper/major 路径、版本、App ID、扫码 UID/UIN 和 SDK GUID 登记 SSO。登记及撤销复用现有 `queueSsoWork`，租约被替换时旧实例不能误清理新会话；断线、退出、停止会撤销自己的登记。
- 新增错误 GUID、同账号重连旧序号、迟到登记成功、关闭失败重试及票据字段白名单回归。SSO 登记成功只发布 SSO 能力，不据此发布数据库或推送就绪。
- 新读取器已在本机独立进程中实测：先载入本仓库注册桥和 QQ wrapper，再载入 `nt_helper`，未登录时按预期返回「当前登录票据尚未就绪」，没有改变进程工作目录、读取外部 QQ 或输出票据内容。已登录票据获取和真实在线请求仍待扫码验收。
- 私有会话阶段完整 `pnpm ci:local` 七项通过，更新后的独立 Worker 再次通过实际二维码获取与正常退出冒烟；这不包含已登录票据、发包或数据库就绪验收。
