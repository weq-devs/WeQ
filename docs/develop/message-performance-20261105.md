# 会话首屏优化（2026-11-05）

## 改动

本轮针对首屏读取和窗口复用，不改变消息排序、未读阅读位置、撤回/删除可见性、数据库变化失效和校准周期，不扩大缓存或新增 QQ 数据库索引。

### 撤回标记合并读取

`AntiRecallDb.listRecalls` 支持单种或多种记录来源，合并前去重，仍按会话及当前页消息 ID 过滤，保留 64 位 ID 与每批 256 个 ID 的上限。

`AntiRecallService.getRecallMap` 将私聊和数据线兼容标记合为一次查询。典型私聊页从两次表存在探测加两次记录查询（4 次 SQL）降至一次探测加一次记录查询（2 次 SQL）。空页不查库；没有记录表时只探测一次，不缓存缺表结论，之后启用防撤回可立即读取新表。群聊仍是一次探测和一次读取。

撤回标记仍在正文返回前完成，不通过延后标记或读取旧快照来加速。

### 缓存按实际使用保留

窗口缓存新增不改变 LRU 顺序的 `peek`；预取新鲜度检查使用此入口，真正读取窗口才提升访问优先级。

缓存内部区分尚未被读取的预取窗口与已阅读窗口。容量或字节预算不足时优先淘汰前者；预取被采用后按普通窗口保留。该内部优先级不修改 `prefetched` 的阅读来源标记，避免影响“从未读处阅读”的恢复规则。

`canPrefetch` 在后台任务开始前检查是否有可用名额。12 个名额全被已阅读窗口占用且目标不在缓存中时，跳过后台预取；用户点击不受此限制，仍正常冷读取并缓存。过期条目会在检查时清理；既有窗口重新预取不被降为低优先级。

容量继续为 12 个窗口、12MiB 序列化数据预算、单窗最多 200 条、10 分钟过期。没有增加常驻资源或定时器。

### 首屏任务及时释放

首屏完成或失败时同步释放当前任务，不等待 Promise 清理微任务。完成后立即切换目标或失败后立即重试，都会创建正确的新任务；旧任务的清理仍只处理自己的订阅，不清除后来创建的任务。取消、账号切换与迟到回调的拒收规则保留。

### 阶段采样

补接此前只有类型声明、未实际记录的 `messagePage` 和 `roamingCache` 阶段，通过现有账号级 `messagePerformance` 返回。`messagePage` 覆盖私聊/群聊最新页的分区解析、读取、可选引用补全、撤回标记和渲染对象转换；`roamingCache` 覆盖本机漫游时间线页读取。失败和取消也计入耗时，原错误原样传播。

采样沿用每阶段最近 256 条的上限，不包含消息、账号/会话 ID、SQL、路径或 URL；并行阶段可能重叠，不能简单相加为总耗时，也不等同于 native 独占执行时间。尚未覆盖完整点击到像素呈现或所有后台业务分类。

## 验证方式

- 缓存回归：预取检查不提升 LRU、后台条目优先淘汰、采用后保留、过期清理、无名额跳过后台且点击仍读取。
- 首屏任务回归：已完成任务与新目标交接、失败后立即重试，以及既有取消、分阶段正文、缓存恢复和未读阅读位置测试。
- SQL 回归使用 `@weq/testkit` 明文 SQLite 运行实际源码，核对 SQL 次数、表/会话隔离、64 位 ID、来源去重、270 个 ID 分批、缺表后新建与全量读取顺序。
- 阶段回归核对实际消息服务调用和异常路径；已有漫游缓存、自撤缓存和消息页回归继续运行。

全部业务验证使用合成数据，不读写真实 QQ 数据库、不联网。只运行上述相关单测、受影响包及桌面类型检查和改动文件的 Biome 检查，不运行全仓 CI。本轮不修改版本号、不打包或重启日常实例；真实会话打开 P50/P95 尚未验收。

本轮结果：desktop 4 文件 43 项、db 3 文件 15 项、service 4 文件 27 项，共 85 项通过；db/service 与 desktop 主进程、渲染进程类型检查通过，16 个改动 TS/TSX 文件的 Biome 检查通过。

## 生效

渲染侧缓存调整可由开发模式热更新加载；数据库/服务层调整需要重新编译并重启 WeQ 主进程。安装版须在后续包含该提交的构建中生效，无需重启 QQ。
