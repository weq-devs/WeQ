# 导出查看器（2026-10-24）

## 范围

- 工具菜单提供「导出查看器」，只接入 WeQ 导出目录与聊天 JSON/JSONL，不接入 HTML、TXT、CSV、XLSX。
- 目录复用已有 `baseline.json` 发现逻辑，读取消息日志；无基线的旧目录可以查看当前目录的 JSON/JSONL。
- 原生 JSON、富 JSON/JSONL、旧裸数组和 WeQ 现有 ChatLab 输出均有适配。ChatLab 已扁平化的内容按文本呈现，不反推媒体或嵌套结构。
- 新 JSON 与 ChatLab 元数据增加 `conversationId`；旧格式兼容明确的会话字段、成员身份与配套日志，不按昵称关联。

## 关联与增量

查看器按会话类型和稳定标识查询当前账号的会话目录；明确为其他平台的内容不自动关联 QQ。跳转复用已有会话跳转总线，消息定位前重新读取本机消息并验证归属。等待目录或消息期间切换账号会中止操作；嵌套转发内部不提供原会话跳转。

旧格式识别规则：

- 读取元数据中的 `conversationId`、`conv`、`groupId`，以及元数据或消息里的 `targetUid`、`targetUin`、`targetGroupCode`。消息身份最多采样前 256 条，首条灰条没有目标不会中止后续识别；不读取嵌套转发中的目标。
- 明确为私聊时，`ownerId` 必须对应成员表中的导出者，剩余唯一成员才是对端。没有成员表时，可使用顶层消息中明确的发送者 UID／QQ 号与导出者核对；单方、缺失或有歧义的数据不按昵称补猜。群聊的 `ownerId` 是群主，不用于此推断。
- QQ 号优先经成员映射统一为 UID；只有 QQ 号时，查询当前账号会话目录，以唯一的同类型目标映射为本机 UID，跳转和增量配置均使用该 UID。
- 同名配套的 `<聊天文件>.report.json` 只接受 `weq-export-report/1`。目录中的 `export-report.json` 不能单独给任意 JSON 指派身份，只用于核对通过共有消息 ID 关联的隐藏日志。
- 缺少 `baseline.json` 时仍探索 `.weq-export/messages-<64 位哈希>.jsonl`，最多 64 份，不跟随隐藏目录或日志的软链接。旧聊天文件没有身份时，仅在顶层消息 ID 与日志采样相交且目标唯一时补关联；没有对应聊天文件的日志可独立查看，媒体根目录仍是导出目录。
- 身份候选冲突或明确为其他平台时不自动关联；没有清单的日志仅提供查看，不伪造可用的增量基线。

有唯一配套基线时，「增量导出」打开现有配置并预填基线。没有基线或同会话基线存在歧义时不自动挑选。当前原文件保持只读，后续合并、授权、范围和目标处理沿用原有导出流程。

## 读取与安全

- JSON 用原生 `JSON.parse`，读取前检查 64 MiB 上限；没有新增解析依赖。
- JSONL 逐块解析，单行上限 8 MiB；消息日志只读取带换行提交标记的完整记录，普通 JSONL 允许末行无换行。
- 查询每页最多返回 100 条，但仍扫描整份消息以统计筛选结果；尚未实现持久化全文索引。超深或超长消息明确标记显示截断，不修改来源。
- 文件大小或更新时间变化时要求重新打开，读取过程中也会再次检查。关闭来源撤销访问能力并中止其正在执行的扫描。
- 媒体复用现有 URL 构造器、灯箱和流式文件响应，支持 Range；只解析授权目录内的真实路径，拒绝绝对路径、远端 URL、穿越和软链接逃逸，不回退到 QQ 在线接口。
- 媒体能力为临时随机标识，关闭后不能再次读取；响应使用 `no-store`、`nosniff` 与禁止脚本/外联的 CSP sandbox。
- 当前同次最多打开 64 份来源，目录扫描有界。查看器关闭工具面板时保留页面现场；明确「关闭导出」或账号工作区卸载时释放来源。
