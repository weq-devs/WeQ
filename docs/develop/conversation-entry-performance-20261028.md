# 会话首屏请求与查询优化（2026-10-28）

## 实现

本轮落实页面加载研究中的第 2、3 项，沿用既有会话缓存、未读校准、SQL 公平队列、
消息分页与动态时间线，不修改版本号。

- Web 的 `listLatest`、`listBefore`、`listAfter`、`listFrom` 使用独立 HTTP 请求，
  不再等待同批慢目录接口。搜索仍独立返回，其余接口保持批处理；取消消息读取也独立发送。
- 最近会话第一页保持交互优先级，后续目录分页、好友与资料目录、通知、隐藏／删除会话及
  群附加资料使用已有后台队列。沿用最多八次交互后让出后台的公平规则，未读快速校准不降级。
- 当前会话读取可附带 `readWindow: { owner, generation }`。每个渲染工作区独立 owner，
  切会话递增 generation，并通过 `cancelMessageRead` 撤销上一代。主进程按账号服务隔离，
  保留取消记录以处理取消先于查询到达的情况；旧取消不会影响新一代或其他渲染窗口。
  账号内最多保留 256 个 owner，空闲超过 30 分钟后按需清理。
- 取消会移除同一读取上下文尚未执行的 SQL，并拒收已经执行的旧 SQL 的结果；不宣称能够
  中断原生执行。未带窗口标识的旧调用仍可使用原接口。
- 漫游缓存的 legacy、native、protocol 三个来源改为单次 `UNION ALL` 查询。
  每个来源独立过滤隐藏记录、排序和限额，返回后继续使用原有合并与去重，不能在合并前
  用全局 LIMIT 挤掉独立消息。已初始化缓存每页由三次 native SELECT 往返减为一次；
  不缓存“没有消息”的结论，后续写入无需另建负缓存失效规则。
- 消息页新增可选 `deferReplyMedia`。聊天首屏、翻页、定位及实时刷新启用它，正文仍包含
  同页撤回和删除状态。默认关闭，导出及其他调用保持原来的引用补全语义。
- 正文显示后，`replyMedia` 每批最多读取 200 个本地消息的 40900 引用缓存，使用后台优先级。
  沿用既有媒体筛选、解码和 IPC 转换。后补只应用于查询时同一版本的消息对象，
  通过 WeakMap 保存展示补丁，不改正文快照，避免实时刷新把后补当正文修改反复替换。
  漫游消息不按本地 msgId 猜引用来源。失败保留原占位，不阻断阅读。

## 验证

新增回归先复现普通 Web 批次阻塞消息读取，以及空漫游缓存仍做三次 SELECT。
定向测试覆盖优先级、后台最终执行、取消先到、旧取消迟到、双向定位共用窗口、
独立 owner、同序号多身份、跨来源去重、隐藏／恢复、64 位序号、引用后补迟到，
以及后补接口的 Buffer／大整数 IPC 形态。

测试只使用受控异步返回、合成消息及明文 SQLite。专项结果随本轮交付记录，
不把 SQL 次数下降当作真实大库的耗时比例。源码验证不代表运行实例已加载；
本轮不重启日常实例、不清缓存、不操作真实 QQ 消息。

本轮定向回归 24 文件、214 项通过（desktop 83、service 119、db 12）。desktop
主进程／渲染进程与 service 类型检查通过，本次源码及测试的 Biome 检查、差异空白检查通过。
Web 在本轮独立输出目录构建通过，产物已清理，未覆盖日常产物；仍有大 chunk 提示，
本轮未将第 4 项页面回访或第 5 项首包瘦身混入实现。没有运行全仓 CI、桌面打包或真实大库耗时采样。
