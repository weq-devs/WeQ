# 渲染资源生命周期与峰值限制（2026-10-24）

## 背景与范围

10 月 24 日北京时间 15:39、17:17 的主窗口退出与 10 月 20 日相同，均落在 Blink / PartitionAlloc OOM 路径。离线反例另确认消息装扮永久 pin、字体迟到注册与必达等待区无界等缺陷。本次修这些可验证的路径，不声称已经证明历史 OOM 只有一个原因。

## 持有与释放

- 消息装扮、装扮预览与报告挂件按款共享独立样式节点，返回幂等释放函数；最后一个使用者离开即取消在途预热、释放 pin 并移除规则。不再每次拼接并重解析全局历史样式表。
- 消息 hook 绑定组件生命周期、可见范围（额外 200px 预留）及标签页活动状态。离开时释放，重新可见时可再次预热；不清聊天数据。
- 预热开始前 pin 整批帧，全部成功并经过两帧绘制才开播。失败、取消或预算不足都保留静态首帧，不把 allSettled 当成就绪。
- FontFace 按文档、字体族和资源 URL 共享在途加载与引用计数；最后一个使用者释放时 delete，过期加载不 add。消息字体的派生版本使用不同字体族，避免旧版本覆盖新版本。生效装扮、两处字体预览和报告均接入这套管理。
- 报告装扮页非活动时释放专用资源；报告选中的主字体在报告关闭或重置时释放，不影响其它仍在用同款字体的报告。

## 预算与失败边界

- 解码缓存最多 64 MiB RGBA 估算、256 张，最多同时解码 4 张、排队 512 张。字节与数量均包含在途解码预留，不因 pin 或 required 突破预算；已在播的帧不主动淘汰。
- 不再有额外 requiredWaiting。队列已满时必达请求明确失败，可选预热跳过；消费者的 AbortSignal 可撤销自己的需求，共享资源的其它消费者不受影响。
- 新动画超过剩余容量、资源损坏或单款超过 256 帧时，当前显示静态首帧；下次进入可见范围或重新选择装扮时可重试。未禁用正常范围内的动态装扮，也不提高 V8 堆上限。
- 真实新 Image 在赋 src 前以 Range 请求读取 PNG 签名和 IHDR，响应忽略 Range 时也只消费前 24 字节并取消余流；先拒绝异常尺寸，再预留解码预算。媒体协议对气泡、挂件与字体帧也执行同一头部检查，保护 CSS 首帧等不经显式预热的入口。实际解码尺寸比预检更大时拒绝保留。此预算只约束受管预热，不是 Chromium / GPU 总内存硬上限，文件在预检与解码间改变也不能承诺没有瞬时峰值。
- FontFace 管理器每文档最多保留 128 个不同资源，并独立限制最多 128 个尚未完成的原生加载；即使快速取得后马上释放，也不能绕过在途上限。超出时返回不可用并使用原有字体回退链。

## 图片与诊断

默认本地代理路径的时间线图片增加 v=thumb，复用既有缩略图优先、原图兜底；灯箱仍用原图 URL。动画表情和编辑器本地预览不改源。启用“优先 CDN”时仍保留原来的 CDN 优先和失败回退策略，不猜测 QQ CDN 的缩略参数。缩略图添加 lazy / async 解码提示。

分钟诊断经 DOM meta 与隔离 preload 按需交换固定数值：retained / pinned / reserved、完整在途数量、取消数、受管字体 / 加载中字体 / 文档字体数、样式与规则数。最多统计 512 个受管样式节点的规则，遗漏数量单列；payload 超 2048 字节不接受，主进程再次投影白名单，不含正文、URL、字体名、账号或堆快照。
