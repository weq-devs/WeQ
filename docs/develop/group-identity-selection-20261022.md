## 官方静态契约

基于已有官方 Mac QQ 固定样本（`wrapper.node` SHA-256 `d6fc116b7d0bc30b6e90ce1643a5aec3bd6ca864b303c9ce30418b5c0a5777dd`）的限定窗口：

- `getIdentityList` 参数转换 `0x936d18` → manager `0x12b43e4` → worker `0x1320d4c` → 编码 `0x35a2578`，命令 `0x9436 / 0`。
- 请求根 tag 1 为群号 uint64，tag 2 为成员 UIN uint64，不是 UID。
- 响应 userInfo@1 的 uin@1 必须匹配目标；level@2 包含 curLevel@1、name@2、progress@3；titles@3 包含 titleId@1（string）、name@2、isSet@3、specValue@4、popText@5。
- 当前展示选择由 `isSet` 决定；等级独立，不从文本、角色或选项编号推导。
- `setIdentityTitleInfo` → worker `0x1321128` → `0x35a3a2c`，命令 `0x9437 / 0`；群号为根 tag 1，数值 titleId 为 tag 2，没有目标成员参数。
- 两条路径都用 group_common_req_worker 成员函数槽 `0xC0`；已贯通 KernelDepends 的 SendOidbReqByUin，必须设 UIN-form（OIDB 信封 tag 12=1）。设置窗口 `0x1321270` 同样明确传 `0xC0`，不是从读取接口类推。

固定证据、独立构造与真实失败回执保留在所属 Agents 项目的 `work/protocol-parts-2-4-20261022`，不复制真实身份、票据或成员资料到仓库。

## 实现

`GetGroupIdentity`／`SetGroupIdentity` 使用现有 OIDB dispatcher，不新增运行模块或依赖。
读取保留缺失选中标记、未知／超界字符串 ID、缺失等级；多个选中不擅取第一项。
只有规范十进制且在 uint32 范围内的 ID 可以提交，`0` 是合法数值，不用真值判断丢弃。
不硬编码等级／管理／专属选项编号；选项名称由服务端返回。

`AccountWriteService` 只读取当前账号 UIN，不允许前端选择其他成员作为设置目标。
保存前重新取得当前目录，找不到请求 ID 就不发设置；异步读取后与写入前复核运行时。
设置的空业务回应只算 accepted，必须独立查询选中标记才确认。
IPC 查询在前后复核账号／数据源，另外检查群号与账号 UIN。

界面复用 `QQWriteSelectRow` 与显式保存按钮，未改当前值也允许主动提交。
读取在途或失败时不能提交旧目录，错误沿用 `QueryError` 并保留原信息；不自动重试规则拒绝，也不在窗口每次聚焦时重发。
同号换数据源或切群重建字段状态，避免未保存选择被带入另一目标。
云端等级是独立只读行；成员资料与聊天原有等级字段没有被清空或替换。

## 显示规则续查

后续静态核查补齐了官方 Android 普通消息路径：由当前群资料与成员缓存的 `realLevel`、`titleId`、专属文本、角色及两个独立显示开关计算 AIO 模型。
固定样本对有效选择与默认路径分别处理；默认路径可能优先专属文本，但存在专属文本不证明该成员当前就在默认路径。
独立 `Unique` 方法另有专属文本优先逻辑，尚未贯通其所有界面调用点，不与普通消息规则混同。

Mac Node 与 Android 类均确认 `groupHonor` 将选择编号与专属文本分开，Android 引用窗口还明确其拥有者为 `MsgAttributeInfo`。
其 SQL／wire 映射仍未完整建立，因此本轮没有凭字段相似或单一优先级修改徽标，也没有把当前目录直接套用到所有历史消息。
