# 弹窗层级与入口定位修复

## 共用规则

- `Modal`、`OverlayLayer` 和 `WindowSurface` 通过 `OverlayLayerContext` 传递父层级。父浮窗因点击、聚焦或重新打开而提升时，子层重新领号，不能落到父层后面。Portal 不切断 React 上下文。
- 所有独立 portal 的菜单、列表和弹窗都使用 `useOverlayLayer`，不能依赖静态 CSS 数字压住其他窗口。提示文字、全局工具栏不属于可交互子弹窗。
- `OverlayAnchorProvider` 记录当前文档内的入口；共用外壳在捕获阶段记录各自内部的入口，兼容鼠标点击不自动聚焦按钮的平台及键盘点击。子层只读取本次打开的入口，不随之后点击其他控件而漂移。
- 普通弹窗优先在入口下方展开，下方不足则翻到上方，横纵坐标都限制在视口边缘留白内。浮窗首次展开也沿用入口，之后保留用户拖动的位置。
- 避让使用未受入场动画缩放影响的布局宽高，不拿动画中途的可视矩形当最终尺寸；时间选择器自行引入所需样式，不依赖先访问导出页面。
- 支持显式 `anchor`。已有手工精确定位的菜单保留自己的坐标。入口被收起时使用打开前的矩形快照，不退回屏幕角落。
- 图片、视频等专门的全屏媒体预览继续使用自身布局；不可关闭的启动/锁定提示没有普通按钮入口时仍保留原布局。
- Escape 与 Tab 按实际堆叠上下文选择最上层活动窗口，不能只比较 `aria-modal`。隐藏的窗口不参与比较，父窗也不能抢走已进入子窗的初始焦点。

## 同类入口排查

共用外壳覆盖时间范围、聊天日历、互动标识及等级、缓存详情、分享与管理工具等入口。好友和群资料卡原先绕过共用外壳，现已迁入；表情回应人名单、年度报告分享、全局搜索、账号右键菜单和助手选项菜单补齐动态层级。合并转发宿主在新增或提升记录窗口时重新领层，记录的父子关系单独保留，父记录提升不能遮住子记录；首次展开沿用入口并限制在窄屏视口内。

回归测试在 `apps/desktop/test/nested_surfaces.test.ts`、`profile_nested_surfaces.test.ts` 和 `forward_surface_order.test.ts`，覆盖父窗提升、重新打开、四类子弹窗定位、收起入口的矩形回退、窄视口翻转、真实互动标识三级弹窗、复用合并转发宿主及 Escape 不误关父窗。测试使用离线合成数据，不接触真实 QQ 或网络。
