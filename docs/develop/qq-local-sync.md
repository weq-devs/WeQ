# QQ 本机消息同步

Windows x64 桌面端启动时自动加载 QQ 本机同步组件，普通好友文字取得有效的发送成功回执后，调用宿主的 `syncPrivateTextSent`。桥接在官方 QQ 内补取对应消息、通知聊天界面并处理自身消息的未读状态。消息发送、签名和送达判定仍沿用上游实现。组件异常不改变发送结果。

回执只携带 QQ PID、双方 UID、客户端序号、服务器时间，以及已有的私聊序号和随机数，不携带正文或票据。账号会话守卫随回执传递，切号后旧任务失效。同进程连续消息排队处理，不同进程独立工作。关闭到托盘时继续运行，完整退出时关闭本次组件。已完成初始化的 QQ 可能需要正常重启一次，以便组件观察启动过程。

## 源码与分发

逆向实现与 Windows 加载器在私仓维护，公开主仓只保留回执契约、桌面生命周期管理和产物校验。组件产物由现有原生发布仓构建，发布清单的 `qqSync.win32-x64` 记录协议版本、构建标识、固定文件白名单及逐文件 SHA-256。

`pnpm native:fetch` 从当前 `native/pinned.json` 对应的发布版本拉取组件，放入忽略入库的 `native/qq-sync/`。桌面启动前再次校验文件，开发模式从该目录加载，安装后从 `resources/qq-sync` 加载。缺少组件时给出日志提示，WeQ 仍可启动。其他平台及独立 Web 服务不加载 Windows 桥接，桌面内置 Web 服务复用桌面宿主。

```powershell
pnpm install --frozen-lockfile
pnpm native:fetch --require-qq-sync
pnpm --filter @weq/desktop dev
```

Windows 打包前同样要求组件完整，并复制到安装包的 `resources/qq-sync`。旧发布版本不含该组件时，维护者需先合并配套私仓与发布仓改动，发布原生产物，验证后明确更新版本锚；仅合并主仓代码不会自动切换原生版本。可通过 `native:fetch --from-dir` 使用带完整发布清单的离线产物。

## 验证范围

已用合成记录覆盖多账号会话守卫、连续发送、桌面启停、文件白名单、损坏资产拒绝和离线安装。私仓 Windows 流程构建加载器并运行原生夹具。9.9.35-52892 的普通私聊补取、气泡刷新和未读处理曾做过真机核对；9.9.37-54395 只有离线核验。迁仓后的真实 QQ 与最终安装包仍须联合验收。

手工验证时由用户给测试好友连续发送两条普通文字，官方 QQ 保持同一会话，不切换、不重登，核对两条气泡和未读状态。日志中的通知成功仅代表接口已调用，不能代替界面验收。群聊、临时会话、图片和语音不在本次接入范围。
