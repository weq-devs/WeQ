# QQ 交互当前版本收尾（2026-10-22）

本轮完成本机清单「当前版本」九项，保留工作区其他改动，没有推送或发布。

## 实现范围

- 表情包导出复用已有任务与保存策略，提供图片目录、图片 ZIP 和收藏备份 ZIP。图片按文件头定扩展名，复制原字节，收藏包保留原图、备注和顺序；选择器收藏页复用收藏包导入／导出，导入完成重新读取。
- 获赞统计与资料行并列；点赞弹窗提供三个预设和自定义次数，原窗切换并支持减少动态效果。
- 数据库修复复用空白子窗口机制，系统边框与普通工具浮窗分开配置。完整面板仍在主 React 树中，渲染目标是子文档，主题同步、锁屏、账号目标、历史／回滚与生命周期分别验证。
- 自己的消息头像开放资料入口；本地 `self:<uin>` 不作为 QQ UID 查询。群名片与专属头衔进入资料列表，按已有角色规则原行编辑，复用账号绑定、写后读回及缓存刷新。
- 频道会话与频道消息使用不同的选区 owner。会话多选进入 `guild-conversations`，导出只带 node ID；单会话消息仍使用 `guild-direct` 和精确消息 ID。消息选中态只由气泡绘制，不再叠加外层高亮，选中前后占位尺寸保持一致。

## 自发消息与混合选择

不能用「发送者是自己」判断能否操作，也不能把所有漫游来源都当作未保存占位。

1. 发送占位变成正式原库记录，或变成带 `localSent` 的持久协议缓存时，按可靠序号与 ID／random 迁移选择及 Shift 锚点。同序号但 random 不同的记录不替换。
2. 精确导出中包含缓存身份时，任务读取已有缓存，不依赖联网补全开关，不主动拉取远端消息。普通缓存仍使用已有来源前缀过滤和去重，不混成 QQ 原库 ID。
3. 自发缓存删除使用 `DeletedMsgStore` 的独立记录类型，存储键包含会话类型、会话目标及缓存行身份。IPC 先在指定会话缓存中核对真实 `localSent` 记录；不会将客户端 random 转成 QQ 原库删除 ID。标记可持久化，删除列表显示这些记录并携带会话目标恢复。普通漫游或未经确认的私聊序号不走此路径。
4. 缓存删除仅影响 WeQ 本地显示，不修改 QQ 服务端或之后同步出的正式原库记录；这与原库的类型列删除路径分开。原缓存字节不被移除。
5. 导出、分析及删除先分出支持／不支持项。混合选择打开数量说明，可复用 `GapMessagesModal` 的私聊预览管线逐条查看原因，确认后只处理支持项。全部不支持时仍可预览，不能继续；取消或切会话不执行旧操作。批量删除保留未处理项。
