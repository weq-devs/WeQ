# 聊天首屏加载收尾修复

## 现场与边界

2026-10-25（北京时间）观察到桌面开发版的会话列表、群资料已经显示，但消息区持续显示骨架。只读采样中主线程仍响应，渲染诊断没有退出记录；同一群的消息服务约 0.84 秒返回 25 条消息。现场没有捕获窗口身份变化的瞬间，不能将下面的状态泄漏认定为该次现象的唯一根因。

## 修复

- 接收消息结果仍检查账号来源、会话及窗口身份，防止过期结果覆盖搜索定位或另一个会话。
- 区分“窗口仍可接收结果”和“请求仍属于当前会话”：同一会话的窗口变化后，即使结果被丢弃，仍结束首屏及后续加载；切号、切会话、取消请求后不改新页面的状态。
- 未读水位读取移入现有 `loadConversationEntry` 生命周期，提前返回、正常完成和抛错都经过同一处收尾。失败继续向调用方抛出，不伪装成成功的空消息页。
- 同会话窗口失效时复用已有 `refreshWindow` 校准；继续遵守历史窗口不自动贴底、账号绑定及在途窗口检查，不反复重试失败请求。

## 验证范围

离线回归使用合成消息和受控异步返回，覆盖窗口失效、旧会话迟到成功／失败、未读快照提前返回、首次及后续页失败，以及现有分阶段显示、阅读位置和缓存行为。不读写真实 QQ 数据库、不联网，不替代真实聊天长时间运行验收。类型与针对性检查结果随本轮交付回执说明；没有运行全仓 CI、打包、安装或发布。

本轮 5 个相关测试文件共 42 项通过，渲染层 `typecheck:web`、3 个改动源码／测试文件的 Biome 和差异空白检查通过。修复前新增回归出现预期失败，修复后转绿；现有开发服务器已能提供新模块，但没有通过切换真实会话来制造竞态，也不声称已完成真实聊天端到端复现验收。
