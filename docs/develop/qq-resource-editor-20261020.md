# QQ 资源与管理交互续作

基线：`origin/dev` 的 `5927d3e1`；分支：`feat/qq-resource-editor`。

## 商城单张表情保存

- 单张详情复用 `getMarketPackImage` 取得既有 GIF 缓存，不枚举同包或新增密钥恢复链路。
- 默认保存、本次另存、稍后保存沿用公共保存准备与资源任务；系统选择器取消不建任务，任务完成后从导出任务列表查看结果、打开或另存。
- 单文件格式固定为原有 GIF，公共保存机制避免覆盖同名内容；获取期间切换账号实例或配置不发布旧来源结果。
- Web 的浏览器下载仅登记现有缓存文件，不询问服务器保存目录；服务器保存仍走公共策略。
- 验证：19 项商城入口、保存选择与资源任务回归通过；桌面主进程、渲染层类型检查通过；4 组深浅主题、自定义主题色及 390/1200px 布局检查通过。
- 未做真实 QQ 下载或原生选择器点选，不冒称真机端到端验收。

## 公告运行态复核

本轮开始时未发现运行中的 WeQ/Electron，无法完成“运行实例重载后只读复核”。此前源码修复仍保留，运行态验收待后续可用实例，不用离线用例代替。

后续复核已完成：发现新启动的开发实例及重载后的渲染页面，确认其构建包含按内容类型排除公告标签的实现。通过现有数据库查看器执行限定测试群的 `SELECT`，再用已有 codec 解码原字段，与运行接口返回的公告按身份对应比较：本地记录 1 条、类型标签项 1 个、运行返回 1 条，过滤后的正文完全一致，正文长度 3，末尾额外标签为 0。没有发布、修改或删除公告，没有重启或操作该实例界面；调试连接已断开。记录只保留计数与一致性结果，不收录公告正文、发布者或凭据。

## 邮件附件保存

- 附件只用现有不透明令牌和 `mail.download`，不改变认证、下载协议或附件范围。下载进入公共资源任务的私有目录，完整后发布，保存、取消、失败及另存回执沿用任务列表。
- 保存主动作沿用公共偏好，菜单只改本次；位置取消不发起下载，也不关闭邮件正文。Web 明确区分服务器保存与原有浏览器下载。
- 公共单文件输出新增原文件名输入，保留大小写扩展名、多重扩展名和无扩展名文件；不把附件强制当成 JSON 或添加 bin 后缀。原有格式型导出不受影响。
- 创建、排队执行与下载完成均核对邮箱服务实例及账号配置；失效令牌不创建任务，来源变化不发布迟到结果，异常信息仍经过邮箱脱敏边界。
- 补齐商城单张与邮件附件的任务类型标签，避免被旧兜底误标成群文件。
- 验证：44 项桌面邮箱、商城、公共保存及回执回归，11 项服务输出形态回归通过；桌面 node/web 类型检查通过；桌面/Web 深浅主题、自定义主题色及 390/1200px 共 8 组布局检查通过。未访问真实邮箱、下载真实附件或点选原生保存框。

## 气泡、字体与挂件保存

- 商城条目的另存与消息装扮卡片的单项／整包另存共用面板级保存锁及公共菜单；不为每个商城卡片创建保存查询。
- 保留 `buildDecorationFile`／`buildDecorationBundle` 的真实资源转换，先得到实际 TTF、静态 PNG 或动画 ZIP，再用公共保存准备选择对应文件位置；ZIP 是既有单文件结果，不误判成目录，也不新增资源格式。
- 生成与系统选择期间检查账号、配置和服务实例；取消不建任务，不覆盖原资源。完整结果进入公共资源任务，保存失败时仍有可重试的缓存和回执。
- Web 的服务器保存通过公共目录策略，浏览器下载沿用原宿主分配及下载句柄，二者独立；写入使用独占创建，不覆盖同名文件。
- 验证：30 项装扮转换、保存路由／控件、商城页及任务标签回归通过；桌面 node/web 类型检查通过。8 组深浅主题、自定义主题色与宽窄布局检查覆盖桌面／Web 控件，发现并修复 Web 卡片内部按钮越界后复验。真实装扮资源下载与原生保存框点选未实测。

## 个人空间相册导出

- 相册内媒体勾选与相册列表整本导出两个既有入口均迁移公共保存菜单及资源任务；固定所选目标与账号配置，不在排队时清空选择，不再让渲染层直接拼磁盘路径或逐页写用户目录。
- 单项媒体按实际 URL 与已有视频本体／封面回退决定文件名及类型；多项和整本相册使用资源包。只有单项视频在文件选择前取一次已有本体 URL，整个任务不新增媒体协议或格式；签名失效仍明确失败，不扩展失效补全。
- 整本导出保留原有 30 条分页、最多 10000 页、重复项去重、提前空页／重复页检测及成功文件；页读取失败作为单独失败项记入资源清单，不把未知数量当作完整结果。分页大小提到桌面共享常量，与浏览入口一致。
- 下载使用原有 `downloadUrlToFile`，传递取消信号并等待所有在途 worker 收尾。取页／取视频 URL、选择位置、下载和发布前核对来源。旧导出接口仍保留兼容，但同样受服务器保存根与来源约束。
- 来源变化会清空对应选择；取消选择器保留选择，已排队任务从公共任务列表查看进度、停止、失败清单、另存与打开。Web 不把服务器写入冒充本机下载。
- 验证：38 项相关资源路由、空间相册界面、保存准备与任务标签回归通过；桌面 node/web 类型检查通过；媒体／整本两个入口在桌面／Web、深浅主题、自定义主题色与 390/1200px 共 16 组工具栏布局检查通过。布局使用合成内容，不涉及真实 QQ 媒体或原生选择器点选。

## 年度报告导出

- 末页原有 HTML／PDF／长图三个入口沿用公共单文件保存、偏好及本次菜单；文件名在桌面共享模块统一。位置取消不创建任务或启动捕获；三条 RPC 返回任务 id 或取消的 `null`，前端不把排队冒称已落盘。
- HTML 使用原有自包含文档，PDF／PNG 仍调用原宿主的 `renderHtmlToPdf`／`renderHtmlToLongPng`。没有更换捕获引擎、格式或空间发布流程。完整结果留在私有任务缓存，用户后续另存不重新捕获；宿主不支持时保留原错误。
- 选址、预热与捕获后核对账号／配置及服务实例；报告 HTML 缓存按年份、页面集合及读取范围隔离，范围变化不复用上一份文档。无旧范围字段的界面在本次报告首次可用来源绑定，不能把旧报告提交给新来源。
- 公共保存菜单与服务器位置弹窗增加可选 `portalTarget`，报告复用既有全屏浮层宿主；未传的其他页面保持原来的 body 挂载。末页仅在窄／矮窗口收紧排版，超高内容保留内部原生滚动，不抢报告舞台翻页。
- Web 明确是服务器保存，浏览器下载由公共任务列表提供。捕获进行中取消会等待原宿主调用返回，再丢弃未完整发布的结果，不承诺中断宿主截图或新的续传能力。
- 验证：54 项报告路由、末页、原 HTML 页面、范围隔离、公共保存及浮层挂载回归通过；桌面 node/web 类型检查通过；桌面／Web、深浅主题、自定义主题色、390/1200px 宽与 480/800px 高共 16 组工具栏检查通过，三种格式及菜单均在画布内可见。捕获单测使用宿主替身，未把它冒称真实 PDF／长图引擎或原生选择器点选验收。
