# 聊天图片预览预算（2026-10-26）

## 修复范围

离屏立即移除 `src` 会让快速往返滚动反复加载；加载前的浏览器图片节点还可能露出文件名或 `[图片]`。此前修复只隔离了迟到事件，没有覆盖加载占位与保留策略。本次保留独立加载节点的事件隔离，并将加载中、已淘汰和真实缺失状态改为图形占位；真实缺失的原因仍可悬停或通过无障碍标签读取。

## 设置与策略

- 全局配置 `chatImageCacheMiB`，默认 128，允许整数 0–1024。设置位于「基础功能 → 聊天消息 → 图片与表情」，保存后更新共享设置查询，当前窗口无需重启；其他窗口在设置查询刷新后采用新预算。0 关闭离屏保留，不阻止可见图片加载。
- 每个渲染窗口按账号创建缓存，切换账号或退出账号时丢弃旧缓存。图片、接收动画表情和商城表情共用预算；装扮帧、灯箱原图和磁盘缓存不属于此预算。
- 只持有成功加载的图片节点，不额外复制图片字节，也不主动下载离屏新图。相同源与 `srcSet` 组合共享一份记录；预算按自然宽 × 自然高 × 4 字节估算，不按压缩文件大小计费。
- 可见范围含 200px 预留；最近查看的资源排在保留队列末尾。预算或 512 项保留数量超限时，从最旧的离屏项开始淘汰；可见资源优先，最后一个可见使用者离开后重新收敛。超出预算的单图不额外保留。调小预算立即淘汰，调大预算可接纳当前已加载的可见预览。
- 已加载资源跨虚拟列表卸载保留，未加载请求仍可在离屏后取消。缓存淘汰丢弃节点引用，并通知仍挂载的离屏消费者移除源；不直接修改其他消费者的 DOM，不把取消或旧节点错误当成当前源失败。

## 预算边界

这是软性预览保留预算，不是 Chromium/Blink/GPU/进程内存硬上限。自然尺寸仅能估计一帧 RGBA，动画额外帧、浏览器缓存、在途解码和多窗口开销不能据此精确计量；也不承诺释放引用后 working set 立即下降。多个可见资源可暂时超过预算，避免正在查看的图片闪空；512 项限制同样优先保护可见项。

## 离线验证

`chat_image_cache.test.ts` 覆盖 LRU、共享引用、预算收敛、零预算、尺寸异常、数量边界、加载图形、离屏保留、虚拟列表和账号隔离。`chat_image_cache_settings_ui.test.ts` 覆盖保存、共享查询更新、失败重试与无效输入；服务测试覆盖旧配置、持久化及损坏值归一化。已有迟到事件回归继续保留。

`test/browser/run-chat-image-cache.mjs` 使用真实 QqImage / QqMarketFace 与设置控件、合成 PNG 和离线设置替身，验证延迟加载时无可见文字、深浅色/窄屏/主题色、25 轮滚动不重发缓存图片请求、虚拟列表重新挂载与零预算离屏释放。浏览器与测试服务器在结束时关闭，不访问真实 QQ 数据或外部网络。验证只代表合成场景，不冒称日常实例升级、真实数据长测或解决所有图片内存增长来源。
