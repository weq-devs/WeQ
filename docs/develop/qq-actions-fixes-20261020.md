## 在线状态 EOF

只读核对实际 `misc.db` 缓存，逐字段用旧 schema 解码，失败精确落在
`48902 → 20320 → 20337 → 1`。主状态 10、扩展状态 2000 时，20337 的实际 wire 为：

| Tag | Wire | 含义 |
| --- | --- | --- |
| 1 | varint | 表情编号 |
| 2 | length-delimited | 自定义文字 |
| 3 | varint | 表情类型 |

旧代码把 tag 1 作为天气字符串读取，因而抛出 `premature EOF`。修复后保留
20337 原始 bytes，仅在已确认的 subType=2000 下解码；没有将自定义结构套到天气等其他类型。
真实自身缓存只读复核成功，未保存真实 UID、状态文字或原始 blob 到仓库。

标题栏显示自定义文字及已知系统表情；编辑器同时显示基础状态与扩展状态名称，回填自定义
文字和表情。后台读回不覆盖正在编辑的草稿，同号切换来源清除旧草稿。扩展状态保存后
复用原有最多 15 秒的本机同步等待，并刷新标题栏查询。没有修改 QQ 原库。

## 头衔清空与读回

固定空头衔回归证实，原编码省略 `0x8FC/2` 内层 tag 5 与 tag 7；服务端会将字段缺失
理解为不修改，不等于清空。现在两个空字符串均显式保留，永久常量和其他字段不变，不恢复
有效期 UI。自己的头衔与成员编辑器都复用写会话的有界本机读回，并定向刷新群成员缓存。

## 好友分组回执与读回

`0x1255/0` 的请求 UID／分组字段、UIN-form 及默认分组 0 的显式存在性保持不变。
上游在该命令单独兼容已应用码 `2001002`；本机 native 的 `decode_oidb_reply` 则将任意
非零信封码转换为固定形状 `OIDB error <code>: <message>` 后抛出，不提供结构化错误码。
因此在该命令的 invoke 内仅识别精确前缀 `OIDB error 2001002:`，其他业务码、网络错误、
相似编号均继续抛出。没有修改共享传输层的成功规则，也不将该回执提升为“已读回确认”。

分组编辑器保存后有界核对 `peerState.categoryId`，随后刷新分组名册和对应好友缓存。
读回为旧值时继续显示未同步，刷新失败不重复写入。针对性回归覆盖匹配／不匹配读回、
精确已应用码及其他错误不被吞掉。

没有指定好友和原始失败业务码，本轮未做真实好友分组写入，不能确认用户原反馈就是
上述业务码造成；保留真实移动、读回与恢复验收。

- [上游固定版本的分组回执策略](https://github.com/SnowLuma/SnowLuma/blob/db142db9e6398c779283eab9afc3552da1e2c361/packages/protocol/src/oidb-services/contacts/set-friend-category.ts)

## API 用量修复

下面保留修复前的源码盘点；实施结果和验证范围另列在表后。

| 实际调用路径 | 修复前记账缺口 |
| --- | --- |
| `agentlab/http.ts` 的画像聊天、embedding | 成功且有 usage 时才记；缺 usage、HTTP 失败与网络失败不记 |
| `agentlab/extract.ts` 的画像提炼、视觉描述 | 成功后手动 reportUsage；失败无请求账目 |
| `service/account/assistant.ts` 流式多轮 | 重试是额外 HTTP 请求但不单独记；取消或 reader 异常会跳过末尾 reportUsage，即使已收 usage 也漏记 |
| 同文件非流式摘要与整理调用 | `callApi` 直接返回 JSON，调用方没有统一回传 usage |
| `service/account/intent_sense.ts` 三处 API 调用 | 各自 reportUsage，但 app_context 注入的端点解析器没有 onUsage，实际回调为空；意图／画像／推荐缺独立归属 |
| `bootstrap/agentlab_config.ts` 连通性测试 | 使用无 onUsage 的临时端点，不进入当前账号记账；实际消耗请求遗漏 |
| `agentlab/tts.ts` 远程语音合成和测试 | 当前无 token 记账接口，需区分合成请求计数与服务商计费单位，不能将字符或音频量冒充 Token |
| `service/account/agentlab_usage.ts` | 仅保留数值记录，无未知、结果状态、请求 ID 去重；scope 只有 build/chat/assistant |
| `renderer/views/agentlab/UsagePanel.tsx` | 全部次数直接作 token 平均分母，没有未知用量与失败／取消覆盖说明 |

实施结果：

- `agentlab/api_usage.ts` 统一真实请求的开始、usage 更新与结束回执；每次实际尝试分配 ID，
  重复流式累计值只更新原记录，HTTP／网络失败与取消都留账。已取消但尚未发出的请求不记。
- 缺失分项为 `null`；仅同一份回执的输入、输出都已知时才可求和。数值须为非负安全整数，
  兼容 prompt/completion 与 input/output 两组 token 字段，不估算文本长度，不用默认 0
  冒充缺失数据。真实 0 与未知分开，平均值只用已知请求。
- 非流式聊天、embedding、画像提炼、视觉描述、助手标题／摘要、多轮流式请求、意图分析、
  互动画像、推荐回复均接入。提炼、记忆、发言决策、关系评分等按实际功能标签归属，
  不把它们一律算作助手或画像。
- 助手 400／429 重试各记一条真实尝试；usage 在 SSE 片到达时更新，随后 reader 取消或失败
  不丢已收到的用量。错误回执若带可解析 usage 也保留；服务端不提供时仍是未知。
- HTTP 200 或 SSE 数据帧内的业务错误仍按失败处理，不因 HTTP 成功而显示成功；空错误文案
  有明确回退反馈，已返回的 usage 继续保留。
- 远程语音在发生首个 HTTP 请求时开始记账，后端真实重试另记 ID；同一合成任务的结果下载
  不重复当作新的推理。复用已有响应解析取 usage，不额外复制音频响应，不将字符／音频量
  当作 Token。原生本地意图引擎、启发式及自托管 GPT-SoVITS／CosyVoice 不写云 API 账本。
- `TokenUsageStore` 继续按账号及来源存储，保留原有 5000 条上限；模型测试和独立语音服务
  使用一个应用级账本，查询时明确合并，不创建同路径的多个 store 相互覆盖。
- 同一进程切回相同来源时用弱引用复用仍存活的账本；旧在途回调和新会话不会互相覆盖文件，
  也不把仍在运行的请求误判成重启中断。弱引用不使所有历史账号账本永久常驻。
- 重启后遗留的 pending 请求显示为中断，不无限显示“进行中”。历史数字记录继续读取，
  无法事后恢复的历史漏账不伪造、不回填。统计不保存正文、图片、音频、Base URL 或密钥。
- 独立 bot 的 UsageSink 同步按请求增量更新，总量、模型、日期和小时不重复累计，WebUI
  同样区分未知、失败和取消。
- 桌面用量面板新增功能归属及未知次数，未知输入／输出分开显示；无已知用量时不画虚假的
  0 Token 曲线或占比。新样式使用主题 token，已检查宽窄窗口、深浅主题和主题色。
- 当前账号与全局记录分别落盘；面板明确标记全局请求数量与功能，不把连接测试或独立语音
  误标成当前 QQ 的助手调用。可见面板每 5 秒刷新，后台不轮询，离开账号沿用已有查询清理。

验证覆盖请求状态、功能归属、持久化、切回来源、流式重复用量、重试及取消；另有 320／390／1200
宽、深浅主题、不同主题色、纯未知／混合用量的 12 组离线界面检查，无页面横向溢出。
320 宽的表格在自身容器内可横向滚动。没有发送真实付费 API 请求；真实服务商对照测试
