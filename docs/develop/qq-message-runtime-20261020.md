## 意图与回复建议的独立上文范围

前序取消精华缺口补齐后，继续第 11 项。设置新增独立的 `analysisContextMessages` 与 `suggestionContextMessages`，均为 0–100 整数，默认分别为 4、23；后一默认保留原 API 建议窗口“23 条上文加最新消息”的实际取值。旧配置自动归一化，无效值不部分写入。

- 分析窗口额外读取边界上文，但不将这些额外历史作为待分析目标；原有相邻 8 分钟／总跨度 15 分钟限制保留。
- API 批次改为逐目标结构化输入，各自携带已截取上文，不再全批共用第一条目标的上文；本地分析与建议兜底分别使用对应配置。
- 分析缓存 schema 更新并记录条数，参数不匹配或旧上下文格式不作为命中；仅改变建议条数不清空分析结果。
- 分析与建议分别维护运行时版本。旧在途任务不会删除新任务、写入新缓存或发出旧结果；`getSuggestions` 的可选 `revision` 仅隔离客户端查询缓存，实际取值来自服务端保存配置，不允许通过查询参数覆盖。
- 界面同步版本变化，清除旧胶囊与不可分析标记；旧订阅与迟到悬停结果不能重新插回。「清空并重算」也更新运行时版本。
