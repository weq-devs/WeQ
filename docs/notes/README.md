# 过程记录（不进站点）

这里放**过程性**材料：阶段性方案、验收回执、TODO 清单、某次重构的流水账。
它们的读者是当下的参与者，不是后来查文档的人。

## 和 `docs/develop/` 的分工

| | `docs/develop/` | `docs/notes/` |
| --- | --- | --- |
| 内容 | 「系统现在怎么工作」：协议、架构、坑 | 「我们当时做了什么」：计划、回执、待办 |
| 时效 | 长期有效，要随代码更新 | 写完即过期，不要求维护 |
| 进站点 | 是，要写导航 | **否**，`srcExclude` 已排除 |
| 命名 | 主题名 `send-message.md` | 带日期 `20261112-xxx.md` |

## 判断标准

一条材料该放哪里，问一个问题：**半年后有人改这块代码，读它有用吗？**

- 有用（讲清了为什么这么设计、哪里踩过坑）→ `docs/develop/`
- 没用（只记录了当时做到哪一步）→ `docs/notes/`

## 注意

- 这里的文件**不会被任何检查覆盖**，包括链接检查。写坏了没人管。
- 不要在正文里放账号、uin、好友数据、抓包原文。
- 需要长期引用的内容，请提炼成 `docs/develop/` 里的一篇再引用。
